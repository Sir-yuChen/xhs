> 市面上的小红书工具要么只能爬数据，要么只能发笔记，要么需要手动复制粘贴到 AI 平台再贴回来。
> **XHS 把「采集 → 内容库 → AI 改写 → 图片润色 → 一键发布 → 定时自动运营」全链路打通。**
> 一个浏览器标签页，完成别人用 5 个工具才能做的事。

**⚠️ 本项目仅供学习交流使用，禁止任何商业化行为，如有违反，后果自负**

## 核心优势

| | 传统方案 | XHS |
|---|---|---|
| **数据采集** | 写脚本 / 用第三方爬虫 | 平台内搜索 + 一键入库，素材自动下载到本地 |
| **内容管理** | Excel / 文件夹 / 各种笔记软件 | 统一内容库，标签筛选，卡片预览 |
| **AI 改写** | 复制到 ChatGPT → 手动粘贴回来 | 编辑器内一键改写，标题/正文/标签全覆盖 |
| **图片处理** | Photoshop / 在线工具 | AI 图片润色 + 参考图，原位替换 |
| **发布** | 手动打开创作者平台上传 | 选账号 → 点发布，支持定时 |
| **自动化** | 没有 / 需要写代码 | 定时任务中心配置关键词 + 频率，全自动：搜索→改写→发布 |
| **长任务** | 浏览器挂十几秒，刷新/重启就丢 | 发布 / 同步 / 商品生成三类长任务全走**持久化队列**（落 `tasks` 表），单 worker 逐篇跑，进程重启自动续跑 |
| **话题** | 手工维护标签，发出去平台还不认 | 平台形态 `#名字[话题]#` 的解析与回填同一套实现，同步 / 采集 / 商品生成自动落话题关系 |
| **多账号** | 反复切换浏览器 | 账号矩阵统一管理，2h 自动健康巡检 |
| **数据隔离** | 单用户工具，多人共用即串数据 | 库内所有数据按平台账号维度隔离，多用户互不干扰 |

## 平台预览

> v1.0.1 起 `static/` 下的 v1 期界面截图已全部移除（与现行版本早已不一致），各页面能力以本清单为准。

- **账号矩阵**：扫码 / 手机验证码 / Cookie 导入三种绑定方式，Cookie 经 Fernet 加密存储，2 小时健康巡检、过期自动通知；一个账号的三张平台令牌（网页版 / 创作者 / 千帆）分列管理。
- **笔记发现**：关键词搜索与 URL 直查，多维筛选；详情抽屉看无水印原图、互动数据、评论区，一键存入内容库。
- **内容库**：卡片 / 列表双视图，话题检索、批量操作、JSON / CSV 导出，筛选条件本地持久化。
- **笔记工坊**：图片工坊 / 视频工坊 / 草稿工坊三个页签合为一页，AI 改写正文、润色标题、拖拽排序素材、AI 图片润色。
- **我的笔记**：账号自有内容与互动数据（我发布的 / 赞过的 / 收藏的 / 互动消息），并挂载千帆商品与其阅读、支付表现。
- **队列记录页**：发布 / 同步 / 商品生成三类长任务的批次与明细，唯一批次号、5 秒轮询进度、失败原因、取消与重试。
- **定时任务中心**：内置系统任务按用户各持一份，调度日志按用户收口，调度器线程异常由看门狗自动复活。
- **数据洞察 / 竞品监控**：仪表盘总览、互动趋势、Top 内容、热门话题；关键词 / 账号 / 品牌 / URL 监控并留存快照历史。

## 🛠️ 快速开始

### 环境要求

- Python 3.10+
- Node.js 20+

### 安装依赖

```bash
git clone https://github.com/Sir-yuChen/xhs.git
cd xhs

pip install -r requirements.txt
npm install
cd frontend && npm install && cd ..
```

### 启动项目

```bash
# 一键启动（后端 + 前端）
python main.py --with-frontend
```

启动后访问：
- 前端: http://localhost:5173
- API 文档: http://localhost:8000/docs

首次启动自动创建数据库（Alembic 迁移 + 初始化数据），注册账号即可使用。

### 本地常驻运行（后台自启）

开发机把它做成「开机就在后台跑」的常驻服务，由计划任务 `XHS-AllInOne-App` 托管
（登录触发 + 不因电池停止 + 无执行时长上限 + 崩溃自动重启）：

| 文件 | 作用 |
|---|---|
| `.hermes/scripts/run-app.py` | 监督进程（用 `pythonw.exe` 运行，无控制台窗口）：拉起后端与前端，任一个挂掉 5 秒后自动重启 |
| `.hermes/scripts/register-app-task.ps1` | 注册/更新计划任务并立即启动 |
| `.hermes/scripts/stop-app.ps1` | 停止任务并回收 8000 / 5173 端口 |

两个入口：

- http://127.0.0.1:8000 —— 后端直出**生产构建** `frontend/dist`（启动器注入 `FRONTEND_SERVE_STATIC=true`，仓库配置不动）。
  注意：改前端后要 `cd frontend && npm run build`，8000 才会看到新代码。
- http://127.0.0.1:5173 —— Vite dev server（改代码即时热更新，`/api` 反代到 8000）。

日志：`.hermes/logs/app.log`（后端输出 + 每次重启记录）、`.hermes/logs/vite.log`。

```bash
# 启动 / 停止 / 取消自启
powershell -NoProfile -ExecutionPolicy Bypass -File .hermes/scripts/register-app-task.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .hermes/scripts/stop-app.ps1
schtasks /delete /tn "XHS-AllInOne-App" /f
```

> `run-app.py` 是这台开发机专用的（写死了 pythonw / node 的绝对路径，避免依赖 PATH）；
> 干净环境仍然用上面的 `python main.py --with-frontend` 手工起一次。

### 🖥️ 桌面版（Windows 安装包）

不想配 Python / Node 环境，可以直接装桌面版：下载 `spider-xhs-setup-<版本>.exe`
双击安装即可，内含 Python 运行时、Node 签名运行时、后端、前端构建产物，装完自动起服务并开浏览器。

```powershell
# 自己打包（Windows + Python 3.12 + Node 20+ + Inno Setup 6）
powershell -NoProfile -ExecutionPolicy Bypass -File packaging\build.ps1 -Version 1.0.2
```

产物落在**项目根目录** `spider-xhs-setup-1.0.2.exe`（约 88MB，`lzma2/max` 压缩）。
数据与日志装在安装目录里（`data/` `logs/` `backend/app/storage/`），**卸载只删程序文件、数据保留**。
详见 [`packaging/README.md`](./packaging/README.md)。

```bash
docker compose up -d
```

## 🧪 测试与质量保障

本项目把「验证」当成交付物的一部分，而不是事后补票：

- **1123 条自动化测试**（2026-09-26 实测，`1123 passed / 0 failed / 0 errors / 0 skipped`；全量并行回归约 **165s**）：API 契约、服务层、迁移幂等、账号隔离、队列持久化与守活、发布状态机全覆盖
- **14 个前端行为脚本**：不依赖前端测试框架，用 esbuild 打包**真实**组件在 jsdom 里驱动，钉住「必须做到 / 不得出现」的 UI 契约
- **变异测试**：每条关键守卫都配套「故意改坏必须变红」的变异用例——守卫承重有证据，不是永远绿的摆设
- **慢用例打标**：迁移往返等 >3s 的用例打 `@pytest.mark.slow`，内循环 `-m "not slow"` 秒级反馈
- **三层回归循环**：改一次代码跑内循环（`-x --lf`）→ 一个功能点跑受影响文件集（`pick_tests.py` 自动选）→ 收尾跑全量

```bash
# 跑某个测试文件（pytest.ini 已固化 -n auto 并行 + junit 判据自动落盘）
pytest tests/backend/test_note_sync.py -q -x --lf

# 全量回归（判定只看 .hermes/reports/reg.xml 四数，退出码会假性变 1）
```

## 🗝️ 注意事项

- `apis/` 是底层 SDK 层，**请勿直接修改**，上层通过 `backend/app/adapters/` 中转调用
- 对小红书/千帆的**探测 / 调研 / 取证**一律**只读**（GET 或只读查询 POST），不做登录逆向
  - ⚠️ 澄清（2026-10-11）：硬约束管的是**探测**那条线。**用户在本系统内的显式写操作**
    （商品上下架 / 删除、图片空间增删、发货、售后…）是另一条线，与直连官方后台同一性质，
    走「本店归属校验 + 两层确认」；定时任务里的写操作只有「清理未引用图片」且**默认暂停**
  - ⚠️ 「只读」**不等于**「不需要签名」：千帆图片空间列表是**只读但强制签名**的端点
    （判据是**有没有副作用**，不是带没带签名）
- 数据库所有数据按**平台账号维度隔离**，多用户互不操作同一份数据
- Cookie 有时效性，平台内置 2 小时自动健康巡检 + 过期通知
- 所有敏感数据（Cookie、API Key）使用 Fernet 加密存储
- AI 功能需在「模型配置」页面配置 OpenAI 兼容的 API 端点（支持火山引擎、阿里云百炼等）
- `data/`（真实库与备份）、`backend/app/storage/`（媒体素材）、`node_modules/`、构建产物均**不入库**（见 `.gitignore`）
