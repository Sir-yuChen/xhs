# 2026-09-16

## 项目梳理：XHS_ALL_IN_ONE

产出 `PROJECT_MAP.md`（项目根目录），13 个章节的结构化梳理。

关键结论（跨会话可复用）：

- **定位**：小红书全链路运营平台（采集→内容库→AI改写→图片→发布→自动运营），同时是逆向签名 SDK 仓库。
- **技术栈**：FastAPI + SQLAlchemy 2.0 + Alembic（14 个 revision）+ APScheduler + curl_cffi；前端 React 19 + Vite 7 + antd 6 + recharts。
- **分层约定**：`apis/`（底层 SDK，禁止直改）← `backend/app/adapters/xhs/`（唯一中转）← `services/` ← `api/` 路由（21 个 router，约 130 端点）。
- **数据模型**：21 张表 + `note_tags` 关联表；账号分 `pc`（采集）/ `creator`（发布）两类；Cookie 多版本加密存 `account_cookie_versions`。
- **时区约定**：全项目统一 `backend/app/core/time.py::shanghai_now()`，禁止裸 `datetime.now()`。
- **配置优先级**：`config/default.yaml` < `CONFIG_FILE` < `.env` < 环境变量；`scheduler.enabled` 是定时能力总开关（默认 false）。
- **签名体系**：四层（curl_cffi 指纹 → Cookie/DS/websectiga → b1/MNS(x-s,x-t)/x-s-common → profileData/x-rap-param）。算法唯一存在于 `xhs_utils/**/js/`，Python 侧通过 subprocess 调 Node 并对输出做长度/前缀正则校验。详见仓库内 `SIGNATURE_ALGORITHM_DEEP_DIVE.md`。

已识别的缺口（后续若有相关任务可直接切入）：

1. `api/platforms/xhs/pc.py` 中 `/notes/comments`、`/users/notes`、`/homefeed/*` 为 mock 占位实现（真正的评论抓取在 `crawl.py` 的 `/xhs/crawl/data`）。
2. 蒲公英（`apis/xhs_pugongying_apis.py`）、千帆（`apis/xhs_qianfan_apis.py`）SDK 已实现但 backend 零引用，未接入 UI。
3. `backend/app/core/task_runner.py` 的 `InProcessTaskRunner` 是死代码（从未被调用）。
4. `BackgroundScheduler` 与 FastAPI 同进程，多副本部署会重复执行定时任务，无分布式锁。
5. `tests/backend/` 仅 3 个测试文件（README 称 126 passed，实际覆盖需核对）。
6. `secret_key` 与 `fernet_key` 未分离，改 secret_key 会导致历史 Cookie 全部解不开。
7. SQLite 用 `PRAGMA journal_mode=MEMORY` 而非 WAL。
