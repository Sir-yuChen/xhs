## 三方令牌通用性：真机矩阵实验（用户提问 → 两套体系）+ 新缺陷 DEF-051

**用户问题**：「千帆，创作者平台以及PC端，三个平台的登录令牌是否通用，如果通用则就无需创建多个账号，
只需要一个账号使用相同令牌即可。」（并要求**用浏览器实测**，不要用脚本推）

### 结论：**不通用 —— 是「两套体系」**
| 只注入 | → www | → creator | → ark（千帆） |
|---|---|---|---|
| PC 凭据（acct7 晨晨家） | ✅ 晨晨家 | ✅ 显示「晨晨家」 | ❌ 被打回 `customer.xiaohongshu.com/login` |
| 创作者凭据（acct8 观隅好物） | ❌ 只有游客会话 | ✅ | ✅ **进 `ark.xiaohongshu.com/app-system/home`，显示「观隅好物的店」** |
| 千帆凭据（binding1） | ❌ 只有游客会话 | ✅ | ✅ |

- **网页版**独立：`web_session` + `id_token`
- **customer 单点登录**：`customer-sso-sid` + `customerClientId` → **创作者与千帆共用**，
  凭 `POST /api/cas/customer/web/service-ticket`（`{'service': <目标站>, 'type':'tgt'}`）互相换 ticket
- PC jar 里**没有** `customer-sso-sid` ⇒ 拿不到 ark 的 ticket ⇒ PC → 千帆失败
- **创作者/千帆 → www 不成立**（全仓只有 `exchange_creator_session_from_user_cookies` 一个方向）
  ⇒ **借会话是唯一办法，不是绕路**；「只留一个账号、删掉借用逻辑」在平台侧做不到
- **可优化但未做**：千帆绑定理论上可由创作者凭据派生（`shop_account_bindings` 还带店铺/游标字段，属独立设计）

### 方法（关键）
真实 Chrome + 隔离 profile + CDP 9222；**每份凭据一个干净 profile**（复用 profile 会串味）；
www 登录态用项目自己的只读适配器 `get_self_profile()` 验，**不靠页面长相猜**。

### ⚠️ 新缺陷 **DEF-051（🟠P1 `[OPEN]`）**：`web_session` 存在 ≠ 已登录
**什么都不注入**的干净 profile 访问 `www.xiaohongshu.com` 也**照样被种上 `web_session`**；
这份 jar 调 `/v2/user/me` 回 **`ok=True` 但 `nickname=None`、`user_id` 每次不同**（游客）。
而全项目唯一的判定 `account_service.has_web_session()` **只检查「键在不在且非空」** ⇒ 游客会话被判成
「网页会话可用」→ 页签亮着却读不出本人数据（正是 v1.21 想消灭的形态）。
影响：① 能力端点误报 `session_source=own`；② 借用候选被游客 jar 污染；③ 从**未登录**浏览器导入 Cookie 时稳定复现。
**修法待拍板**：推荐(A) 复用 v1.21 的 `_jar_is_same_identity` 探活语义加一层「会话自检」。

### ⚠️ 事故：本日志文件被写坏编码（本轮修掉）
**现象**：`2026-09-20.md` 里有 **2 行含非法 UTF-8 字节**（L42、L49，行首残留 `0x87 0xBA`）。
**连锁**：① 用 UTF-8 读取时，**整个文件**会被回退按 **GBK** 解码 → 前半段正常的中文全变成 `宸ョ▼鏁欒` 这种乱码
（`工程教训` 的 UTF-8 字节被当 GBK 读就是这个形状）；② 于是**按「读到的文本」去 Edit 会匹配失败**
（视图与磁盘字节不一致，报「当前文件内容与 old_string 不一致」）。
**根因**：此前某轮用 **shell（GBK/CP936 环境）追加中文**，一段 payload 被有损转码。
**处置**：备份原始字节 → 逐行 `utf-8` 解码、失败行按上下文复原 → 整文件重写为 **UTF-8**（现已全文件合法）。
**教训**：
- **写中文文档一律走 Write / Edit 工具（UTF-8），不要用 shell `echo` / heredoc 追加**；
- **Edit 报「内容不一致」但肉眼所见一致时，先验 `read_bytes().decode("utf-8")`** —— 多半是编码问题，不是工具问题；
- **自查一行**：`python -c "open(p,'rb').read().decode('utf-8')"`，全仓 md 一次扫完（本轮只此一个文件命中）。
