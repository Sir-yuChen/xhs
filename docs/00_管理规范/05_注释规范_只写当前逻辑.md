# 注释规范：只写当前逻辑，简短突出核心

> 2026-10-28 用户口径立规，**强制**。
>
> 用户原话：「新增一个规范，代码中所有注释说明，只保存当前最新代码逻辑的说明，
> 简短明了突出核心代码逻辑即可」

## 1. 一句话判据

**注释只解释「现在这段代码为什么这样写」，不解释它的历史。**

写完一条注释前问一句：**删掉这条注释，读者会不会把这一行改成 bug？** 会 ⇒ 留，且只留这一句；
不会（只是讲来历、讲某年某月的缺陷、讲被谁取代）⇒ 删。

## 2. 六条规则

| # | 规则 | 反例（删） | 正例（留） |
|---|---|---|---|
| 1 | **不留历史**：日期 / DEF 编号 / 「2026-xx-xx 用户口径」「曾被取代 / 原先是 / 已修」 | `# 2026-10-24 修订：path 优先于 perms（原来是反的）` | `# 判重按 path → perms → name` |
| 2 | **不留被推翻的方案**：旧实现长什么样、试过三条路哪两条失败 | `# 试过 db.add / insert()，都会多带列 —— 改 text()` | `# 必须用 text() 显式列名：表列少于模型列` |
| 3 | **不留事故叙述**：缺陷复盘、实测日志、多少次踩坑 | `# 实测：种子 179 行，库里只落 173 行，侧栏丢 6 个入口` | `# 页签与宿主共用同一个码，按 perms 判重会跳过它们` |
| 4 | **不写代码复述**：`# 遍历列表` / `# 返回结果` / `# 判空` | `# 循环所有行并组装成树` | `# 孤儿行按顶级处理（父被删了也别丢数据）` |
| 5 | **只留约束**：单位、边界、顺序依赖、性能、只读、脱敏 | — | `# 每页都过一次限流器，超限等待而非停止` |
| 6 | **改写而非追加**：新结论直接替换旧句子，不留「~~旧值~~ → 新值」 | `# 上限原 20 页，现改为无限翻页` | `# 翻到平台没有下一页为止，刹车靠限流器速率` |

## 3. 长度

* 单行注释 **≤ 1 行**（约 40 汉字），超出说明你在讲故事；
* 函数 docstring 只保留 **契约**（入参含义 / 返回 / 抛什么 / 唯一实现或唯一真相源），**≤ 5 行**；
* 模块 docstring ≤ 15 行，只写「这个模块负责什么 + 边界在哪」。**不写演进史**（演进史归 `docs/`）。

## 4. 唯一允许长注释的地方

**「破坏了不报错」的判据**（静默错）—— 这类注释短写会让人删掉承重代码，故允许写清
「为什么不能那样改」，但仍要**去掉日期与编号**，只留因果：

```python
# ✅ 好的静默错说明（因果关系，无历史）
# 种子无主键：id 由 DB 分配。把种子 _seq 当主键会与自增序列打架。
# 按 (row_type) 判父子，绝不用 parent_id IS NULL —— 孤儿明细会被当成父行读出来。
```

## 5. 提交前自查（抄进每个需求的收尾清单）

```bash
# 本轮 diff 里新增/修改的注释行，先人工过一遍上面 6 条
git diff -U0 | grep -E '^\+' | grep -E '#|"""' | head -50
```

判据：**diff 里出现日期、DEF 编号、「原先是/曾/被取代/实测/踩坑」⇒ 改写或删除**
（`docs/` 里的文档不受此限，文档本来就该记决策史）。
