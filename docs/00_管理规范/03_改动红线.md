# 改动红线（「接缝类」改动的最小强制清单）

> **适用判据 = 失败模式，不是「新功能 vs 修 bug」**：
>
> | 失败模式 | 走哪 | 本文管吗 |
> |---|---|---|
> | **地基塌**（建/删表·迁移·端点·跨模块契约·公共层）| **通道 A · 五阶段** | ❌ 不管 |
> | **接缝错**（前端组件·lib·服务内部逻辑·文案）| **通道 B · 本文** | ✅ |
> | **数据/环境**（存量数据·迁移夹具·环境依赖）| **通道 B · 本文** | ✅ |
> | **口径变**（平台改契约，**过期事实**）| **通道 B · 本文** | ✅ |
>
> ⚠️ **别按 commit 前缀或「新功能/修 bug」分** —— 实测会**反向指错**：
> `fd78357`（前缀 `feat`，实为交互修正 ⇒ 该走本文）·
> `afd944f`（前缀 `fix`，实为删 5 个模块的地基变更 ⇒ 该走五阶段）。
>
> 拿不准 ⇒ **按地基类走**（宁重勿漏）。
> 立规 2026-10-15（用户口径「任何需要改代码修改文档等操作时，均需要先评估修改影响范围…」）。
> ⚠️ **本文不是五阶段的重复** —— 是**接缝类的专属入口**；四步**强制**，但**不要求走五阶段**。

用**本项目 55 条真实提交**回放证明：**改动的「规模」完全不预测风险**。

| 真实提交 | 规模 | 风险 |
|---|---|---|
| `1929a95` | **1 文件 +0/-0**（只改数字 `16/140/125→17/145/130`）| ⚠️ **命中「文档数字」** —— 三校验的对象 |
| `eba3e24` | 1 文件 +8/-4 | 真·琐碎 |
| `d2d49dd` | 2 文件 | **修的是「弹窗空白」真 bug** |
| `7deca67` | **72 文件** | ⚠️ **灾难**（误把已移除的工作流加回）|
| `afd944f` | 14 文件 **-3206 行** | 删功能，牵动全仓引用 |

⇒ **不按规模分级**（1 文件可能危险、72 文件也可能危险），
**按「改动的对象类型」触发** —— 且**由脚本自动判定**（可机械，不靠记性）。

## ⚠️ 接缝类专属强制项：**必须跑一条真链路**

**实证**：`fd78357`（商品发布收口）三个 bug —— **单测全绿**：

| bug | 为什么单测抓不住 |
|---|---|
| `Popconfirm` 默认弹右侧 ⇒ 「确认上架」压在「发布并下架」上，**手一落又点一次** | 这是**布局 + 人机时序**，不是逻辑 |
| `submit` 漏 3 个依赖 ⇒ 删图后提交用**旧闭包快照** | 单测直接调函数，**不经过 React 闭包生命周期** |
| 遮罩文案**说反了**（「正在发布并立即下架…（红线）」）| 文案不是逻辑断言 |

⇒ **规则**：改**前端交互**或**前后端契约** ⇒ **必须真跑一遍**（真机，或驱动真实页面的脚本）。
**只跑 `pytest` + `tsc` 不算验证过。**

## 四步（强制 —— 无论改动多小）

### ① 列清单：**要改什么**（精确位置）

```text
- backend/app/services/xxx.py:123   改 A 逻辑
- docs/02_设计文档/24_...md §22.3    同步契约
- tests/backend/test_xxx.py:45       守卫锚点随改名动
```
**列不出来 ⇒ 你还没搞清现状，先去读代码。**（实测：不列清单就动手 = 漏连带的头号原因）

### ② 反查连带：**改完会影响到谁**

```bash
python .hermes/scripts/impact_check.py --changed
```

它会输出两段：
1. **【改动红线】本次必须额外做**（按下方规则表自动判定）
2. 每个候选符号的引用点（源码 / 测试 / 文档分组）

**四把尺子**（反查方式，视改动对象选）：

| 改的是什么 | 怎么找 | 本项目实例 |
|---|---|---|
| **后端符号** | 全仓反查调用点 | 删 `note_category` ⇒ **9 文件 + 42 测试** |
| **数据模型** | 反查「读这张表的全部读点」| `note_goods` 改键 ⇒ **牵动 6 处** |
| **前端形态** | **反查接缝两侧**（谁产出/谁消费）| `passedSkuSpecs` 改形态 ⇒ 过滤**全失效** |
| **文档数字** | 跑三校验 | 改一处 ⇒ 校验 FAIL |

### ③ 定判据：**跑哪条命令算合格**

**答不上来 ⇒ 不许动手**（没有判据的改动 = 做完了也不知道对不对）。
把判据写进改造说明 / 台账（一行）。

### ④ 改完验证 + 留痕

按 ③ 的判据跑完，**结果留痕**（跑了哪条命令 + xml 四数 / 变异 CAUGHT / 校验 PASS）。

⚠️ **验证的对象必须是实际执行的那份** —— 实测踩过：
补丁修好但**躺在工作区没提交** ⇒ 重跑跑的仍是旧版 ⇒ **踩同一个坑第二次**。

## 触发规则表（由 `impact_check.py --changed` 自动判定）

| 改动对象 | 本次必须额外做 | 依据（本项目实证）|
|---|---|---|
| **任何代码** | 三条循环：`pick_tests.py` 选文件 → `pytest -x --lf` → `tsc`（动前端时）| AGENTS §2 |
| **公共层**（`core/` / `models/` / `main.py` / `lib/api.ts` / `conftest.py`）| **全量回归** | `7deca67` 就栽在这 |
| **守卫 / 测试 / 变异脚本**（`tests/` / `mutate_verify_*`）| **变异验证**（改坏必须红）| 「没被咬住的守卫等于没有守卫」|
| **文档数字**（`AGENTS.md` / `docs/README.md` / 设计文档 / `version.json`）| **三校验脚本** | `1929a95` **1 文件也命中** |
| **流程 / 规范文档**（`docs/00_管理规范/`）| **同层 Gate 互查** + 守卫措辞同步 + 速查表↔细则一致 | 2026-10-15：给 Gate 3 加条目而 Gate 4 已覆盖 ⇒ **重复** |
| **删除 / 退场**（删除行数 ≥ 100）| **反查全部引用点**（含迁移/守卫/文档/注册表）+ 补**防复活守卫** | `afd944f` 删工作流、`7deca67` 又加回 |
| **数据库 / 迁移** | **库副本三向实测** + 真库前备份（含 `-wal`/`-shm`）| 项目既有规矩 |
| **前端契约 lib**（`precheck-publish` 等）| **反查接缝两侧** | 形态不一致是「单测全绿但链路错」头号来源 |

**⚠️ 多条命中时**：**全部要做**（`7deca67` 那种大改会命中 5 条 —— 那正是它危险的原因）。

## 与五阶段的关系

| 场景 | 走哪条 |
|---|---|
| 新需求 / 新增功能 / 跨模块新链路 | **五阶段**（`01_文档先行工作流.md`）|
| 优化 / 修 bug / 改文案 / 改文档 / 调参数 | **本文四步**（轻量但强制）|
| **拿不准** | **按五阶段走**（宁重勿漏）|

⚠️ **例外**：改动**触及公共层或契约**时，即使是「小优化」也要**回设计文档同步**
（因为契约变了，设计文档就过期了 —— 这正是硬约束 1「文档先行」的触发条件）。

## 三条最贵教训（本项目实测，改任何东西都适用）

| # | 教训 | 实证 |
|---|---|---|
| 1 | **外部契约靠抓包，不靠想** | 商品发布 **4 次返工**（发货模式载体 / 规格图开关 / 货号 / 图片格式）|
| 2 | **判据式 > 举例式**（判据要能穷举）| SKU 匹配判据改 **4 次**、每版都写「定论」|
| 3 | **规范要能被执行**（不接线的规矩 = 纸面规矩）| `library_item_filter.cjs` 写进文档但从没被跑过 |

⚠️ **第 3 条的落地要求**：本文的**触发规则由 `.hermes/scripts/impact_check.py --changed` 实现**，
并有守卫 `tests/backend/test_gate2_guard_wiring.py` 钉住（脚本存在 + 能咬住中文路径）。
