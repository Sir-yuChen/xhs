# 功能设计文档模板（总 — 分 — 总）

> 来源：`docs/00_管理规范/01_文档先行工作流.md` **§2.0**（用户口径 2026-10-15/16）。
> **复制这份骨架写新功能设计文档**（Gate 2 判据）。
>
> ⚠️ **为什么是「总—分—总」**（用户 2026-10-16 口径）：
> ```
> 总①  需求的总体设计逻辑 —— 详细化
> 分   前后端**分开**设计 —— 各自用什么工具 / 底层数据结构 / 组件 / 实现逻辑
> 总②  把前后端**关联**起来 —— 串成端到端链路，实现完整需求
> ```
> | 少了哪段 | 会怎样（本项目实证）|
> |---|---|
> | 没有**总①** | 前后端各自设计时**对不齐目标** —— `passedSkuSpecs` 前端产行名、后端要比带前缀 spec ⇒ 全被滤掉 |
> | 没有**分** | 两层混着写 ⇒ **改一处看不懂另一处**；设计 24 涨到 25 个大节、绝大多数是「第 N 批」，**规格锚点被淹没** |
> | 没有**总②** | 两层**各自自洽、接缝没人管** —— 本项目绝大多数「单测全绿但链路错」都在接缝 |

## 2.5a 文案与信息密度（**用户明确口径 2026-10-16，硬约束**）

> 用户原话：**「说明或提示文案不要占用过多的页面布局，越少越好」**

| # | 判据 | 为什么 |
|---|---|---|
| C1 | **一行能说清就一行**；不写「为什么这么设计」的解释句 | 解释是给开发者的，写在**注释 / 文档**里，不上屏 |
| C2 | **同一信息不重复**（标题已说的，正文不再说一遍） | 弹窗里的 `Alert` 优先复用**卡片标题**，别再加一条 |
| C3 | **提示不占独立区块**（能并进已有行 / Tooltip / `extra` 就不新开一行） | 每多一行都是**挤掉的表单高度** |
| C4 | 长解释放 **Tooltip**（鼠标悬停才出），常驻区只留结论 | 常驻 = 永久占版面 |
| C5 | 弹窗类**禁大段说明文字**（`Alert description` 超过一行要复查） | 弹窗高度是稀缺资源 |

⚠️ **落地要求**：写页面守卫时，**新加文案要有「不超出 N 字 / 不新开区块」的判据**，
否则这条会退化成纸面规矩（沿用本页 §三条最贵教训 第 3 条）。

# 总② · 前后端关联（端到端）

> **把前两节串起来** —— 这是「实现完整需求」的收口，也是**最高发区**。

## 4.1 逐字段的「谁传 → 谁读 → 什么形态」⭐⭐

| 字段 | 前端产出（**准确形态**）| 后端读点（**准确形态**）| 不一致会怎样 |
|---|---|---|---|
| （例）`spec` | `颜色分类:【中古风】三斗柜`（**带前缀**）| `visible` 比对的 `c.spec`（带前缀）| 缺前缀 ⇒ 全被滤掉、价格库存一行不落 |
| （例）`delivery_label` | `全款预售` | `extra="forbid"` 白名单**未加** | **静默丢弃** ⇒ 发布成默认值 |

**⚠️ 判据**：每行都要能回答「**不一致会怎样**」。
**答不上来 ⇒ 还没设计完，别进编码。**

## 4.2 端到端链路（用户点一下，系统发生了什么）

```text
① 用户点「提交」
② 前端 collectXxx() → 组装 payload {字段…}
③ POST /api/xxx  ← 后端校验（白名单 / 归属 / 门禁）
④ 服务层 buildXxx() 组装平台体
⑤ 调平台 batch_xxx() → 拿回 {…}
⑥ 落库 + 状态流转
⑦ 响应 {…} → 前端据 X 状态渲染 Y
```
**每一步标**：失败时**谁负责报错、报什么**（别让失败静默）。
