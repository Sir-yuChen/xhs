# XHS_ALL_IN_ONE 项目架构总览

> 小红书一站式智能运营平台：**采集 → 内容库 → AI 改写 → 图片润色 → 一键/定时发布 → 全自动运营** 全链路闭环。

> - **梳理日期**：2026-09-16
> - **梳理方式**：源码、配置、数据库迁移全量通读；关键数字均经命令实测核实

---

## 1. 项目定位

项目对外是**两个身份**，共用同一套底层能力：

| 身份 | 形态 | 使用者 |
|---|---|---|
| **Web 运营平台** | FastAPI 后端 + React SPA 前端 | 运营人员（多账号矩阵 + 内容管线） |
| **XHS 底层 SDK 仓库** | `apis/` + `xhs_utils/`，逆向签名 + HTTP 接口封装 | 上层 Agent 工具链（Clawbot / Claude Code / Codex），经 [XhsSkills](https://github.com/cv-cat/XhsSkills) 引入 |

> ⚠️ README 明确标注：**仅供学习交流使用，禁止任何商业化行为**。

## 2. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 后端框架 | FastAPI + Uvicorn | 工厂模式 `create_app()`，lifespan 管理调度器生命周期 |
| ORM / 迁移 | SQLAlchemy 2.0 + Alembic | 13 个 revision 脚本 |
| 数据库 | SQLite（默认）/ MySQL（生产） | SQLite 用 `PRAGMA journal_mode=MEMORY` |
| 调度 | APScheduler `BackgroundScheduler` | 与 FastAPI **同进程** |
| 鉴权 | 自研 JWT（HS256）+ PBKDF2-SHA256 密码 | access 15min / refresh 7day，迭代 26 万次 |
| 加密 | Fernet 对称加密 | Cookie、API Key 落库前加密 |
| HTTP 客户端 | **curl_cffi** | 伪装 Chrome 146 TLS/HTTP2 指纹；**AI 服务用 requests** |
| 签名运行时 | **Node.js 子进程** | JS 算法唯一实现源，Python 侧不重复实现 |
| 前端 | React 19 + Vite 7 + TypeScript 5.9 | antd 6 + recharts 3 + @dnd-kit + zod |
| 部署 | 多阶段 Dockerfile + docker-compose | Node 构建前端 → Python 运行 |

## 4. 分层架构与调用约定

```
前端 SPA（React 19 + antd 6）
   ↓ axios（/api 前缀，自动 refresh token）
FastAPI 路由层（131 个端点，21 个 router）
   ↓
服务层 services/（AI、调度、账号、下载、限流、通知、监控爬取）
   ↓
适配层 adapters/xhs/  ← 上层唯一允许调用 SDK 的入口
   ↓
SDK 层 apis/ + xhs_utils/（curl_cffi 发请求 + Node 子进程算签名）
   ↓
小红书（PC 站 / 创作者平台 / 蒲公英 / 千帆）
```

**硬性约定**（README 明示）：`apis/` 属底层 SDK，**请勿直接修改**；上层必须经 `backend/app/adapters/` 中转调用。

**适配层细节**：每个 SDK 调用都包在 `direct_xhs_request_env()` 上下文里（`request_env.py`），加线程锁临时摘掉 `HTTP_PROXY/HTTPS_PROXY/ALL_PROXY` 等环境变量，避免本机代理污染 SDK 请求。

## 6. 数据模型（21 张表）

| 域 | 表 |
|---|---|
| 用户 | `users` |
| 账号矩阵 | `platform_accounts`、`account_cookie_versions`（Cookie 多版本加密存档）、`login_sessions` |
| 内容库 | `notes`、`note_assets`、`note_comments`、`tags`、`note_tags`（多对多关联表） |
| 草稿/AI | `ai_drafts`、`draft_assets`、`ai_generated_assets`、`model_configs` |
| 发布 | `publish_jobs`、`publish_assets` |
| 自动运营 | `auto_tasks` |
| 监控 | `monitoring_targets`、`monitoring_snapshots` |
| 系统 | `tasks`（任务审计）、`notifications`、`api_logs`、`keyword_groups` |

> 另有一张运行时表 `app_migrations`（`database.py` 内 SQL 创建，记录幂等数据修复），不计入模型层。

**账号设计要点**：`platform_accounts.sub_type` 区分 `pc` / `creator`——PC 账号负责**搜索采集**，Creator 账号负责**上传发布**。自动运营任务必须同时绑定两者（`pc_account_id` + `creator_account_id`）。

**Cookie 存储**：不覆盖写，而是往 `account_cookie_versions` **追加新版本**，取用时按 `created_at desc, id desc` 取最新；内容用 Fernet 加密。

## 9. 配置与启动

**配置优先级**：`config/default.yaml` < `CONFIG_FILE`（环境变量指定的 YAML）< `.env` < 环境变量。

关键开关（`config/default.yaml`）：

```yaml
database.type: sqlite              # sqlite | mysql
security.secret_key: "dev-only-change-me"   # 生产必改
security.fernet_key: ""            # 空则用 secret_key 派生
scheduler.enabled: false           # 定时能力总开关
frontend.serve_static: false       # Docker/生产置 true
```

**启动**：

```bash
python main.py --with-frontend     # 后端 :8000 + 前端 :5173
docker compose up -d               # 单容器，前端静态内嵌
```

**首次启动自动初始化**（`database.py:init_db()`）：跑 Alembic 迁移；若库已有表但无 `alembic_version`，先 `stamp head` 再 `upgrade head`；另跑两段幂等数据修复（`app_migrations` 表记录是否执行过）：把历史 `gpt5.4` 模型名规范为 `gpt-5.4`，把 SQLite 里存的 UTC 时间整体 `+8h` 迁到东八区。

**时区约定**：全项目用 `backend.app.core.time.shanghai_now()`，不接受裸 `datetime.now()`。
