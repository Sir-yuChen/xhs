# XHS_ALL_IN_ONE 部署与运维

---

## 1. 三种运行方式

### 1.1 本地开发

```bash
pip install -r requirements.txt
npm install                        # 根目录（签名 JS 依赖：crypto-js、jsdom）
cd frontend && npm install && cd ..
python main.py --with-frontend     # 后端 :8000 + 前端 :5173
```

- 前端 Vite dev server 代理 `/api` → `http://127.0.0.1:8000`（`frontend/vite.config.ts`）
- `main.py` 的 `--with-frontend` 会起子进程跑 `npm run dev`，后端退出时自动 terminate

### 1.2 纯后端开发

```bash
python main.py                     # 只起后端
cd frontend && npm run dev         # 另开终端起前端
```

### 1.3 Docker

```bash
docker compose up -d
```

**多阶段构建**（`Dockerfile`）：

| 阶段 | 基础镜像 | 产物 |
|---|---|---|
| Stage 1 | `node:20-alpine` | 前端构建产物 `frontend/dist` |
| Stage 2 | `python:3.11-slim` | Python 应用 + Node 20 运行时 + 前端静态文件 |

**Stage 2 关键步骤**：装系统依赖（curl、build-essential、`libgl1-mesa-glx` opencv 用、`libglib2.0-0`）→ **装 Node.js 20（签名运行时）** → pip 装依赖 → 拷源码 → 拷前端产物 → `npm install` 根目录依赖（crypto-js、jsdom）→ 建数据目录 → 设环境变量 → 健康检查 → 启动。

**环境变量默认值**（Dockerfile）：

```env
PYTHONUNBUFFERED=1
NODE_ENV=production
FRONTEND_SERVE_STATIC=true         # 后端直接serve前端静态文件
CONFIG_FILE=/app/config/default.yaml
```

## 2. 数据卷

| 宿主路径 | 容器路径 | 内容 |
|---|---|---|
| `./data` | `/app/data` | SQLite 数据库（`spider_xhs.db`） |
| `./config` | `/app/config` | YAML 配置 |
| `./backend/app/storage/media` | 同名 | 下载的图片/视频素材 |
| `./backend/app/storage/exports` | 同名 | JSON/CSV 导出文件 |

> 迁移部署时这四个目录必须一起搬。**素材和导出文件存在代码目录下**（`backend/app/storage/`），不在 `data/` 里——备份时容易漏。

## 3. 配置体系

**优先级**（低 → 高）：

```
config/default.yaml  <  CONFIG_FILE 指定的 YAML  <  .env  <  环境变量
```

YAML 的嵌套 key 会被 `config.py:_load_yaml_config()` 映射成扁平的 Settings 字段名（如 `database.sqlite_path` → `database_sqlite_path`）。

### 完整配置项

```yaml
server:
  host: "0.0.0.0"
  port: 8000
  cors_origins: "http://localhost:5173,http://localhost:3000,http://127.0.0.1:5173"

database:
  type: "sqlite"                    # sqlite | mysql
  sqlite_path: "./data/spider_xhs.db"
  mysql_host: localhost
  mysql_port: 3306
  mysql_user: spider_xhs
  mysql_password: change_me
  mysql_database: spider_xhs

security:
  secret_key: "dev-only-change-me"  # 生产必改
  fernet_key: ""                    # 空则由 secret_key 派生（见风险篇）

scheduler:
  enabled: false                    # 定时能力总开关
  interval_seconds: 60

frontend:
  serve_static: false               # Docker/生产置 true
  build_dir: "./frontend/dist"
```

**环境变量映射**（YAML key → 环境变量，全大写）：`server.host`→`SERVER_HOST`、`database.type`→`DATABASE_TYPE`、`security.secret_key`→`SECRET_KEY`、`security.fernet_key`→`FERNET_KEY`、`scheduler.enabled`→`SCHEDULER_ENABLED` 等。

**生产环境必做的配置**：

1. `SECRET_KEY` 换成随机长串
2. **`FERNET_KEY` 显式固定**（否则改 secret_key 会导致历史 Cookie/API Key 全部解不开）
3. `DATABASE_TYPE=mysql` + MySQL 连接信息
4. `SCHEDULER_ENABLED=true`（否则定时发布/自动运营/Cookie 巡检全不生效）

## 4. 启动流程（`main.py` + lifespan）

```
main.py
  ├ 解析 CLI 参数（--host --port --reload --with-frontend --frontend-port）
  ├ 从 Settings 解析 host/port（CLI 在默认值时才用配置）
  ├ （可选）subprocess 启动前端 Vite
  └ uvicorn.run("backend.app.main:app")
       └ create_app()
            ├ CORS 中间件
            ├ /api/health 端点
            ├ 挂载 21 个 router（全部 /api 前缀）
            └ （serve_static 时）SPA 静态回退中间件 + StaticFiles
       └ lifespan
            ├ init_db()                    Alembic 迁移 + 幂等修复
            ├ scheduler_enabled → start_due_publish_scheduler()
            └ shutdown 时关闭调度器 + terminate 前端子进程
```

**SPA 回退**：`frontend_serve_static=true` 时，所有 404 且非 `/api` 前缀且路径最后一段不含 `.` 的请求，都回 `index.html`，交给前端路由。

## 5. 健康检查与可观测性

| 手段 | 位置 |
|---|---|
| 健康端点 | `GET /api/health` → `{"status": "ok"}` |
| Docker healthcheck | 每 30s curl 一次（`start-period=10s`） |
| API 文档 | `http://localhost:8000/docs`（FastAPI 自动生成） |
| 任务审计 | `tasks` 表 + `/api/tasks` 任务中心 |
| 通知 | `notifications` 表 + 前端铃铛 |
| 日志 | Python `logging`（调度器用 `logger.info/warning/error`） |

> 日志未做结构化/采集接入，生产环境需自备日志收集。

## 6. 数据库运维

- **默认 SQLite**：`data/spider_xhs.db`，`PRAGMA journal_mode=MEMORY`（**非 WAL**），高并发写容易锁表
- **生产建议 MySQL**：`mysql+pymysql`，`charset=utf8mb4`
- **迁移**：启动时自动跑；也可手动 `alembic upgrade head`
- **旧库兼容**：有表但无 `alembic_version` → 自动 `stamp head`
- **路径兼容**：老默认路径 `./backend/app/storage/spider_xhs.db` 存在且新路径不存在时自动沿用
- **时区修复**：SQLite 历史 UTC 数据整体 `+8h`（幂等，`app_migrations` 记录）

## 7. 常见运维操作

| 场景 | 操作 |
|---|---|
| 重启调度器 | 重启进程（无热更新开关） |
| 手动触发自动运营 | 调 `POST /api/auto-tasks/{id}/trigger`（`manual` 类型只能这样触发） |
| 手动补跑定时发布 | 调度器开启后下一轮 60s 内自动补跑；或参考 `run_due_publish_jobs_once()` |
| 手动 Cookie 巡检 | 调度器开启后 2h 内执行；或参考 `check_all_account_cookies_once()` |
| 查看调度器状态 | `GET /api/tasks/scheduler` |
| 清理素材 | `backend/app/storage/media/`（前端图片管理页只删库记录，**文件需手动清**） |

## 8. 运行时依赖

| 依赖 | 用途 | 缺失后果 |
|---|---|---|
| **Node.js 20+** | 执行签名 JS（`xhs_utils/**/js/`） | 全部采集/发布失败 |
| crypto-js、jsdom（根 `package.json`） | 签名 JS 运行时依赖 | 同上 |
| curl_cffi | TLS 指纹伪装 | 请求被风控 |
| opencv-python / Pillow | 图片处理（webp→jpeg 等） | 素材转换失败 |
| PyExecJS | JS 执行备用 | — |

> **Node 是硬依赖**：Docker 镜像专门在 Python 镜像里又装了一遍 Node 20。本地开发必须先 `npm install`（根目录），否则签名调用报错。
