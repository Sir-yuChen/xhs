## 二、验收主体（按链路走）

## 链 1 · 账号接入链

> **业务目标**：一个新账号，从扫码登录到「能被商品/笔记链路使用」。

| 步 | 在哪 | 点什么 | 应看到 |
|---|---|---|---|
| 1 | 平台选择页 `/platform-select` | 点「小红书」卡片 | 进 `/platforms/xhs/dashboard` |
| 2 | 账号矩阵 `/platforms/xhs/accounts` | 点「添加账号」 | 弹窗居中弹出，三个登录方式（扫码 / 手机号 / 千帆邮箱）|
| 3 | 同上弹窗 | 走**扫码**登录（若不方便重启会话：用**一个已退出登录**的账号点「补登」，效果等价） | 成功后**弹窗自动关闭**（不用手点）|
| 4 | 账号矩阵卡片 | 点卡片上「**去补登千帆**」 | 弹窗扫码 → 绑定成功 |
| 5 | 账号矩阵卡片 | 看卡片 | 显示**店铺名**（如「观隅好物」）、粉丝/关注/获赞**三项有数字** |

**✅ 链路通过判据**：卡片上「同步商品」「同步商品笔记」**可点**（未绑千帆时这两个是灰的）—— 这才叫「账号可用」。

**⚠️ 断链点**
- 第 3 步弹窗不关 ⇒ DEF-073 回归
- 第 5 步粉丝数恒 `0`/空 ⇒ DEF-039 回归
- 第 5 步显示「未检测」且**点不动** ⇒ DEF-084 回归（过期判据漏了平台码）

### A 组 · 平台与账号基建

#### A1 · 平台选择页

- **入口**：登录后自动落地 `/platform-select`
- **操作**：观察页面
- **期望效果**：显示「小红书」卡片（已启用）+「大模型网关」独立卡片；其余平台显示「即将上线」
- **判定**：① 两个卡片都在；② 点小红书卡片进 `/platforms/xhs/dashboard`；③ 点网关卡片进 `/llm-gateway`

- 🔲

#### A2 · 平台列表失败态（DEF-023 修复点）

- **入口**：同上（需**故意**制造后端不可达）
- **操作**：停掉后端 → 刷新 `/platform-select`
- **期望效果**：显示**红色 Alert**「平台列表加载失败」+ 具体原因
- **判定**：**不再**显示小红书的假卡片列表（旧行为是静默用前端副本兜底、掩盖后端故障）

- 🔲

#### A3 · 账号卡片与登录

- **入口**：侧栏「账号矩阵」`/platforms/xhs/accounts`
- **操作**：加账号 → 扫码 / 手机号 / 千帆邮箱三种方式各试一次
- **期望效果**：成功后卡片出现，**弹窗自动关闭**；昵称/头像/粉丝数正确
- **判定**：① 弹窗自动关（DEF-073 修复点）；② 粉丝/关注/获赞三项**有数字**（DEF-039 修复点，不该恒空）

- 🔲

#### A4 · 账号同步入口

- **入口**：账号矩阵 → 某账号卡片
- **操作**：点「同步笔记」→ 再点「同步商品」→ 再点「同步商品笔记」
- **期望效果**：三个按钮各自发起任务；按钮态变「同步中…」；页面**不再**出现独立进度卡（§35.18 后收敛）
- **判定**：① 三按钮都对（商品笔记是独立任务，§44 拆分）；② 该账号已有任务在跑时**只提示不重复触发**（「该账号已有同步任务在跑，本次未触发新执行。」）；③ 触发失败走 `message.error` 报**真原因**；④ 卡片内**无进度区块**（进度/结果去任务中心「任务日志」看）

- 🔲

#### A5 · 千帆重新登录提示

- **入口**：账号矩阵
- **操作**：找一个千帆会话**已过期**的账号（或手工清掉其 ark 令牌）
- **期望效果**：卡片出现「重新登录千帆」入口，**能点**（DEF-084 修复点）
- **判定**：不是「未检测」这类不给入口的状态

- 🔲

#### A6 · 账号删除

- **入口**：账号矩阵 → 卡片操作
- **操作**：删除一个测试账号
- **期望效果**：列表消失；用**旧 id** 再发任何请求都 404（软删闸，DEF-055）
- **判定**：删除后该账号不出现在任何下拉 / 筛选里

- 🔲

### B 组 · LLM 网关与服务商

#### B1 · 服务商 CRUD

- **入口**：`/llm-gateway` → 「服务商」页签
- **操作**：新增一个服务商（填 base_url + key）→ 编辑 → 删除
- **期望效果**：增删改都生效；列表里**看不到令牌**
- **判定**：① 响应里令牌字段**恒不返回**，只有 `has_access_token` 布尔（安全设计）；② 删除有二次确认

- 🔲

#### B2 · 连通性测试

- **入口**：服务商页签 → 某行「测试」
- **操作**：点测试（先配一个**有效的** base_url + key）
- **期望效果**：返回真实连通结果（成功/失败都有明确文案）
- **判定**：失败时给的是**平台原文原因**，不是「未知错误」

- 🔲

#### B3 · 模型全生命周期同步

- **入口**：服务商页签 → 服务商行的「同步模型」
- **操作**：点同步
- **期望效果**：拉回该服务商可用模型清单，落模型行
- **判定**：同步后能在模型行里看到 `healthy` / `last_health_at` / 类型（text/image/video）

- 🔲

#### B4 · 模型级健康检查

- **入口**：服务商页签 → 展开模型子表
- **操作**：对某模型行点「检查」
- **期望效果**：该行 `healthy` 状态刷新，带时间戳
- **判定**：健康是**模型维度**的（不是服务商一个总开关）

- 🔲

#### B5 · 预警规则

- **入口**：`/llm-gateway` → 「预警规则」页签
- **操作**：新增一条规则（如日用量超阈值）→ 触发条件 → 看是否落站内通知
- **期望效果**：规则可增删改；命中后 `notifications` 有站内通知
- **判定**：内置任务「LLM 网关监控」（每 10 分钟）在任务中心可见且启用

- 🔲

#### B6 · 用量看板

- **入口**：`/llm-gateway/usage`（网关区第一个菜单，也是进入网关的默认页）
- **操作**：看三段时间总览卡 / 30 日趋势图 / 四维拆分 / 明细表 + 筛选
- **期望效果**：数据来自**本地台账** `llm_gateway_usage_logs`（不是 New API 的库）
- **判定**：调用过 LLM 后（例如做 H 组生成）这里数字**会动**

- 🔲

#### B7 · 停用在用模型被拦

- **入口**：服务商 → 模型子表
- **操作**：尝试停用一个**正被业务点使用**的模型
- **期望效果**：**400** `LLM_MODEL_IN_USE_BY_BUSINESS`（带说明）
- **判定**：不是静默停用（静默停会让业务链路突然报找不到模型）

- 🔲

## 链 17 · 系统更新链（2026-10-13 用户需求，设计 36）

> **业务目标**：装了新版才知道自己是什么版本、有新版能升上去，**且升级不动历史数据**。
> 两个入口语义不同：**打开软件**那次**强制**，**顶栏图标**那次由用户**自行选择**。

|---|---|---|---|
| 1 | 打开软件 | 等启动检查跑完 | 若**无新版**静默（不打扰）；若有新版 ⇒ 弹窗**不可关闭**（无 X、点蒙版不关），标题「发现新版本」，**无**「暂不更新」|
| 2 | 顶栏图标 | 点「检查版本更新」 | 弹窗出现，标题「检查版本更新」；**可关**（右上 X / 点蒙版 / 「暂不更新」）；打开即自动查一次 |

| 5 | 有新版本时 | 点「下载」→「立即安装并重启」 | 进度条 → 装完自动重启；**重启后账号 / 笔记 / 历史数据全在**（`data/` 不被覆盖）|

第 5 步升级后**数据零丢失**。

**⚠️ 断链点**
- 启动入口**没有**强制（能关掉就跑了）⇒ 断链（用户口径「只有在每次软件打开时的入口才要求强制更新」）
- 手动入口**不可关**（用户主动点的检查，必须能选择不更新）⇒ 断链
- 弹窗尺寸不是**视口 40%**（宽 40vw + 高 40vh；口径连续改过 56vw→50vw→40%）⇒ 断链
- 「已是最新」时**不显示版本历史**（只剩一行绿字 + 大片空白）⇒ 断链（本轮实测踩到并修）
- `version.json` 只留最新一条（丢失历史）⇒ 断链
- 更新详情里出现 `##` / `**` 等 Markdown 符号（在纯文本处原样显示）⇒ 断链
- 升级后 `data/` 被删 / 被覆盖 ⇒ 断链（**最高风险**；守卫：安装器不得有 `[UninstallDelete]`）
- 仓库**私有**时未带令牌却报「已是最新」（假结论）⇒ 断链（公开仓库免令牌）
