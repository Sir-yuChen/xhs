# 第二阶段 · 业务链路全链路验收手册（按链路走）

> **用途**：**用户手动验收用**。与 `09_第二阶段功能点全链路验收清单.md` 的区别：
> - `09` = **单点清单**（107 条，一个功能点一条）—— 适合查「有没有这个功能」
> - **本文件** = **串联链路**（12 条，一个业务目标一条）—— 适合查「这条业务跑不跑得通」
>
> 每条链路 = **一串前端按钮按真实业务顺序** → 末端拿到一个**业务结果**。
> 判据放在**链路末端**：末端对，链路上每一步都会顺；末端错，能一眼看出断在第几步。
>
> **建立**：2026-10-04　**前置**：后端 + 前端在跑，登录主测试账号 `18739473138`，账号矩阵里有一个**已绑千帆**的账号
> **验收进度**：🔲 未验 / 🔵 通过 / 🔴 断链（写断在第几步 + 看到什么）

**怎么用**：一条链路从上往下走完，把末端的 `🔲` 改 `🔵`。断了标 `🔴` + **第几步** + 现象。
**可以跳**：链 9（写操作，需真实待发货订单）；**AI 生成类链路当前会以「400 结构化原因」失败**（上游 LLM Key 401，非代码问题），换 Key 后即可跑通。

## 链 7 · **人工审核发布链**（最长的链）

> **业务目标**：工作流**自动**从话题跑到「待人工审核」，人放行后才发布。
> 这是本项目「**不许全自动发布**」这条硬口径的验收链路。

| 步 | 在哪 | 点什么 | 应看到 |
|---|---|---|---|
| 1 | 工作流 `/platforms/xhs/workflows` | 「新建工作流」 | 填名 → 选节点（topic / generate / **review** / schedule / publish / monitor）|
| 2 | 同上 → 触发器 | 设「定时」（cron）| 保存后**任务中心**出现该工作流的 job 行 |
| 3 | 同上 → 工作流行 | 「**立即执行**」 | run 开始；**连点第二次应 409**（工作流级互斥）|
| 4 | 同上 → 运行记录 | 看节点链 | 自动节点依次完成，跑到 **review 节点**停住（`waiting`）|
| 5 | 同上 → 「**待我审核**」 | 点某条 | 看到待审笔记内容 |
| 6 | 同上 | **通过** / **驳回** | 通过 ⇒ 下游继续；驳回 ⇒ run `failed(review_rejected)` 且**下游不执行** |
| 7 | 队列记录 `/task-records` | 筛发布队列 | 出现 `workflow_publish` 条目（发布下沉队列）|
| 8 | 任务中心 / 排期 | 看排期 | 排期在**独立表**，`notes.scheduled_publish_at` **未被写入** |
