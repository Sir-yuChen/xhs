1. 为什么要合

现状：33 列描述同一个小红书账号，却散在 3 张表里。
platform_accounts（18 列，身份）· account_cookie_versions（4 列，会话，11 行历史）· login_sessions（11 列，登录过程，226 行里 194 条 pending 是垃圾）。

每条「这个账号能不能用千帆」的判定，都要跨 2 张表 join： has_ark_session() → qianfan_cookies_for_account() → 查 account_cookie_versions 按 created_at desc 取最新一行 → 解密 → 按通道拆信封 → 取 ark。 这个「跨表取最新」在 20+ 个调用点重复出现，且注释自承「无法在 SQL 里过滤，只能逐条判定」。

4. 等级判定（按 77 规范）

L1xhs_accounts = 小红书工作区私有表

  • C1 表名带 xhs_ ✅
  • C2 原 platform 列 NOT NULL ✅（说明平台曾是隔离维度）
  • C3 平台专有列：sub_type / seller_id / shop_state / external_user_id ✅

合并后 platform 列删除，因为表名已表达工作区 —— 这正是「两级规范」的落地效果：隔离维度从「列值」上提到「表名」。

5. 影响面与验证判据

代码影响

  • 后端 49 个文件引用 PlatformAccount / AccountCookieVersion / LoginSession
  • 前端 15 个文件
  • ORM 类：PlatformAccount → XhsAccount，删 AccountCookieVersion / LoginSession
  • 服务层 account_service 的「跨表取最新」逻辑简化为单行读字段

迁移验证（四步）

  • ① 副本 upgrade：3 表 → 1 表，数据搬对
  • ② 重跑 upgrade：幂等
  • ③ downgrade：还原 3 表 + 历史行
  • ④ 再 upgrade
核心判据（合并后必须逐条实测）：
  • has_ark_session(7/8/9) 与合并前逐账号同值 —— 这是 20+ 个调用点的唯一真值来源
  • qianfan_cookies_for_account(id) 返回串与合并前逐字节一致（同一份加密信封解出来的）
  • 5 个账号的 external_user_id / sub_type / status 全部不变
  • 唯一键 (user_id, sub_type, external_user_id) 仍然拦得住重复绑定

6. 风险与取舍（必须说清）

⚠️ 我原本判断「cookie 历史是故意的」，查证后修正了：
代码注释写的是「无法在 SQL 里过滤，只能取到存活账号后逐条 has_ark_session 判定」—— 这说明历史多行是当时没做 JSON 列时的妥协，不是功能需求。所有读点（20+ 处）最终都归到 「取最新、按通道拆、返回字符串」，没有任何一处读「第几版」。
合并后反而能在 SQL 里直接 WHERE cookies_json->>'ark' IS NOT NULL 过滤，是净收益。
保留的取舍：cookie 历史压缩为「每通道最新一份」后，放弃「回溯某次登录前的令牌状态」能力。 当前没有任何代码用它，且令牌失效时的处理是「重新登录」而非「回滚到旧令牌」。若将来需要审计，可加 xhs_account_cookie_log（历史表，只写不读）—— 但那会重新变成两张表，建议等真需要时再加。

7. 不合并的同类（避免过度合并）

表对判断原因
draft_assets（1 行）→ ai_drafts.assets_json 暂不合并 有独立 CRUD 端点（GET/POST/DELETE + 重排 sort_order）。压成 JSON 要把「重排/单条删/单条加」全改成读-改-写，反而引入并发覆盖
ai_generated_assets（0 行） 暂不合并 draft_id 可空 ⇒ 它是「一次 AI 生成调用」的记录，不是草稿附件。合并会丢历史
notes + note_topics 保留分表多对多关系，一篇笔记 N 个话题
no_traffic_cleanup_logs + items 保留分表一次清理 N 条明细（父行 8 / 子行 5，但结构是一对多）
llm_gateway_*（4 张） 保留分表配置 / 模型 / 预警 / 用量账本，四个不同概念；usage_logs 171 行是时序
判据（写进 77 规范）：从属表如果「一个父行对应 N 行」且 N 可能几十上百 ⇒ 分表； 如果「恒为 0 或 1 行」⇒ 合并成 JSON 列。账号域的三张表属于后者（cookie 每通道 1 份、登录历史 1 条）。
