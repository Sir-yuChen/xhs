## 一、10 句话需求

1. **开发者的角色**：在现有逆向 SDK 与运营后台基础上做增量开发的工程师，不重写底层，只做扩展。
2. **项目名称**：XHS_ALL_IN_ONE · 我的笔记列表。
3. **本次要加的功能**：在左侧菜单新增「我的笔记」入口，展示**当前登录账号在小红书平台侧的自有内容与互动数据**。
4. **主要用户**：需要复盘自己账号内容表现的运营者（我发了什么、效果如何、谁在评论）。
5. **四个 Tab**：我发布的 / 我赞过的 / 我收藏的 / 互动消息，用 Tab 自然隔离，不混在一起。**「我发布的」须同时支持 PC 账号与创作者账号**（创作者账号同样能发布笔记，且店铺相关内容正是创作者账号的能力），按账号实际具备的链路选数据源。
6. 每条笔记以卡片展示：封面、标题、**点赞数**、发布时间、图文或视频标识。
   **卡片不做正文摘要**（D6）：列表接口实测不返回正文，硬做需要为每条笔记补发一次请求，已拍板不做。
7. 点开卡片**以弹窗展示详情**：正文、图片列表（可左右切换）、视频（可播放）、**笔记原始链接**（可跳出到小红书），以及该笔记的**评论列表**。正文 / 多图 / 视频 / 完整互动数都在**弹窗打开时按需拉取一次详情**取得（D7）。
8. 若该笔记挂了商品，详情里额外展示**商品信息**（标题、价格、主图、商品链接）。商品数据来源改为**千帆商家后台**（D8）——PC 网页链路实测不返回该字段。
9. 素材以**平台 CDN 直链**方式展示，用户点「下载」时才落到本地。
10. **数据边界（重要）**：全部**实时从平台读取，完全不入库**。本需求不新增数据表，不改动 `notes` 相关表。

## 二、需求条目

| # | 需求 | 优先级 | 口径 |
|---|---|---|---|
| **R1** | 我发布的笔记 | 高 | 当前账号作为**作者**发布的笔记列表，分页加载。**PC 与创作者账号均须支持**（D5） |
| **R2** | 我赞过 / 我收藏的笔记 | 中 | 当前账号在小红书站内互动过的笔记列表，分页加载；**仅网页会话账号**（D9） |
| **R3** | 互动消息 | 中 | 赞和收藏通知 / @我的 / 新增关注，分页加载；**仅网页会话账号**（D9） |
| **R4** | 笔记详情与评论 | 高 | **弹窗内**展示单条笔记的正文 + 完整媒体（图文多图可切换 / 视频可播放）+ 原始链接 + 评论列表；详情按需拉取（D7）。**创作者链路上正文 / 视频 / 评论结构上不可得 → 不发请求、不渲染**（D11） |
| **R5** | 挂载商品信息 | 中 | 详情内展示笔记所挂商品；**数据源为千帆商家后台（D8）** —— ✅ **2026-09-19 已实现**：绑定千帆店铺后，卡片与弹窗按 `note_id` 显示商品（标题 / 主图 / 规格 / 商品链接）；**价格（v1.6 补齐）**由千帆商品列表接口按页批量补一次（`¥ 54.40~144.00` 形态，同价则单值），拿不到就留空。**映射的补齐方式（v1.8 定调）**：**加载笔记时按需补齐**这几条笔记的商品（见 R5b），不做后台全量同步。未绑定时页面给出**可执行**的绑定入口 |
| **R5a** | **商品价格** | 中 | 千帆商品笔记列表**不含**价格（实测），价格只能来自商品接口。实现口径：**每页最多 1 次**批量查询（多个商品 ID 逗号拼接 `whole_keywords`）、失败**静默留空**、**不缓存**（价格随时会变）。理由与代价见设计 12 §24.4.1 |
| **R5b** | **商品映射按需补齐（v1.8 定调）** | 高 | **不做后台全量同步**；**加载笔记时**才同步这一页笔记挂载的商品：千帆 `goods-note/list` 的 `note_ids` 支持逗号分隔多个笔记 ID，**每页 ≤1 次**只读请求；命中即落库，第二次浏览该页**零请求**；失败静默（页面照常渲染），凭据失效标 `invalid` 并给「重新绑定」入口。契约见设计 12 §24.1.1 / §24.3.2 |
| **R6** | 素材按需下载 | 低 | 单个图片 / 视频的手动下载 |
| **R7** | **列表无限滚动** | 高 | 笔记列表与互动消息列表**滚动到底部自动加载下一页**，**移除「加载更多」按钮**；失败即停并给显式「重试」（D13） |
| **R8** | **跨分类关键词搜索** | 中 | 在「我发布的 / 我赞过的 / 我收藏的」范围内按关键词检索，**结果必须标注来源分类**并给出「已扫描多少页」；仅网页会话账号可用（D14） |
| **R9** | **弹窗评论区固定尺寸** | 中 | 详情弹窗**整体不滚动**；正文区与评论区**各自内部滚动**，评论区**固定高度**（不随评论多少跳动）（D15） |
| **R10** | **互动数据缺值的展示口径** | 中 | 账号级三项计数（粉丝 / 关注 / 获赞数）取不到时**渲染 `0`**（不再渲染 `-`），并在卡片内给一行 **25–30 字**的可读原因；**小红书号**取不到仍渲染 `-`（它不是计数）。Creator 账号的计数来源**不再追**（实测结构不可得，按 WONTFIX 收口）（D16） |
| **R11** | **商品链接的展示形态** | 中 | 笔记详情弹窗里，挂载商品的链接**以文本展示**（完整 URL 可见、超长省略）、**点击即复制**到剪贴板并给成功提示；**不再做成跳转链接**（用户要的是把链接拷去别处用）（D17） |

## 三、约束

### 3.1 用户侧约束（硬约束，不可绕过）

| # | 约束 | 后果 |
|---|---|---|
| **C1** | `user_posted`（我发布的）**需要 URL 级 `xsec_token`**，而它不是 Cookie | 「纯 API 全自动取自己的笔记」**可能不可行**，必须保留「手工粘贴主页 URL」的降级路径。见 §四 P1 |
| **C2** | 只能读**当前账号自己**可见的数据 | 不做「任意博主的私域数据」；赞过/收藏本身是公开可见的，但本需求只用于自己的账号 |
| **C3** | 账号必须处于可用状态且 Cookie 有效 | Cookie 失效时**给出可读原因**，不静默返回空列表 |

### 3.2 技术侧约束（来自现状代码与项目硬约定）

| # | 约束 | 说明 |
|---|---|---|
| **C4** | **不修改 `apis/`**，只能经 `backend/app/adapters/xhs/` 中转 | 架构硬约定（`03_开发文档/01` H-6） |
| **C5** | **禁止调用 SDK 的全量循环方法** | `get_user_all_notes` / `get_all_likesAndcollects` 等会翻页到 `has_more=false`，几百条笔记会产生几十次请求，直接触发风控。**必须用单页方法 + cursor 透传** |
| **C6** | **纯实时，不落库** | 不新增表、不写 `notes`。避免「实时数据污染内容库」与「重复采集」两个既有问题 |
| **C7** | 沿用现有 PC 链路（`sub_type='pc'`） | 不改签名、不加新平台配置；`apis/xhs_pc_apis.py` 的能力已齐备 |
| **C8** | 不影响一期任何现有功能 | 现有 `/xhs/pc/notes/detail`、`/notes/comments` 行为不变 |
| **C9** | 不依赖 `ark.xiaohongshu.com`（千帆） | 本需求走 PC 站内链路，**不受 M0 门禁与商品笔记自动化的抓包阻塞** |

## 七、非功能需求

| 类别 | 要求 |
|---|---|
| **风控（最高优先）** | ① 一律单页请求，不做后台全量预热；② 切 Tab 才发请求，不轮询；③ 不做「一键拉全部历史笔记」；④ **搜索是有界扫描**（每类 ≤ 5 页、默认 3，模型硬夹紧），不做全量翻页；⑤ **无限滚动**一页一请求、in-flight 去重、**失败即停**，不做自动重试与后台预取（D13 / D14） |
| **性能** | 列表首屏 ≤ 3s（受平台响应影响，超时给可读提示而非转圈不动） |
| **错误可见性** | Cookie 失效 / 无权限 / 平台限流 → **必须给可区分的中文原因**，不得静默显示空列表 |
| **数据真实性** | 互动数、商品信息**一律来自平台**；解析不到的字段留空并标注，**禁止填 0 或占位假值** |
| **安全性** | Cookie 沿用现有加密存储（`account_cookie_versions`）；**接口必须鉴权并校验账号归属** |
| **兼容** | 一期所有现有功能的行为与接口保持不变 |

## 十、决策点

### 10.1 已拍板（2026-09-18）

| # | 决策 | 结论 | 影响 |
|---|---|---|---|
| **D1** | 「笔记列表」的范围 | ✅ **四个 Tab 全做**：我发布的 / 我赞过的 / 我收藏的 / 互动消息，**用 Tab 自然隔离** | R1–R3 全部保留；互动消息内部再分子类。工作量最大的一档，但边界清晰、互不干扰 |
| **D2** | 数据是否落库 | ✅ **纯实时拉取，完全不落库** | **无数据表变更、无迁移**（显著降低风险）；同时放弃「保存到内容库」按钮 |
| **D3** | 素材策略 | ✅ **引用平台 CDN 直链 + 按需下载** | 零额外存储；**UI 须说明 CDN 链接有时效性**，久置后可能失效 |
| **D4** | 「链接」的含义 | ✅ **两者都要**：笔记原始链接 + **笔记挂载的商品链接** | 引入 R5 与未知量 P2；商品解析按「尽力解析 + 优雅降级」实现 |

### 10.3.1 第三轮拍板（2026-09-18，真机样本后）

|---|---|---|---|
| **D10** | 商品相关提示是否保留 | ✅ **改为：只保留可执行的绑定入口** | v1.1 的「一律不提示」成立于「结构上不可能有数据」。现在数据可得，于是**未绑定**时给一条 Alert + 「绑定千帆」按钮（用户自己能解决的事），**绑定后不再有任何提示**，只显示商品与同步覆盖率。逐条「未解析」提示仍不做（逐条假警）。修订于 2026-09-19 |

### 10.3.2 第四轮拍板（2026-09-18，页面体验优化）

| # | 决策 | 结论 | 影响 |
|---|---|---|---|
| **D13** | 列表翻页方式 | ✅ **改为滚动到底部自动加载下一页，「加载更多」按钮移除** | 触发粒度仍是**用户的一次滚动**（与点按钮同阶），风控面不因此上升；护栏：一页一请求、in-flight 去重、**失败即停 + 显式「重试」**、无自动重试、无后台预取（设计文档 §20）。**取代** v1.3「显式按钮」的结论 |
| **D14** | 关键词搜索的范围与实现层 | ✅ **服务端有界扫描**：每类（我发布的 / 赞过的 / 收藏的）最多 N 页（默认 3、上限 5），返回命中项 + **来源分类标签** + 扫描元数据，可带游标续搜 | **不**调全量循环（C5）；也**不**做「只搜当前已加载的一页」（会给用户错误的"没有"）。仅网页会话账号可用，creator 链路置灰并说明（设计文档 §22） |
| **D15** | 详情弹窗的滚动形态 | ✅ **弹窗整体固定不滚动**；正文区与评论区**各自内部滚动**，评论区**固定高度 280px** | 用固定 `height`（不再用 `maxHeight`），消除「短/长笔记骨架不同」与「评论到达时高度跳动」；窄窗降级为 body 内滚（设计文档 §23） |
| **D16** | **互动数据缺值的展示口径 + Creator 计数是否继续追** | ✅ **缺值渲染 `0`**（不是 `-`），卡片内保留一行 **25–30 字**的原因；**Creator 计数不再追**（WONTFIX） | 用户 2026-09-18 拍板。① `0` 是**展示层默认值、不是数据事实**——「真 0」与「没取到」的区分责任交给那行原因，`profile_json` 仍写「未知」，**不得把 `None` 改写成 0**；② 原因文案一律 25–30 字、超长由后端截断到 30 字（前端不硬编码业务判断）；③ 依据 §21.3 实测（身份接口无计数、数据中心候选端点 404），Creator 侧无可用来源，跟踪卡⑧ 按 WONTFIX 收口 |

### 10.3.4 第五轮拍板（2026-09-19，千帆商品接线验收后）

| # | 决策 | 结论 | 影响 |
|---|---|---|---|
| **D18** | 商品映射的补齐方式 | ✅ **加载笔记时按需补齐**（2026-09-19 用户定调） | 用户原话：「千帆商品映射改为后台全量同步，**不改为全量**，而是**加载笔记时才同步**对应笔记挂载的商品」。理由：店铺近 2000 条商品笔记≈上百页，而一页只显示 10 条，全量慢跑每轮都要重翻、且大部分页可能永不被打开；按需补齐把成本精确投在用户真正看的那一页，且命中即落库（第二次零请求）。实现见设计 12 §24.1.1 / §24.3.2 |

### 10.4 推翻 v1.0 假定的实测证据（D8 的依据）

`R5` 在 v1.0 中默认「PC 详情接口返回商品字段」。2026-09-18 用真实账号（`pc` 类型，Cookie 当日更新）实测**三条链路全部无商品字段**：

| 链路 | 接口 | 实测结果 |
|---|---|---|
| 我发布的列表 | `/api/sns/web/v1/user_posted` | 返回项**仅 8 个字段**：`cover, display_title, interact_info, note_id, time, type, user, xsec_token` |
| 搜索列表 | `/api/sns/web/v1/search/notes` | `note_card` 无商品字段；`corner_tag_info` 只有 `publish_time` |
| 笔记详情 | `/api/sns/web/v1/feed` | `note_card` 13 个字段，raw ≈ 5.5 KB 全键名正则扫描 `goods\|item_id\|product\|commerce\|sku\|mall\|shop\|jump\|scheme\|link\|biz` **零命中** |

> 旁证：`xhs_utils/xhs_creator_util.py:177,246` 的**发布载荷**里存在 `goods_info` 字段（默认为 `{}`），
> 说明平台侧确有此概念，只是**PC 读取链路不返回**。App 端能看到商品，是因为 App 走的是另一套接口。
