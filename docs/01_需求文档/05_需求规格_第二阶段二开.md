# 第二阶段二开 · 需求规格说明书（总体）

> **体系位置**：`01_需求文档/`（阶段一产出，面向小模型，宁短勿长）
> **建立**：2026-09-29　**状态**：草案（待评审）
> **关联**：详细需求见 `02_设计文档/16_功能设计_第二阶段二开.md`

---

## 1. 一句话定位

在一期「账号矩阵 + 采集 + 内容库 + 商品笔记自动化 + 发布 + 监控」已跑通的基础上，第二阶段把平台从
**「半自动运营工具」升级为「AI 驱动的全链路内容生产与数据运营中台」**：自建第二条（LLM 生成）与
第三条（热点驱动）笔记生产链路，补齐媒体资源生成与本地素材库、三平台数据仪表盘（商品监控 + 笔记监控）、商品编辑优化，并合并发布/运营
中心为可编排的自动化工作流，实现「选题 → 生成 → 审核 → 定时 → 发布 → 监控 → 复盘」一键闭环。

## 2. 角色与用户

| 角色 | 说明 |
|---|---|
| 开发者 | 本项目唯一实现方（文档先行，按 §5 硬约束施工） |
| 使用者（运营者） | 小红书带货/种草类账号与店铺运营者，管理多账号矩阵，用 AI 批量生产商品笔记并追踪效果 |

## 3. 背景与目标

- **一期已交付**：账号矩阵（三平台令牌、店铺↔账号 1:1）、采集、内容库、笔记工坊（草稿 AI）、
  商品笔记自动化（千帆智能生成 = **第一套生成链路**）、发布队列、同步队列、定时任务中心、桌面打包。
- **二期总体目标**：把「靠官方千帆智能生成」这一条腿，补成「官方 + 自研 LLM + 热点驱动」三条腿，
  并用统一的数据仪表盘与自动化工作流把生产、发布、复盘串起来。

**衡量标准（可验收）**：
1. 从「一件商品」到「一篇可发布笔记（含文案 + 封面图/视频 + 话题）」一键产出，全程无需人工写文案；
2. 一条笔记的完整生命周期数据（曝光/互动/转化/归因）可在仪表盘一站式查看、跨账号对比；
3. 一个工作流可编排并一键执行「多商品 → 多笔记 → 定时 → 多账号发布」；
4. 文档体系体积压减 ≥ 50%，核心「现状」结论无缺失、可回溯。

|---|---|---|---|

| 2 | 热点驱动生成 | 主动学习平台热门话题/商品 → 生成对应笔记+标签+媒体 | P1 |

| 4 | 商品编辑优化扩展 | 媒体资源、AI 生成商品图/视频、商品编辑、商品列表功能扩展 | P1 |

## 5. 各方向要点（概要）

### 方向 0 · 文档体系蒸馏
- **现状问题**：`docs/` 60 文件 2.94MB，最大膨胀源是各设计文档堆叠的「演进链/修订史」（如
  `13_账号矩阵同步` 647KB、`04_测试跟踪` 555KB），`_legacy_v1` 旧文档另占约 0.5MB。
- **目标做法**：① 演进链抽取归档（`_history/`，append-only）；② `_legacy_v1` 整体删除（README 已授权）；
  ③ 超长文档按「现状 / 历史」分离；④ 正文只留「现状」结论，保留 `AGENTS.md` 权威数字。
- **验收**：总体积压减 ≥50%，`verify_doc_counts.py` / `verify_doc_stats.py` 双脚本仍 PASS。

### 方向 1 · 大模型功能扩展（商品→笔记，第二套生成链路）
- **现状**：已有「官方千帆智能生成」第一套链路（`/xhs/product-notes/generate-save` 等）。
- **目标**：自建 LLM 生成链路，与官方链路并存，补齐可插拔的大模型供应商与媒体生成。
- **核心**：① LLM 供应商配置化（DeepSeek/通义/Gemini/豆包等，OpenAI 兼容 base_url + key）；
  ② 商品信息 → 笔记文案（标题/正文/话题标签/封面文案，多风格模板）；③ 媒体资源生成（文生图商品图/
  封面、图生视频、图文拼图）；④ **本地素材库**（配置多个本地文件夹，快速加载图片/视频素材供生成选用）；
  ⑤ **提示词模板**（公共提示词模块 + 单独提示词模板，可组合复用）；⑥ **笔记媒体可复用商品原始详情图 /
  参考原始图生成新图**，生成图可指定落素材库或直接用于当前笔记；
  ⑦ 复用 `note_goods` + 发布队列完成「生成→保存→发布」。

### 方向 2 · 热点驱动生成（第三条生成链路）
- **目标**：主动学习平台热门话题，做「话题 → 商品匹配 → 笔记生成」闭环。
- **核心**：① 热门话题采集（榜单/热搜词/话题热度，走现有采集链路，只读）；② 话题↔商品智能匹配；
  ③ 按话题生成笔记内容 + 标签 + 图片/视频媒体；④ 结果入内容库，可一键发布。

### 方向 3 · 数据监控与仪表盘（商品监控 + 笔记监控两大类）
- **现状**：有同步/采集/监控散点数据，但无统一汇总视图。
- **平台范围**：**只保证三个平台** —— 网页版（www）/ 创作者中心（creator）/ 千帆（ark），
  **不做蒲公英 / 聚光**。
- **两大类数据**（维度参考对应平台数据分析中心）：
  ① **商品监控**（参考千帆数据中心）：销量、订单、加购、支付、笔记引流、商品转化漏斗、库存、价格、上下架状态；
  ② **笔记监控**（参考创作者中心数据中心）：曝光、点击率、阅读完成率、互动（赞/藏/评/转）、互动率、
    粉丝净增、流量来源、搜索词、发布后趋势。
- **核心**：① 三平台数据源采集（只读、限流）；② 采集调度 + 落库 + 历史趋势；③ 仪表盘（recharts：
  商品监控面板 + 笔记监控面板 + 总览）；④ 归因（笔记→商品→订单漏斗，`note_goods` 联动）。

### 方向 4 · 商品编辑优化扩展
- **核心**：① 媒体资源（主图/视频批量上传、**参考原始详情图/主图/商品信息 AI 生成新商品图/视频**、
  封面优化）；② 商品编辑（标题/卖点 AI 润色、SKU/规格/价格管理）；③ 商品列表（批量改价/上下架、库存同步、标签分组、高级筛选）。

### 方向 5 · 合并发布中心 + 自动运营中心 → 自动化工作流
- **核心**：① 统一入口（发布 + 运营合并为一个工作台）；② 工作流编排（触发器/条件/动作，节点化）；
  ③ 全链路一键发布（多商品→多笔记→定时→多账号）；④ 执行日志 + 失败重试 + 复盘。

### 方向 6 · 订单模块（重要）
- **目标**：千帆订单全生命周期管理 + 订单监控。
- **核心**：① 订单同步（千帆只读探测落库）；② 订单查看（列表/详情/筛选/搜索/导出）；③ 发货/售后
  （写操作，走千帆官方链路，**需显式确认 + 二次确认**，二期谨慎）；④ 订单备注/包裹备注；⑤ 订单监控
  （订单量/销售额/客单价/转化率/退款率/发货时效/订单来源归因，接入仪表盘）。
- **分期**：一期只读（同步+查看+导出+监控）；二期写操作（发货+退款售后，高风险）。

### 方向 7 · 调研补充扩展（择机）
- 合规护栏（风控、限流、AIGC 标识）；竞品/对标账号监测；内容素材库（爆款拆解）；
  多平台扩展（抖音/视频号）；粉丝画像/人群运营；RED Skill 发布（把生成能力做成可挂载 Skill）。

## 7. 范围外（非目标）

- 不做登录逆向 / 写接口破解（延续一期「只读边界」：探测只读，发布走已有千帆/创作者合法链路）。
- 不做大规模高频爬取（违《用户协议》/《刑法》285/PIPL，见 §8）。
- 不做评论/私信/关注等高风险互动自动化（本期仅规划，默认不落地）。
- 不承接第三方商业数据（蝉妈妈/新红/千瓜）的付费数据源，数据以官方后台 + 自有账号为主。

## 8. 风险与合规（硬约束，贯穿全程）

1. **平台合规红线**：小红书无公开 API，自动化基于逆向，存在封号、法律风险。
   延续一期「只读边界」：探测一律 GET/只读查询；发布走官方合法链路（千帆/创作者）；不打印 Cookie/token。
2. **限流与风控**：所有采集/生成/发布过 `CrawlRateLimiter.wait_allow()`，额度走运行时配置（基线 8，勿调高）。
3. **AIGC 标识**：AI 生成的媒体/文案需保留平台 AIGC 溯源字段（一期已有 `aigcTaskId` 机制，复用）。
4. **数据合规**：只采集公开数据，不碰用户隐私（手机号/地址/私信）；采集结果仅用于本账号运营决策。
5. **模型密钥安全**：LLM 供应商 key 走 `system_settings` 落库（按 user 隔离），不落代码/日志。
