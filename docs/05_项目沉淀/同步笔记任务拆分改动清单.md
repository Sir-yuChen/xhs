# 同步笔记任务拆分改动清单（普通笔记 / 商品笔记）

> 状态：**✅ 已实施并测试通过**（2026-09-30；权威契约见设计 13 **§44**，本文件保留为实施前的改动清单）
> 目标：把当前「同步笔记」这一个**混合双源**任务，拆成「同步普通笔记」「同步商品笔记」
> 两个**独立任务 + 独立入口**，在账号信息卡上分开展示与触发。

---

## 0. 现状（拆分前的真实代码事实）

| 层 | 现状 |
|---|---|
| 源清单 | `note_sync_service._note_sources()` 返回 `[creator, ark]` 两个源；**creator 是硬门禁**（无 creator 会话直接 `return []` 拒绝），ark 是可选追加（填空合并补商品挂链/指标） |
| 任务类型 | 只有一个 `xhs_note_sync`（`sync_task_service.NOTE_SYNC_TASK_TYPE`），管这个混合任务 |
| API 入口 | `POST /accounts/{id}/notes/sync`（`accounts.py:708`）→ `start_note_sync` |
| 状态查询 | `GET /accounts/{id}/notes/sync/status`（`accounts.py:802`） |
| 账号卡按钮 | 已有 4 按钮：`同步数据`(互动) / `同步笔记`(混合←拆) / `同步商品`(店铺台账，非笔记) / `删除` |
| 前端门禁 | `lib/sync-gates.ts::noteSyncPlan` —— `blocked = !creatorOk`（creator 单一硬门禁），ark 仅当 creator 成立才列 |
| 定时任务 | `system.note_sync`（job_key）↔ `xhs_note_sync`（task_type），映射在 `ACCOUNT_JOB_TASK_TYPES` |

**关键歧义点（必须澄清）**：账号卡现有的「同步商品」按钮 = 同步**店铺商品台账**
（`xhs_shop_goods_sync`，商品 SKU/价格，不是笔记）。而用户要的「同步商品笔记」是
**千帆 `goods-note/list` 返回的商品笔记**（挂链笔记）。两者不是一回事，新按钮命名要区分开。

---

## 1. 拆分方案总览

```
现在                                  目标
──────────────                      ──────────────
同步笔记（混合双源）            ┌─ 同步普通笔记（creator 源，硬门禁 = creator）
  ├ creator 普通笔记 ────────→  │   任务类型：xhs_note_sync（沿用）
  └ ark 商品笔记（填空合并）    └─ 同步商品笔记（ark 源，硬门禁 = ark）
                                    任务类型：xhs_goods_note_sync（新增）
```

- **同步普通笔记**：只跑 creator 源，门禁 = 创作者会话可用。
- **同步商品笔记**：只跑 ark 源（千帆 `goods-note/list`），门禁 = 千帆会话可用。
- 两个任务**互不阻塞**、各自独立防重、各自独立状态查询、各自独立按钮态。

## 2. 后端改动清单

### 2.1 任务类型登记（`services/sync_task_service.py`）

1. 新增常量：`GOODS_NOTE_SYNC_TASK_TYPE = "xhs_goods_note_sync"`（与 `NOTE_SYNC_TASK_TYPE` 并列）。
2. `ACCOUNT_JOB_TASK_TYPES` 增一行映射（若商品笔记同步也要走定时任务观测）：
   `"system.goods_note_sync": GOODS_NOTE_SYNC_TASK_TYPE`。
3. 新增定时任务 job_key（`config/initial_data/scheduled_jobs.json` 种子 + 注册表，若商品笔记同步需定时触发）。

### 2.2 源清单拆分（`services/note_sync_service.py`）

4. `_note_sources()` 拆成两个函数，或加一个 `only` 参数：
   - `_note_sources(db, account, only="creator")` → 只返回 `[creator]`；
   - `_note_sources(db, account, only="ark")` → 只返回 `[ark]`（且 **ark 变硬门禁**：无 ark 令牌则 `return []`，不再依附 creator）。
   - 保留原「混合」逻辑与否由你定：建议**彻底删除混合路径**（DEF-044：同一语义不留两份），普通同步只传 `only="creator"`、商品笔记同步只传 `only="ark"`。

### 2.3 任务入口拆分（`services/note_sync_service.py` + `api/accounts.py`）

5. `start_note_sync()` 保持为「普通笔记同步」入口（`task_type=NOTE_SYNC_TASK_TYPE`，源 `only="creator"`）。
6. 新增 `start_goods_note_sync()`：`task_type=GOODS_NOTE_SYNC_TASK_TYPE`，源 `only="ark"`，
   防重口径复用 `sync_task_service.find_active_task`（换 task_type）。
7. 新增端点 `POST /accounts/{account_id}/goods-notes/sync`（普通笔记端点旁），逻辑与
   `start_account_note_sync` 同构，但：
   - 门禁从「creator 会话」换成「ark 会话」；
   - 调 `start_goods_note_sync`；
   - `log_id` 观测走 `job_key="system.goods_note_sync"`（若登记了定时任务）。
8. 新增端点 `GET /accounts/{account_id}/goods-notes/sync/status`，返回商品笔记同步的
   `status_payload(..., GOODS_NOTE_SYNC_TASK_TYPE, ...)`。

### 2.4 执行体 / 编排（`note_sync_service._sync_with_task`）

9. `_sync_with_task` 的 `for source in sources` 循环**天然支持单源**（传一个源就跑一个源），
   无需大改。需确认：
   - 商品笔记同步时，`_sync_source` 的 `kind == "ark"` 分支现在是否依赖「creator 先跑」的
     前置（如游标推进、正文潜力假设）。若 ark 分支假设了 creator 已落正文，需解除该耦合。
   - 进度分母（`work_total`）在单源下自然只算该源，无需特殊处理。

### 2.5 账号级任务 worker

10. `account_task_service` 的认领逻辑按 `task_type` 识别——需确认 `GOODS_NOTE_SYNC_TASK_TYPE`
    能被子 worker 认领（若认领白名单写死了 task_type，需加新值）。

## 3. 前端改动清单

### 3.1 门禁纯函数（`lib/sync-gates.ts`）

11. `noteSyncPlan` 拆成两个：
    - `noteSyncPlan`（普通笔记）：`blocked = !creatorOk`（沿用，逻辑不变）；
    - 新增 `goodsNoteSyncPlan`（商品笔记）：`blocked = !arkOk`（ark 单一硬门禁）。
12. `SOURCE_LABELS` 无需大改（`creator`/`ark` 已存在）。

### 3.2 API 请求函数（`lib/api.ts`）

14. 新增 `queryGoodsNoteSyncStatus(accountId)`（对应 `/goods-notes/sync/status`）。

### 3.3 账号信息卡（`pages/platforms/xhs/accounts-page.tsx`）

15. 按钮区：「同步笔记」按钮拆成两个：
    - `同步普通笔记`（`handleNoteSyncClick` 沿用，走 `noteSyncPlan`）；
    - `同步商品笔记`（新增 `handleGoodsNoteSyncClick`，走 `goodsNoteSyncPlan`，门禁不过弹千帆补登提示）。
    - 命名需与现有「同步商品」（店铺台账）区分 —— 建议：`同步笔记`（普通）与 `同步商品笔记`。
16. 轮询状态集拆成两套：`noteSyncIds`（普通）与 `goodsNoteSyncIds`（商品笔记），各自 5s 轮询、各自「同步中」按钮态（仿现有 `startNoteSync` / `startGoodsSync` 双轨）。
17. `firstQuerySyncStatus` 的 `querySyncStatus("notes"/"goods")` 扩成三类（`notes` / `goods_notes` / `goods`）。
18. 「同步商品笔记」的选项弹窗（全量/时间区间）复用 `setSyncOptions({ kind: "goods_notes", ... })`，`SyncNotesOptions.kind` 需加新枚举值。

## 4. 需要你先拍板的两个决策点

1. **商品笔记同步是否要独立定时任务**（`system.goods_note_sync`）？还是仅账号卡手动触发即可？
   - 若只要手动：跳过 2.1 的第 3 点、2.3 的 `log_id` 观测、种子 JSON。
2. **`_note_sources` 混合路径是删还是留**？
   - 建议**删除混合路径**（`only` 参数二选一），避免「老同步笔记」和「新两个按钮」语义并存造成困惑。
   - 但这会影响存量：老任务中心「任务日志」里 `xhs_note_sync` 的历史记录语义（原本含商品笔记），需在文档里标注口径变化。

## 5. 风险与连带（DEF 级约束提醒）

- **同步是「翻到底」全量**（§21）+ 等待式限流（`wait_allow`）——拆成两个任务后，同一账号的
  creator 源与 ark 源会**并发打平台**（原来是串行在一个任务里）。需确认限流桶是否按
  `account_id:channel` 分，避免两个任务互抢额度（`get_rate_limiter` 的 key）。
- **账号级互斥**：现在 `_sync_busy_accounts` 按账号互斥。拆分后两个任务是不同 task_type，
  若共用同一账号互斥位，则普通/商品笔记仍会串行（可能反而更稳）；若要并行需评估额度。
- **迁移/历史**：`tasks` 表复用，新 task_type 无迁移成本（`task_type` 是字符串列）。
- **文档回数**：改端点/path/任务类型后，须跑 `verify_doc_stats` + `verify_doc_counts` 两个脚本，
  并更新设计 13 相应 §。
- **测试**：`tests/backend/test_*.py` 里凡断言「同步笔记=混合双源」的用例（尤其 `_note_sources`
  返回双源、`sync-gates.cjs` 的 `noteSyncPlan` 行为脚本）都要跟着改。
