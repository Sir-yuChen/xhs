# 14 · 功能设计：桌面打包与安装（v1.0）

> 版本：v1.0（2026-09-24） · 状态：已实施
> 上游依据：AGENTS.md 硬约束 1（文档先行）；本文档是「打包成电脑桌面应用」需求的唯一设计真相源。

## 1. 目标与范围

把 XHS_ALL_IN_ONE（FastAPI 后端 + React 前端 + SQLite）打成 **Windows 桌面安装程序**：

| 项 | 口径 |
|---|---|
| 产物 | `spider-xhs-setup-<版本>.exe`，生成后放**项目根目录** |
| 版本 | 当前 **1.0.0**（构建脚本 `-Version` 参数化，后续只改版本号重跑） |
| 数据落点 | **全部**运行时文件夹（`data/`、`backend/app/storage/**`、`logs/`、`config/`）一律落在**安装时用户选择的安装目录**下，不写 `%LOCALAPPDATA%`、不写 Program Files 之外的位置 |
| 目标机器 | **不需要**预装 Python / Node.js（两者都打进安装包） |
| 不做 | 自动更新、代码签名、macOS/Linux、MySQL 切换（保留能力，安装版默认 sqlite） |

## 2. 总体架构

```
┌─ 安装目录（用户自选，默认 {localappdata}\Programs\SpiderXHS，免 UAC）─┐
│  SpiderXHS.exe            ← 启动器（PyInstaller onedir，无控制台）      │
│  _internal/               ← Python 运行时 + 全部依赖 + 后端代码          │
│  node_modules/            ← crypto-js（放安装根，见 §5 解析路径）        │
│  runtime/node/            ← node.exe（PATH 前插，签名链路裸调 node）     │
│  frontend/dist/           ← 前端生产构建产物（后端 StaticFiles 直出）     │
│  config/default.yaml      ← 可编辑配置（启动器以 CONFIG_FILE 指向它）     │
│  config/initial_data/     ← 应用初始化数据（定时任务配置，设计 15 §4.5）   │
│  data/                    ← spider_xhs.db（WAL）、secret.key            │
│  backend/app/storage/     ← media / exports / tmp_note_publish          │
│  logs/                    ← launcher.log（uvicorn 日志同写此处）          │
└──────────────────────────────────────────────────────────────────────┘
```

**启动链路**：双击 / 开始菜单 → `SpiderXHS.exe`（无窗口）→ 建目录、注环境变量 →
uvicorn 起 `127.0.0.1:<端口>` → 健康检查通过 → **独立应用窗口**打开 Web UI。
托盘图标提供「打开界面 / 退出」。端口默认 8000，被占则按 8001→8010 回退
（前端 `lib/api.ts` 的 `baseURL: "/api"` 是**相对路径**，回退对 UI 透明）。

**独立窗口口径（2026-09-26 取代「系统默认浏览器」）**：launcher 用 Edge（Win10/11 自带）
或 Chrome 的 `--app=<url>` 起「无地址栏 / 无标签栏 / 无工具栏」的独立窗口（`--window-size=1440,900`），
并配**独占 user-data-dir**（`%LOCALAPPDATA%\SpiderXHS\app-profile`）——①不受用户已开着的浏览器
实例影响（共用 profile 时 `--app` 参数可能被已有进程吞掉、窗口不开）；②不共享用户的插件 /
历史 / 登录态。两者都找不到才退回系统默认浏览器（兜底，日志记 WARN）。
⚠️ 任务栏图标仍是浏览器图标 —— 这是 `--app` 模式的固有限制；要完全自有图标/窗口需换
pywebview 内嵌 WebView2（bundle 增 20-30MB），当前不做（用户 2026-09-26 选定）。

**子进程控制台抑制（2026-09-26，用户实测缺陷）**：打包版是 windowed 进程（无控制台），
而签名运行时（`xhs_utils/xhs_core|xhs_pc|xhs_creator` 的 `runtime.py`、`xhs_pc/params.py`、
PyExecJS）每次调用都裸起 `node.exe` —— Windows 会为无控制台进程 spawn 的控制台子进程
**新建黑色控制台窗口** ⇒ 页面每有操作/每轮轮询都闪黑窗，频繁到无法操作。修法：launcher
在 frozen 时给进程内 `subprocess.Popen.__init__` 默认注入 `CREATE_NO_WINDOW`（0x08000000），
一处覆盖全部 6 处现有调用点与未来新增调用点（`subprocess.run` 与 PyExecJS 都经 Popen），
不逐个改 runtime.py（同一语义不留两份实现）。GUI 子进程（Edge 窗口）不受影响。
端到端验证：pythonw（无控制台父进程）下，未打补丁子进程 `GetConsoleWindow()!=0`、
打补丁后 `==0`。

**托盘退出语义（2026-09-26 修订 · 2026-09-26 深夜补第二条腿）**：退出 = `server.should_exit=True`
+ **树杀独立窗口进程**（`taskkill /T /F`，独占 profile ⇒ 进程树全是本应用窗口，不误伤用户自己的浏览器）
+ uvicorn `timeout_graceful_shutdown=5`。不关窗口的话，页面停在连不上的界面且轮询连接
不断 ⇒ 优雅停机互相等待卡死。

⚠️ **为什么必须两条腿（v1.0.1 实测：用户点托盘退出后应用窗口仍在，而后端已停）**：

1. **窗口可能不止一个** —— `_app_window_proc`（单变量）改为 **`_app_window_procs`（列表）**：
   每次 `open_app_window()` 成功拉起一个进程就追加，退出时逐个 `_taskkill_tree(pid)`。
2. **Chromium 的单例转交会让 pid 落到空壳上** —— 同一 `--user-data-dir` 再开一次时，
   新进程只是把请求转交给已有实例然后**立刻退出**：我们手上的 pid 早已结束，而真正显示
   窗口的那个进程不在我们的名单里。⇒ 退出时再加一条**按 profile 兜底**：
   PowerShell `Get-CimInstance Win32_Process` 过滤命令行含 `app-profile` 路径的
   `chrome.exe` / `msedge.exe` 并 `Stop-Process`。**独占 profile 让这条兜底安全** ——
   匹配串是本应用专属目录，用户自己的浏览器进程命令行里不会有它。
3. 只按 pid 杀、不做 profile 兜底 ⇒ 用户看到的正是「后端关了、窗口还开着」
   （任务管理器里后端进程确实没了，因为那条腿是好的）。

## 3. 启动器职责（`packaging/launcher.py`）

启动器是唯一的「安装目录适配层」，**不改后端业务代码**，全部通过既有扩展点注入：

| 职责 | 实现 | 依据 |
|---|---|---|
| 定位安装目录 | frozen 时 `APP_ROOT = Path(sys._MEIPASS).parent`；开发态 = 仓库根 | PyInstaller onedir 布局 |
| 数据库落安装目录 | 环境变量 `DATABASE_SQLITE_PATH=<APP_ROOT>/data/spider_xhs.db`（`as_posix()`，SQLAlchemy URL 安全） | `core/config.py` 既有 env 覆盖 |
| 前端静态直出 | `FRONTEND_SERVE_STATIC=true` + `FRONTEND_BUILD_DIR=<APP_ROOT>/frontend/dist` | `frontend.serve_static` 既有开关 |
| 配置指向安装目录副本 | `CONFIG_FILE=<APP_ROOT>/config/default.yaml`（绝对路径优先于 `__file__` 相对定位，frozen 下也成立；且用户可编辑） | `_load_yaml_config()` 第 2 优先级 |
| 签名 Node 运行时 | `PATH` 前插 `<APP_ROOT>/runtime/node`；裸 `['node', …]` 与 PyExecJS 均走 PATH | `xhs_utils/*/runtime.py`、PyExecJS |
| JWT 密钥 | `SECRET_KEY` 未外部指定时：读 `<APP_ROOT>/data/secret.key`，没有则生成并落盘（重装同目录不失效） | `security.secret_key` 既有 env 覆盖 |
| CWD | `os.chdir(APP_ROOT)`：`storage_dir`（`Path("backend/app/storage")`）、alembic 旧相对解析等一律落到安装目录 | 相对路径统一收口 |
| 单实例 | 启动前探活候选端口；已有健康实例 ⇒ 只开独立应用窗口后退出；端口均占 ⇒ 8011 起顺延，日志记录实际端口 | — |
| 日志 | `logs/launcher.log`（launcher 自身 + uvicorn 访问/错误日志，windowed 模式 stderr 不可见） | — |

环境变量一律 `os.environ.setdefault` 语义：**外部显式设置优先**（高级用户可改数据位置），未设置才注入安装目录口径。

## 4. 后端适配点（唯一一处代码改动）

`backend/app/core/database.py::_run_alembic_migrations()`：alembic 的相对
`script_location = backend/alembic` 在 frozen 后按 CWD 解析会失败 ⇒ 基于 ini 自身路径
设**绝对** `script_location`（`dirname(ini_path)/alembic`，dev 下与现值等价，零行为变化）：

```python
script_location = os.path.join(os.path.dirname(ini_path), "alembic")
if os.path.isdir(script_location):
    alembic_cfg.set_main_option("script_location", script_location)
```

`backend/alembic.ini` 与 `backend/alembic/versions/` 由 PyInstaller `--add-data` 收进
`_internal/backend/`；`config/default.yaml` 收进 `_internal/config/`（`__file__` 相对定位的兜底）。

**不动**的部分：`apis/`（禁改）、签名 JS、业务服务、前端。

## 5. Node 运行时打包

- 运行期 JS 依赖只有 **crypto-js**（实测：`xhs_utils/**/js` 的外部 require 仅 crypto-js，
  根 `package.json` 的 jsdom 运行时不引用）；node_modules 只打 crypto-js 一棵树。
- **放置位置 = 安装根 `node_modules/`**（与开发仓仓库根同构）。node 的 require 解析
  有两条路，放安装根两条都覆盖：
  ① 文件式（`subprocess` 调 `node <js>`）：从 `_internal/xhs_utils/.../js` 逐级向上，
  穿过 `_internal` 到达安装根；
  ② PyExecJS 管道式（源码经 stdin 喂给 node，`cwd` = 安装根）：直接从安装根解析。
  ⚠️ 放 `runtime/node/` 下两条路都够不着——开发机正常只因仓库根有 node_modules，
  这个差异打包初期实测踩过（冒烟 6a/6b 两条探针专门盯它）。
- `node.exe` 来源：构建机 `where node` 优先；找不到则从 npmmirror 下载固定 LTS 版本
  （`packaging/build.ps1` 内 `NODE_VERSION` 变量，与 nodejs.org 官方包一一对应）。
- 体积预估：安装包 **≈350–500MB**（opencv ≈90MB + node ≈50MB + Python 运行时 ≈100MB + dist ≈2MB + 其余依赖）。

## 6. 构建流程（`packaging/build.ps1 -Version 1.0.0`）

```
① 前置检查：Python3.12 / node+npm / ISCC（Inno Setup，缺失给出去向指引）
② build venv：系统 Python3.12 派生 packaging/.venv-build（隔离，不污染用户 site-packages）
   └─ pip install -r requirements.txt + pyinstaller + pystray
③ 前端：npm ci && npm run build → frontend/dist
④ PyInstaller：SpiderXHS.spec（onedir，hidden imports 全静态可分析；版本信息写入 exe）
⑤ 组装：runtime/node（node.exe + node_modules/crypto-js）、frontend/dist、
   config/default.yaml、config/initial_data/（整目录，应用初始化数据）、
   assets/app.ico（由 frontend/public/logo.jpg 生成）
⑥ ISCC：installer.iss → spider-xhs-setup-<版本>.exe 输出到【项目根目录】
```

后续发新版：`powershell -File packaging\build.ps1 -Version 1.0.1`，一步到位。

## 7. 安装 / 升级 / 卸载

- **安装**：Inno Setup，`PrivilegesRequired=lowest`（免 UAC，安装目录必须可写——
  数据就在里面）；默认目录 `{localappdata}\Programs\SpiderXHS`，安装时**可自选**；
  `UsePreviousAppDir=yes` 便于覆盖升级；开始菜单 + 可选桌面快捷方式。
- **升级**：重跑新版安装器、选同一目录覆盖；`data/` 不覆盖 ⇒ 账号 / 笔记 / 商品全留；
  后端启动自动 `alembic upgrade head` 应用新迁移。
- **卸载**：只删程序文件（安装记录内的），**数据永远保留** —— `data/`、`backend/app/storage/`、
  `logs/` 都是运行期生成、不在卸载记录里，自然留存；要彻底清除就删整个安装目录。
  ⚠️ 早期设计是卸载末弹 Yes/No 问「是否连带删数据」，实测 `/VERYSILENT` 静默卸载时
  [Code] 里的 MsgBox **不会**被自动应答、卸载器堵死在弹窗上（冒烟挂死 16 分钟）——
  且「默认删用户数据库」本身也是危险默认，故整段移除（2026-09-24）。

## 8. 验证口径（发版门禁）

1. 静默安装到测试目录（`/SILENT /DIR=`）；
2. 起 exe ⇒ `/api/health` 200、`GET /` 返回 `index.html`、`/openapi.json` 可开；
3. 安装目录下 `data/spider_xhs.db`、`storage/{media,exports,tmp_note_publish}`、`logs/launcher.log` 均生成；
4. `runtime/node/node.exe --version` 可执行；`node -e "require('crypto-js')"` 通过（签名链前提）；
5. 端口回退：占住 8000 后启动，实例改端口且独立窗口开到实际端口；
6. 卸载：程序文件清除、数据目录按选择保留/删除；
7. 真机链路冒烟（扫码登录 / 一次同步 / 一次发布）——需用户账号，交付时由用户执行或明确跳过；
8. **应用初始化数据随包附有**（设计 15 §4.5）：安装目录存在 `config/initial_data/scheduled_jobs.json`
   （可解析、条数与注册表内置任务一致）；首启后 `GET /api/schedule/jobs` 返回这批任务行
   —— 「装完即有用」的判据落在**行**上，不是落在**文件**上；
9. **安装包不含测试产物**（2026-09-24 用户口径「测试代码不要打包」）：bundle 内无 `tests/`、
   `pytest`、`*.cjs` 测试脚本 —— 由 spec `excludes` + build.ps1 尾部自检共同保证（§10）。

> **v1.0 实测补记（2026-09-24）**：上述 1~6 已由 `packaging/smoke-test.ps1` 全量自动化
> （静默安装 / health / index.html / 数据目录落安装目录 / 端口回退 8123→8124 /
> node 双路解析 + sign.js 真签名 / 卸载留数据），7 段全过、25s；第 7 条留用户真机执行。
> 另：卸载语义已改为「只删程序文件、数据永远保留」（§7），冒烟第 6 段同步改判据。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| PyInstaller hidden imports（20+ router 虽为静态 import，services 或有延迟 import） | spec 内 `collect_submodules("backend")` 全量收集；冒烟以 `/openapi.json` 167 operations 为判据 |
| opencv / curl_cffi 原生扩展与数据文件 | pyinstaller-hooks-contrib 均含 hook；冒烟验证导入 |
| frozen 下 `__file__` 相对路径 | DB/前端/CONFIG_FILE 全部走环境变量绝对路径；alembic 绝对 script_location（§4） |
| 未签名 exe 的 SmartScreen 警告 | v1.0 接受（文档明示）；代码签名列为后续可选项 |
| 构建环境污染用户 Python | 一律 `packaging/.venv-build` 派生，禁全局 pip |
