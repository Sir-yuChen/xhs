5 张新表（刻意都不带 user_id）

表关键约束为什么不能带 user_id
menusperms 部分唯一索引（非空时）
path 部分唯一索引
parent_id 无 FK（应用层树）		 它是「权限的定义」不是「某用户的数据」。带 user_id = 每用户一套菜单 = 权限体系立刻失效
rolescode 唯一；is_system=1 禁删/禁停/禁改 code 角色是全局定义
role_menusUNIQUE(role_id, menu_id)
role_id CASCADE / menu_id RESTRICT		 授权是「角色↔菜单」的事实，不带归属
dict_typescode 唯一全局共享枚举
dict_itemsUNIQUE(type_id, value)
type_id CASCADE		同上；不搬 dataPanel 的 belong 多平台列

既有表改动（只动 3 张）

表改什么依据
users+6 列：status / real_name / last_login_ip / last_login_at / must_change_password / deleted_at 现在连姓名、最后登录时间都没有。deleted_at = B9 软删定稿
api_logs+status_code 并从 meta JSON 回填 70,325 行 实测 2000 条采样 100% 有 meta.status_code ⇒ 可全量回填
notifications+link 4 条里 3 条 source_id 是 NULL ⇒ 历史通知原本没有跳转目标
system_settings零变化 —— 不加 scope 该列 2026-09-27 被刻意删除过（设计 10 §7.1 D1）；管理员诉求改走 apply-to-all 端点
回填写法：不逐行 UPDATE（70k 行会卡死），用 SQLite json_extract 一条 SQL。 回填前记 COUNT(*)，回填率 < 99% ⇒ 迁移里 raise 而不是静默跳过。
种子纪律「只补缺不覆盖」：if exists: continue —— 用户改过的 status / name 不被下次升级打回。 与 forbidden_words.json 同一口径。
admin 种子三条配套（缺一不可）：① must_change_password=True 首登强制改密（前端无法跳过）② 用户列表打「默认口令」Tag ③ register.enabled 基线默认 false（防「弱口令 + 开放注册」同时成立）
