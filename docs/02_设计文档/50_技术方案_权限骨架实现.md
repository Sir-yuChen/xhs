## 2.3 `core/deps.py` 改造

```python
# 新增
def require_perm(code: str):
    """FastAPI 依赖工厂。用法：Depends(require_perm("system:user:edit"))"""
    def _dep(current_user: User = Depends(get_current_user)) -> User:
        if not has_perm(current_user, code):
            raise HTTPException(403, detail={"code": "PERMISSION_DENIED",
                                             "message": f"缺少权限：{code}",
                                             "required": code})
        return current_user
    return _dep

# 保留但降级为「内部别名」，只在极少数全站操作使用
def require_admin(...) -> User: ...   # 内部改为 has_perm(user, "system:setting:applyAll")
```

## 4.1 `services/permission_cache.py`（新建）

```python
"""权限缓存：进程内 dict[(user_id, token_version)] → (frozenset, expire_at)。

TTL 60s 兜底；写操作**显式失效**。不引入 Redis（单进程部署，收益为零）。
"""
_CACHE: dict[tuple[int,int], tuple[frozenset[str], float]] = {}
TTL = 60.0

def get(user_id: int, token_version: int) -> frozenset[str] | None: ...
def put(user_id: int, token_version: int, perms: frozenset[str]) -> None: ...
def invalidate_user(user_id: int) -> None: ...
def invalidate_role(role_code: str, db) -> int:
    """角色授权变了 ⇒ 清该角色下所有人的缓存。返回受影响人数。"""
def invalidate_workspace(ws: str) -> None:
    """菜单启停 ⇒ 只清缓存，**不碰 token_version**（不踢人）。"""
```

**key 里带 `token_version`** 是关键设计：`token_version+1` 时旧缓存自动失效，
不用逐个 `del` —— 这也是「改密码/强制下线立即生效」的同一机制。

**`usePermission` 实现要点**
```ts
export function usePermission() {
  const { user } = useAuth();
  const set = useMemo(() => new Set(user?.permissions ?? []), [user]);
  return {
    hasPermission: (c?: string) => !!c && set.has(c),
    hasAny: (cs: string[]) => cs.some(c => set.has(c)),
  };
}
```

# 十一、风险与回退

| 风险 | 触发条件 | 回退手段 |
|---|---|---|
| 挂码挂错 ⇒ 某功能对所有人 403 | S7 批量改 251 处 | 每条改动带 `# perm:` 注释；出问题 `git revert` 单个文件即可（per-file 提交） |
| 迁移 2 回填慢 | 70k 行 UPDATE | 实测单条 SQL < 5s；超 30s 说明缺索引 ⇒ 先在 `meta` 上建临时索引 |
| admin 被锁门外 | 误改 role_menus | G4 守卫：admin 权限代码派生，与 role_menus 无关 |
| 前端菜单全空 | 种子 path 与 router 不一致 | G2 三集合相等断言提前发现 |
| 性能退化（每次请求查权限） | `require_perm` 频繁 | `permission_cache` 60s TTL + key 含 token_version |

**分阶段上线建议**：S0–S4 后端一次性上（前端仍在旧菜单下可用）；
S5–S8 前端改完一起发。中间态不存在「后端要权限、前端没菜单」的死局 ——
因为 `/auth/me` 新增字段是**增量**，旧前端忽略它照常工作。
