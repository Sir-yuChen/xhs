# 千帆发布商品 · 第一步实测证据（2026-10-08）

> 全部来自 **CDP 驱动真实 Chrome + 真实千帆登录态**（账号 8「观隅好物的店」）的操作，
> 不是读文档也不是猜。证据文件：`.hermes/tmp/evidence_publish/`。

## 一、页面的**渐进式渲染**（决定性发现）

发布页 `https://ark.xiaohongshu.com/app-item/good/create` 初始**只渲染「商品图片」**：

```
初次进入（无图）:  商品图片  →  信息已确认，下一步
上传主图并选图后:  商品图片 → 商品标题(+智能生成) → 智能推荐(+立即使用) → 商品类目
```

**实测对照**（同一页面，只差「有没有主图」）：

| 时刻 | hasTitle | hasCat | hasUse |
|---|---|---|---|
| 刚进入 | false | false | false |
| 上传主图并确认选图后 | **true** | **true** | **true** |

⇒ 复刻时必须实现这条**渐进式**：没主图就不该显示标题与类目区。

## 二、类目区在「有主图但无标题」时的文案

```
商品类目
上传图片并完成标题后为您智能识别类目
```

⇒ 类目区**始终存在**，但内容取决于状态：无标题时是这句提示，有标题时才是树/推荐。

实测拿到（无需任何 AI 调用，平台自己给的）：


## 四、点「立即使用」触发的**真实请求**（关键契约）

只发一个 **action-RPC**：

```
POST /api/edith/product/publish_async
{"data":"{\"publishType\":1,\"sourceType\":1,\"actions\":[{\"action\":\"itemAuditPreCheck\",
  \"param\":{\"name\":\"<标题>\",\"categoryPath\":[{\"level\":1,\"categoryId\":\"65f997243e946300016b2e3c\",…}]}}]}"}
```

**后续联动 actions**（同一次交互里被唤起）：

| action | param | 作用 |
|---|---|---|
| `itemAuditPreCheck` | `{name, categoryPath[{level, categoryId}]}` | 标题+类目合法性预检 |
| `getProductPropertyConfig` | `{categoryId}` | 取该类目的**属性配置** |
| `getPropertyGroups` | `{variants:[{variantId,variantName}]}` | 取**规格分组** |
| `getRecommendBrand` | `{title, mainImages[{type,name,width,…}]}` | 按标题+主图**推荐品牌** |

⚠️ `data` 是**字符串化的 JSON**（要 `dump` 一次）—— 与调研文档 25 的结论一致。

## 五、类目识别结果（与真机一致）

点「立即使用」后页面出现「已选类目」，推荐类目 = **「梳妆台/桌」**（id `65f997323e946300016b2fa9`，level 3）。
这与 `search_category('梳妆台')` 的返回**同一条**，互相印证。

## 六、`search_category` 的真实响应（已实测）

```
POST /api/edith/product/search_category   {"keyword":"梳妆台"}   ← 无需签名
data.categories[] 每条含：
  id / name / ename / level / fatherId / isLeaf / needBrand / channelList
  / properties / preCheck / legal / limitNum / maxDeliveryTime
  / personalShopRegionList / categoryType / showSaleMethod / version
```

⚠️ **没有 `path` 字段** —— 只有 `fatherId` + `level`。想要「一级 > 二级 > …」的完整链路，
必须**按 `fatherId` 逐级上溯**（平台自己不回完整路径）。

## 七、类目树接口

`/api/edith/product/get_seller_marketable_categories` 出现在 bundle 的端点表里，
调用形态（从 bundle 逆出）：`{parentCategoryId, channelList, useCategory}`。

⚠️ **实测 HTTP 404** —— 该路径在当前版本下不可直连（可能是内部网关名）。
⇒ **本项目的类目搜索走已验证的 `search_category`**，不走这个。

## 八、图片空间的真实链路（已实测）

```
点「上传图片」 → 弹「选择图片」抽屉（= 图片空间）
  显示：166.92M/15G、共 1592 条、100 条/页
  按钮：上传本地图片 / 搜索 / 取消 / 确认
  搜索框：输入关键词进行搜索
  列表项：100×133 缩略图 + alt=真实文件名
```

点「上传本地图片」→ 出现真实 `input[type=file]`（`accept=".jpg, .jpeg, .png"`）→
塞 `主图02.jpg` → **「上传成功」190.71K**。

⚠️ **本项目刻意不弹这个抽屉**（用户口径）：选本地文件后**静默上传**，只拿链接做预览。

## 九、第一步的官方顺序（用户口径 + 实测一致）

```
1. 主图 → MD5 生成唯一文件名
2. 上传到图片空间
3. 记住「不带后缀」的名称
4. 用该名称搜图片空间，取回链
5. 链接作为商品图片
6. 平台自动生成商品标题 → 点「立即使用」
7. 点「智能生成」可再生成新标题 → 再点「立即使用」
8. 点「使用商品标题」→ 平台自动识别类目
```
