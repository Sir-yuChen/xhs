# 千帆发布商品全流程调研（2026-10-08）

> 证据来源：`.hermes/tmp/evidence_publish/all_edith_requests.json`（52 条真实抓包）、
> `batch_create_item_body.json`（真实发布正文）。
> **本文只记录实测结论，不含推测。**

## 一、整体架构：一个通用 action-RPC

发布页**不是**一组 REST 端点，而是**一个** RPC：

```
POST /api/edith/product/publish_async
{ "data": "{\"publishType\":1,\"sourceType\":1,\"actions\":[{\"action\":\"<名>\",\"param\":{…}}]}" }
```

⚠️ `data` 是**字符串化的 JSON**（要 `json.dumps` 一次），不是嵌套对象。

**实测**：52 条抓包里 40 条 `publish_async`，**每条都是同一形状**，
差别只在 `actions[]` 里的动作。所以「发布页 = 一串 action 调用」，
前端每次交互（选类目、传图、填标题）都触发若干 action。

## 三、AI 生成的参数（**优先使用**，用户点名）

页面点击即触发，**入参极简**（平台自己吃图）：

| 目标 | action | 入参 | 说明 |
|---|---|---|---|
| **商品名称** | `getRecommendItemTitle` | **只需 `mainImages`** | 主图传上去就能生成标题 |
| **商品类目** | `getRecommendCategory` | `imageUrl` + `name` | 图 + 名称 → 推荐类目 |
| **商品属性** | `predictProductProperty` | `categoryId` + `imageUrls` + `title` | 圈了类目后按图预测属性 |

⇒ 前端「AI 生成」按钮应直接打这三个 action，**按顺序**：主图 → 标题 → 类目 → 属性。

## 四、提交（真实发布正文）

## 六、复刻范围（按此实现 UI）

1. **类目选择**（必须先定，后面一大串规则都依赖它）
2. **商品名称**（`name`）+ 短标题（`itemShortTitle`）+ AI 生成
3. **商品图**：主图（5 张）/ 详情图 / 白底图校验
4. **规格与价格**：`variantIds` / `skuData` / 库存
5. **类目属性**：`attributes`（由 `getCategoryProperty` 决定有哪些）
6. **物流**：`shippingTemplateId` / `logisticsPlanId` / `deliveryMode`
7. **售后**：`freeReturn` / `qualifications`
8. **其他开关**：`stockType` / `usePlayback` / `enableMultiWarehouse` / `sizeTableType`

## 七、未决（**不得猜测**）

- `publishMode` 抓包 `2` vs 现有代码 `1`：需再取证（可能 1=普通发布 / 2=基础图创建）。
- 各 action 的**响应体**尚未落盘（抓包只存了请求）⇒ AI 返回的字段名要真机再取一次。
- `attributes` 的取值形状（picklist vs multiSelect）随类目变，需按 `getCategoryProperty` 动态渲染。
