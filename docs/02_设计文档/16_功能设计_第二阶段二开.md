## 2. 方向 1 · 大模型功能扩展（第二套生成链路 + 本地素材库）

### 2.1 完整链路（商品 → 可发布笔记，端到端）

```
用户选商品(1) ──► 选生成配置(2) ──► 入生成队列(3) ──► worker 线程池(4)
                                                            │
   ┌────────────────────────────────────────────────────────┘
   ▼
(5) 组装 Prompt：商品信息 + 风格模板 + 提示词模板(公共模块 + 单独模板) + 素材引用
        ├─ (5a) LLM 网关 → 标题/正文/话题标签/封面文案
        ├─ (5b) 媒体：文生图 / 图生视频 / 图文拼图  OR  从本地素材库选取
        │      OR 直接复用商品原始详情图 / 参考原始图生成新图（可指定参考图）
        ▼
(6) 话题解析 strip_topic_marker / topic_token → 落库 topics + note_topics
(7) 保存本地笔记（publish_status=local+pending）+ 媒体落 media_assets + 挂链 note_goods
(8) 用户预览/编辑 ──► 显式「发布」──► 千帆 note/publish（预审核 + SKU 挂链 + aigcTaskId）
```

- 生成走队列：`POST /xhs/product-notes/generate-llm` 入队即返回，前端 5s 轮询 `generated` 进度，
  **不自动发布**（发布必须用户显式动作，延续一期）。

### 2.2 实现方案

| 层 | 模块 | 说明 |
|---|---|---|
| 后端 | `services/llm_gateway.py` | 统一供应商调用（OpenAI 兼容 base_url+key；文本/图片/视频三类 capability），重试/超时/限流/密钥注入 |
| 后端 | `services/note_generation_llm.py` | 编排：拼 Prompt → 调网关 → 解析话题 → 落库 → 关联商品 |
| 后端 | `services/media_generation.py` | 文生图/图生视频/图文拼图，调供应商，结果落 `media_assets` + AIGC 溯源 |
| 后端 | `services/prompt_template.py` | 提示词模板：公共模块（可组合片段）+ 单独模板（按任务类型），渲染最终 Prompt（见 §2.4） |
| 后端 | `services/material_library.py` | 本地素材库扫描/索引/检索（见 §2.3） |
| 队列 | 复用 `note_queue_service` + `QUEUE_REGISTRY` | 生成队列键名 `generated`（沿用一期） |
| 前端 | `pages/platforms/xhs/` 生成配置弹窗 | 选模板/供应商/媒体来源/素材 |
| 前端 | 生成进度卡 | 复用一期「队列记录页」5s 轮询、无 Tip |

**数据模型**：`llm_providers` / `llm_models` / `generation_templates` / `prompt_modules` / `prompt_templates` /
`media_assets` / `material_folders` / `material_files`（详见 §8）。

### 2.3 本地素材库（用户新增需求，重点）

**需求**：支持配置**多个本地文件夹**作为素材库，快速加载图片/视频素材，供笔记生成、商品编辑选用。

**功能点**：
1. **文件夹管理**：增删多个本地文件夹路径（绝对路径），每个可命名、可启用/停用；
   扫描只读，不改动用户文件。
2. **索引与缩略图**：扫描文件夹内图片（jpg/png/webp）与视频（mp4），生成缩略图与元数据
   （文件名/类型/尺寸/大小/修改时间），入库 `material_files`。
3. **快速加载**：前端素材面板按「文件夹分组」展示缩略图网格，支持关键词搜索、按类型/时间筛选、
   拖拽选用；支持「手动刷新 / 定时刷新」重扫。
4. **引用**：生成笔记（方向 1/2）与编辑商品（方向 4）时，素材面板弹出，选中素材作为配图/封面/视频。

**实现方案**：
- 后端扫描用 `os.walk` + Pillow 缩略图（缩略图存 `storage/materials/thumbs/`），
  SQLite 存索引（`material_folders` + `material_files`），扫描走线程池防阻塞。
- 前端素材面板组件 `MaterialPicker`（弹窗），图片预览复用 antd `Image.PreviewGroup`，
  视频用 `<video>` 标签，拖拽复用 antd `Upload.Dragger` 的 `beforeUpload` 拦截本地选取。
- 大文件夹（>1000 文件）分页 + 增量扫描（按 mtime 判断变更）。

### 2.4 提示词模板 + 商品原始图媒体复用（用户新增，重点）

**A. 提示词模板（两层结构）**

| 层 | 说明 | 示例 |
|---|---|---|
| **公共提示词模块** `prompt_modules` | 可复用的 prompt 片段，按类别组织，可组合拼接到任意生成 | 「小红书种草风格」「去 AI 味」「女性向」「口语化 + emoji」 |
| **单独提示词模板** `prompt_templates` | 按任务类型的完整 prompt 模板，可引用多个公共模块 | 文案模板 / 商品图模板 / 视频模板 / 封面模板 |

- 渲染最终 Prompt = 基础指令 + 引用的公共模块 + 任务模板 + 商品信息/素材注入。
- 公共模块可增删改、可设默认组合；单独模板可增删改、可标默认（按任务类型）。
- 前端：设置页「提示词模板」卡片，两层管理（公共模块库 + 模板库 + 预览渲染效果）。

**B. 商品原始图媒体复用（笔记媒体资源）**

- 单独生成笔记时，媒体来源新增两个选项：
  ① **复用商品原始详情图**：直接把商品原始详情图/主图作为笔记配图（无需 AI 生成）；
  ② **参考原始图生成新图**：指定商品原始详情图中的 1–N 张作为**参考图**，AI 生成新图（换背景/场景/风格）作为笔记配图。
- **参考图可指定**：从商品原始详情图/主图列表里勾选参考图。
- **生成图落点可指定**：生成的新图/视频可「保存到指定素材库」（写入 `material_files`）+「直接用于当前笔记」（挂到当前笔记媒体）—— 两者可同时。
- 复用一期 `media_assets`（AIGC 溯源 `aigcTaskId`）+ `material_files`（落素材库）。

### 2.6 达到效果（验收）

- 选商品 → 选模板 → 点「生成并保存」，**≤60s** 产出：标题（多备选）+ 正文（600–900 字）+
  话题标签 + 封面图/视频（AI 生成 / 素材库选取 / 复用商品原始详情图 / 参考原始图生成新图）。

- 提示词模板：公共模块可组合复用、单独模板按任务类型调用；生成图可指定落素材库 + 直接用于当前笔记。

## 4. 方向 3 · 数据监控与仪表盘（商品 + 笔记 + 订单三类监控）

### 4.1 三大类数据维度（参考对应平台数据分析中心）

**① 商品监控数据**（数据源：千帆 `ark` 数据中心）

| 维度 | 指标 | 说明 |

| 销售 | 销量、订单数、支付金额、加购数、支付转化率 | 千帆经营数据 |
| 内容引流 | 笔记引流数、笔记→商品卡→加购→支付漏斗 | 千帆笔记分析 |
| 库存/价格 | 库存量、价格、上下架状态 | 商品台账已有，扩趋势 |

**② 笔记监控数据**（数据源：创作者中心 `creator` 数据中心）

| 维度 | 指标 | 说明 |
|---|---|---|
| 曝光 | 曝光量、点击率（CTR）、阅读完成率 | 创作者中心数据中心 |
| 互动 | 点赞、收藏、评论、转发、互动率 | 部分一期已有，补齐 |
| 涨粉 | 粉丝净增、粉丝画像 | 创作者中心 |
| 流量来源 | 推荐/搜索/关注来源占比、TOP 搜索词 | 创作者中心 |

**③ 订单监控数据**（数据源：千帆 `ark`，详见 §7.5）

| 维度 | 指标 | 说明 |
|---|---|---|
| 经营核心 | 订单量、销售额（GMV）、客单价 | 千帆数据中心 / `orders` 聚合 |
| 经营质量 | 支付转化率、退款率 | `orders` / `after_sales` 聚合 |
| 履约 | 发货时效 | `order_shipments` |

## 5. 方向 4 · 商品编辑优化扩展（含 AI 生成商品图/视频）

### 7.3 一期只读 · 业务逻辑（订单同步）

**触发**：定时任务（账号维度隔离）+ 手动「同步」。

**同步流程**：
1. 取本账号 `ark` 令牌（拿不到 ⇒ 400 + 结构化原因，**不借会话、不发探活**）。
2. 千帆只读探测：分页拉订单列表（按 `synced_at` 之后的时间范围**增量**拉）。
3. **幂等 upsert**：按 `order_no` 判重 —— 已存在 ⇒ 更新状态/金额/物流/售后；不存在 ⇒ 插入。
4. **状态映射**（下表）→ 本地 `status` 枚举。
5. **完整值落库、界面脱敏**：收货地址/姓名/手机完整值落库（履约发货必要），界面默认脱敏展示，完整值仅发货/打单/导出履约场景使用。
6. 同步完成回写 `synced_at`。

**状态映射**：

| 千帆状态 | 本地 `status` |
|---|---|
| 待付款 | 待付款 |
| 已付款 / 待发货 | 待发货 |
| 已发货 / 待收货 | 已发货 |
| 交易完成 | 已完成 |
| 退款中 / 售后中 | 售后中 |
| 已关闭 / 已取消 | 已关闭 |

**校验与边界**：只同步本账号店铺订单（`shop_id` 由绑定关系限定，越权空集不 404）；分页翻到无下一页（限流等待式，`ABSOLUTE_PAGE_CAP` 沿用一期）；异常先 `db.rollback()` 再记失败，不落半截数据。

### 7.4 二期写操作 · 业务逻辑（发货 + 售后）

**A. 发货** `POST /orders/{id}/ship`
1. 前置校验：订单属于本账号店铺 ∧ `status = 待发货`（否则 400 `ORDER_NOT_SHIPPABLE`）。
2. 入参：物流公司 + 运单号（批量发货：多条 `order_no` + 各自单号）。
3. **二次确认**：弹窗明示「将对真实订单执行发货、不可撤回」，用户再次确认。
4. 调千帆官方发货接口（合法写链路）。
5. 成功 ⇒ 落 `order_shipments` + `orders.status → 已发货`；失败 ⇒ 记录平台原文、状态不变、可重试。
6. **绝不自动发货**；批量发货逐条回滚，回执区分部分成功。

**B. 退款/售后处理** `POST /after-sales/{id}/handle`
1. 前置校验：售后单属于本账号店铺 ∧ `status = 待处理`。
2. 入参：处理结果（同意/拒绝）+ 拒绝理由。
3. **二次确认**：弹窗明示影响。
4. 调千帆售后接口。
5. 成功 ⇒ `after_sales.status → 已同意/已拒绝` + `handle_time` + `handle_result`；失败 ⇒ 记录原文、状态不变。

**统一约束**：发货/售后**不进工作流自动触发**（工作流止于「生成→定时→发布」），必须在订单页人工显式操作，每次独立二次确认。


备注本地写 + 清空 / 状态筛选 + 坏状态 400 —— 全绿。

#### ⚠️ 实测发现（写下来防止后来者「修错」）

**① 平台本身就给脱敏值。** 千帆订单接口返回的收件人 / 手机号**就是脱敏形态**
（`高*` / `189***2857`），DB 里逐字如此。**「完整值落库」这个前提对当前接口不成立**
—— 我们能拿到的上限就是平台给的。这不是缺陷（硬约束③：拿不到就不造，
**不许编一个真实姓名填进去**），但 `include_full` 的语义必须讲清：
**它只是「不做二次脱敏」，不等于「一定有原值」。** 页面据此提示
「平台未提供完整收件信息」，而不是让用户以为按钮坏了。

**② 状态词表是 `待收货`，不是 `已发货`。** 平台语义是「已发货**待收货**」。
且状态由**整数平台码**表驱动（`ORDER_STATUS_MAP`，真机采集：
`1`/`2,21,26`/`4,5,55`/`6,65,7`/`998`），**不认识的码留空串**（不猜）。

**③ 售后优先于发货态。** 已发货但买家申请退款 ⇒ 归「售后中」
（`AFTERSALE_IN_PROGRESS_CODES = (2,)`，售后终态 `3/4` 不改变订单归类）。

#### 本轮修掉的 3 个真缺陷

| # | 缺陷 | 影响 |
|---|---|---|
| 1 | `upsert_order` 对**空 `order_no`** 无守卫（docstring 许诺返回 `None`，实现只判键存在） | 空串落一行 `order_no=''`，该列有唯一约束 ⇒ **第二笔空单号订单会让整个同步任务撞 UNIQUE 崩掉** |
| 2 | `list_orders` 分页参数**只收窄在 `LIMIT`**，返回体回显**原始入参** | 前端传 100000 时页面显示「每页 100000 条」而实际只拿 100 条 ⇒ **分页器总页数算错** |
| 3 | `_csv_cell` 自己加引号 + `csv.writer` 再加一层 | **双重转义**：值变成 `"""带,逗号"""""`，Excel 打开多出可见引号 |

#### 与 §7.8 原型图的差异（如实记录）

- 原型图右列有 `[发货]` / `[售后]` 按钮 —— **未实现**，那是一期只读之外的写操作；
  页面底部明确写「发货、改价、售后审核属平台写操作，未授权，本页不提供」。
- 增加了**监控卡**（§7.7 的指标：订单数 / GMV / 客单价 / 退款率 / 平均发货时长 / 状态分布）。
- 详情用 **Drawer 60vw**（用户既有偏好：按视口百分比，不用固定像素）。

### 7.9 边界与合规

- **一期只读**：订单同步 + 查看 + 导出 + 监控（零写操作，安全）。
- **二期写操作（谨慎）**：发货、退款/售后 —— 走千帆官方合法接口，**显式确认 + 二次确认**，
  不自动发货、不自动退款；高风险，单独评审后再落地。
- 买家隐私（姓名/电话/地址）完整值落库（履约发货必要、商家本来可见），**界面默认脱敏展示**，完整值仅发货/打单/导出履约场景使用；日志脱敏；订单数据仅用于本账号经营。

## 9. 数据落库 / 不落库规划（全项目横切）

### 9.1 落库三原则

1. **可复用、需聚合、需历史追踪的数据 → 落库**（笔记、商品、订单、指标快照、媒体索引、提示词）。
2. **敏感数据脱敏后落库，明文不落库**（手机号/姓名）；**极敏感数据完全不落库**（Cookie/Token、详细收货地址），需要时实时拉取。
3. **纯展示性、可随时重拉的数据不落库**（延续一期「详情原文 JSON 收敛」思路，只落结构化结果）。

### 9.2 各方向落库规划总表

| 方向 | 落库 | 不落库 / 脱敏 |
|---|---|---|
| 1 LLM/媒体 | `llm_providers`（key 脱敏/加密）、`prompt_modules`/`prompt_templates`、`media_assets`（URL+AIGC 溯源）、`material_folders`/`material_files`（本地路径+缩略图） | 供应商 key 明文不落库；生成临时文件用完清理 |
| 2 热点 | `hot_topics`、`topic_goods_match`（结构化热度/趋势/相关度） | 话题全量原文不落库 |
| 3 仪表盘 | `metric_snapshots`（聚合快照） | 原始明细不重复落库 |
| 4 商品 | `shop_products`（+AI 字段）、`product_groups` | 平台商品原始大图不落库（只落 URL + 缩略图） |
| 5 工作流 | `workflows`/`workflow_nodes`/`workflow_runs`/`workflow_run_logs` | 运行中间临时产物不落库 |
| 6 订单 | `orders`/`order_items`/`order_shipments`/`after_sales`/`order_remarks`（字段级见 §7.2） | 买家手机/姓名脱敏；详细地址不落库；Token 不落库 |

### 9.3 敏感数据专项

| 数据 | 处理 |
|---|---|
| LLM 供应商 API Key | `system_settings` 加密落库，日志/响应 `[REDACTED]` |
| 平台 Cookie / Token | 不落库（会话内存，一期既有机制） |
| 买家手机号 / 收件人 | 完整值落库（履约发货必要），界面默认脱敏展示 |
| 详细收货地址 | 完整值落库（履约发货必要），界面默认脱敏展示，完整值仅发货/打单/导出使用 |
| AI 生成内容 | 保留 AIGC 溯源 `aigcTaskId`（合规要求） |
