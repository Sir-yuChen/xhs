## 1. 表关系拓扑（谁撑起全库）

按**被引用次数**（入度）排：

| 枢纽 | 被 N 张表 FK 引用 | 角色 |
|---|---|---|
| `users` | **34 条 FK / 32 张表** | **全局租户根** —— 32 张表挂 `user_id`（`system_settings` / `scheduled_job_logs` 各挂两列） |
| `platform_accounts` | **5 张表 / 6 条 FK** | **数据隔离的实际维度** —— `notes` / `monitoring_targets` / `account_cookie_versions` / `auto_tasks`(×2) / `publish_jobs` |

| `ai_drafts` | **3** | 草稿中心 —— `draft_assets` / `ai_generated_assets` / `publish_jobs.source_draft_id` |
| `llm_gateway_configs` | **3** | 网关配置 —— `llm_gateway_models` / `llm_gateway_alerts` / `llm_gateway_usage_logs` |

出度最大的（自己 FK 最多）：`generation_records` **5** · `auto_tasks` **4** ·
`scheduled_job_logs` / `role_menus` / `publish_jobs` 各 **3**。

**读法**：删表前先看它在上面这张表里。`users` 系（32 张表 / 34 条 FK）**只能删叶子**，删 `users`
等于删库；`notes` 系（4 张）删子表要同时改 `note_purge_service`（删笔记时级联清这些子表）。

### 1.1 数据落地的三条主线（2026-10-27/28 两次口径变更后的现状）

这两条结论会**推翻**「平台数据都同步到本地」的旧印象，读任何表前先记住：

| # | 数据 | 现在在哪 |
|---|---|---|
| ① | **平台商品 / 订单 / 笔记↔商品挂链** | **不落本地**。九个台账表已 DROP（迁移 `n8o9p0q1r2s3`），唯一读出口是 `services/realtime_platform_query_service.py`（平台实时查询）。本地没有对应表 |
| ② | **平台笔记明细（千帆数据中心）** | **只落 `note_datacenter_stats`**，不建 `notes` 行（2026-10-28 口径「数据中心数据不落内容库表」）。此前顺带建 `note_type=local` 的行，让内容库凭空多出 20 条副产物（现已全部软删） |
| ③ | **`notes` 表只存「属于自己的两类」** | `local_generated`（AI 生成）+ `collected`（采集）。内容库列表按 `LIBRARY_NOTE_TYPES` 白名单过滤；`local`（数据中心副产物）与 `synced`（同步链路已退场，410 `NOTE_SYNC_REMOVED`）都不进内容库 |
