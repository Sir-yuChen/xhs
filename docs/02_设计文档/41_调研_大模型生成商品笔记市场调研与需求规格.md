## §0 一句话结论

**项目已经具备「商品 → 笔记」的绝大多数零件（M1 已落地），缺的不是能力，而是「串成一条可交付的产线」** ——
本报告把「一期全链路」收敛为 **7 个必须补齐的缺口**（见 §5），把「二期热点」从「全站热搜」纠正为
**「平台按该商品推荐的热度词」**（真机实证口径，见 §6.1），并给出**可验收的判据**（见 §7）。
**本轮不做**：新建 AI 能力、引入外挂开源项目、语义相似度模型、全站热搜榜。

## §3 市场（商业方案 + 平台规则）调研

### 3.1 商业方案四层格局

| 层 | 代表 | 做法 | 定价（实测公开值） | 对本项目的定位 |
|---|---|---|---|---|
| **平台官方** | **千帆「智能生成」**（本地已接：`POST /xhs/product-notes/generate`） | 平台自己的商品→笔记 | 免费 | ✅ **已有**（第一套链路，保留） |
| 垂直 SaaS | 言影AI / 有赞「碰碰贴」 / 微盟「爆文仿写」 | 一句话/一张图 → 图文 + 视频；含 SEO 与情绪标签 | 订阅 | 参考其**功能清单**，不接数据源 |
| 通用大模型 | Kimi / 豆包 / 通义 / DeepSeek / 文心 | 直接写「小红书风」文案 | 已订阅 | ✅ **已有**（LLM 网关已配 6 家国内服务商） |
| 垂类生图 | **Nano Banana Pro** / Seedream 5.0 / Flux | 多参考图融合出图 | Seedream 0.12–0.30 元/张（免费额度 50–200 张） | ✅ **已有**（设计 19 已选型） |
| 开源 | RedInk / 上表 §2.1 | — | 免费（**非商用**） | ❌ 不整合（§2.2） |

**关键市场事实（可引用）**：

1. **AI 内容已成主流但不是免检通行证**：AI 辅助初稿 + 人工润色的笔记增速 **300%**，而**纯 AI 生成内容流量明显下降**（hashmeta 2026 种草策略）。
2. **平台已明确「不鼓励全 AI 生成」**：小红书创作者营销负责人原话 —— *"AI 只是工具，真正有价值的是创作者的个人观点、经历和独特视角"*（虎嗅 2026）。
3. **实战共识：AI 输出是 80 分初稿，需人工精修三件事** —— ① 去 AI 腔（删「此外/至关重要/值得一提」）② 加人味（真实体验 + 口语 + 平台黑话）③ 查事实（AI 编造数据概率不低）（翔宇工作流 2026 指南）。
4. **付费不必要**：本项目可走**本机 New API 免额度线路 + Seedream 免费额度**（50–200 张），与用户「不默认付费」口径一致（§4.4）。

### 3.2 平台规则（2026 版，**硬约束级**）

#### 3.2.1 AI 标识 —— 从「鼓励」升到「强制」且**已扩到账号层**

| 时间 | 事件 | 内容 |
|---|---|---|
| 2026-01 | 《社区公约 2.0》 | 「如果你在创作中使用了 AI 辅助工具，请**主动标明**」 |
| 2026-02 | 「薯管家」公告 | 未主动标识的内容，平台**识别后统一添加**；打击「去 AI 标识教程」黑产 |
| 2026-04-27 | 首届 AI 治理开放日 | 三条边界：① 鼓励 AI 作创意放大器 ② 反对 AI 作造假工具与低质内容生产机器 ③ **所有 AI 参与创作的内容均需主动标识** |
| **2026-08-07** | 《AI 治理规则公告》升级版 | **第一个把 AI 标识义务从「笔记层」扩到「账号层」** 的平台；AI 虚拟人形象运营的账号，资料页须如实说明并开「AI 虚拟人」标签 |
| 2025-09-01 | **国家强制标准** | 《网络安全技术 人工智能生成合成内容标识方法》**强制执行**（配套《标识办法》） |

**正向激励（重要利好）**：*「有标识的优质 AI 内容，将会得到**公域流量倾斜**」*（小红书官方口径）。

⇒ **本项目必须落地**：生成物的 AIGC 标识要**从「有字段」升到「发布时真的带上」**，且**不得删除/篡改**（§5 缺口 G7）。

#### 3.2.2 重复发布（**商品笔记专属红线**）

《笔记重复发布问题实施细则》（2025-04-06 生效，适用于**所有通过笔记带货的商家和买手**）：

| 场景 | 定义 | 处罚 |
|---|---|---|
| **完全相同** | 图文笔记的**图片、标题、文案**完全一致；视频笔记的**封面、内容、文案**完全一致 | ① 违规笔记及**该账号其他交易笔记在推荐列表少展现/不展现** ② **限制账号每日/每周交易笔记发布数量** |
| **高度相似** | 核心要素经**角度切换 / 顺序调整 / P图 / 拼接**等细微调整后重复 | 同上 |

⚠️ **这条直接否掉了「同一商品出 N 篇换换顺序就行」的做法** —— 项目已有设计 16 §M6「内容按账号维度变异（避免跨账号同文触发去重降权）」（T-605，未实现），本报告把它**提升为一期必做**（§5 缺口 G3）。

#### 3.2.3 商品笔记的**特殊推流机制**（决定「怎么生成才有量」）

| 项 | 常规笔记 | **商品笔记** |
|---|---|---|
| 优先流量 | 社区流量（推荐给普通用户） | **电商流量（推荐给在小红书有购物行为的用户）** |
| 冷启动流量 | 较大 | **较小**（这是结构性的，不是内容差） |
| 核心考核指标 | 封面点击率 / 互动率 / 转粉率 / 观看时长 | **额外考核电商端：商品点击率 / 支付转化率 / 商品加购率** |
| 续命机制 | 数据滚动 | **靠「成交」——没有动销的商品笔记会迅速掉量** |
| 内容占比建议（平台电商学习中心） | — | 起号期 `1 商品笔记 + 2 引流笔记 + 3 电商种草笔记` |

**单篇指标合格线（2026 参考值，可用于 AI 生成后的自评）**：图文点击率 ≥2.5% / 完读率 >40% / 收藏率 >5% / 互动率 ≥5%。
**发布后赛马窗口**：5 min / 30 min / 60 min（前 3 层），**前 1 小时决定能否晋级流量池**。

#### 3.2.4 爆款结构（**可直接变成 Prompt 骨架**）

| 要素 | 硬口径 | 出处 |
|---|---|---|
| 封面 | 3:4 竖版；文字 **≤8–15 字**；主体占比 ≥60%；有核心词大字点击率 +62%；**真实感 > 精修感**（互动率高 38%） | 青瓜 SOP / 人人都是自媒体 |
| 标题 | **= 搜索关键词（人群/场景/品类）+ 情绪钩子**；15–25 字最佳；核心词**前置**（前 4–6 字权重最高） | 保哥笔记 / 创业密码 |
| 标题公式（4 套） | ① 人群+痛点+方案 ② 数字+结果 ③ 反常识+警示 ④ 提问代入 | 青瓜 SOP |
| 正文 | **黄金三段式**：开头 50 字直击痛点 → 中间分点干货 → 结尾互动钩子；**600–900 字** | 青瓜 SOP / 设计 16 §2.6 |
| 正文前 100 字 | **必须含核心关键词**（搜索算法权重高） | 创业密码 |
| 关键词频次 | 核心词在标题+正文出现 **3–5 次最优，>10 次触发堆砌降权** | 创业密码 |
| 话题标签 | **3 个核心 + 3 个长尾 + 3 个场景**（三三法则）；**3 个精准垂直标签比 10 个热门标签曝光高 40%** | 青瓜 / 人人都是自媒体 |
| **埋词位（5 个，含易漏项）** | 标题 / 正文 / 话题标签 / **图片里的文字（会 OCR 识别计入权重）** / **评论区高频词** | 保哥笔记 |
| 搜索流量占比 | 从 2024 年 18% → **2026 年 34%**（且长尾持续数月–一年） | 人人都是自媒体 |
| 视频 vs 图文 | 同等互动下视频推流 ≈ 图文 **1.5 倍**；但图文**收藏率**是视频 2.3 倍 | 同上 |

⚠️ **禁忌词**（生成即拦）：绝对化（第一/最/顶级/必买）、营销感（特价/清仓/链接）。

| 有真实互动的商品数 | **81 / 1801** | 即 **95.5% 的商品零动销** |

#### 4.2.3 商品 ↔ 笔记**覆盖缺口**

| 项 | 值 |
|---|---|
| 售卖中商品 | 2010 |
| **零笔记商品** | **267**（13.3%） |
| 恰好 1 篇 | **1537**（76.5%） |

| 商品台账 `product_note_num` 分布 | 0 篇：300 / 1 篇：1509 / 2 篇：196 / 3 篇：16 |

**文本特征与效果的相关性（实测，用于否掉「玄学调参」）**：

| 阅读档 | 样本 | 平均正文字数 | 平均 emoji 数 |
|---|---|---|---|
| 0 阅读 | 400 | 357 | 6.2 |
| 1–9 | 134 | 320 | 6.5 |
| 10–49 | 8 | 314 | 6.6 |
| 50+ | 2 | 362 | 5.5 |

⚠️ **结论：字数与 emoji 数与阅读量**无单调关系**（四档几乎持平）** —— 不要再把「凑字数」「多插 emoji」当优化手段。
真正区分度在 **封面点击率 / 商品点击率**（这两项**当前台账拿不到**，见 §5 缺口 G2）。

#### 4.2.4 已有素材的真实形态（用于定 Prompt 与图位）

实测平台优质商品笔记正文（抽样 2 篇）的共同结构：

```
痛点场景开场（15 字内建立代入）
 → 商品全称（第一时间引出）
 → 感官体验描述（质地/触感/使用感受，非参数罗列）
 → 分点卖点（emoji 分隔，2–3 个核心卖点，不铺全）
 → 场景化使用（分 2–3 个场景讲怎么用）
 → 结尾轻互动/收藏引导
```

⚠️ **与 §3.2.4 的外部方法论完全同构**（痛点→干货→互动），可据此定 Prompt 骨架。
⚠️ **平台原文明确**「**卖点不要全**，专攻 2–3 个核心卖点更容易出万赞爆文」——本项目的 Prompt 必须**强制收窄卖点数量**。

## §6 二期（热点结合）调研结论

### 6.1 ⚠️ 数据源口径**必须纠正**（这是二期最重要的前置）

平台的**真实**能力边界（真机探测，2026-10-10，已登记设计 17 §13.11.1）：

```
POST /api/edith/aigc-publish/attributes   （只读）
ok: True
data.topic_list.topic_list_info:
  [{"topic":"餐垫",       "type":1, "hot_value":4673},
   {"topic":"桌旗",       "type":1, "hot_value":2794},
   {"topic":"毛孩子时装周", "type":2},          ← type=2 是活动话题（无热度）
   … 共 11 条]
  tips: "平台结合所选商品和社区热门笔记，为您推荐热度较高的词"
```

| 项 | 结论 |
|---|---|
| **有** | 平台按**该商品**推荐的**真实热度词**（`hot_value` 是平台给的，不是我们统计的） |
| **也有** | 同一次调用还带 `note_scene`（新品种草/活动大促/爆品孵化/日常宣发）、`note_style`（好物推荐/产品测评/攻略教程）、`seller_point`（**基于当前所选商品**的 20 个卖点词） |
| **没有** | **全站热搜总榜**（`apis/` 层实测无 `hot_search` / `trending` / `rank_list`） |

⇒ **二期口径定为**：**「平台按商品推荐的热度词 + 场景 + 风格 + 卖点词」四路输入**，**不是**「全站热搜榜」。
⇒ 页面文案**必须如实写**「平台按该商品推荐的热度词」，**不得**写成「全站热搜榜」（否则是编造）。

### 6.2 二期可用的**平台侧数据资产**（本机已有）

| 表 | 行数 | 能做什么 |
|---|---|---|
| `hot_topics` | 33 | 平台按商品推荐的热度词（按商品维度） |
| `topic_goods_match` | 33 | 话题↔商品匹配 + **可解释成分**（`match_reason` + `hot_value`） |
| `note_datacenter_stats` | 2005 | 自己账号商品笔记的真实指标（**含 `item_id` 归因**） |
| `note_metric_snapshots` | 10851 | 笔记指标日快照（趋势） |
| `shop_metric_snapshots` | 3972 | 商品指标日快照（库存/销量/价格） |

⚠️ **二期最大缺口**：热点链已给「话题」，但**没有「热点 ↔ 我的历史数据」的反馈环** ——
即缺「哪类话题/结构在我的账号上真的带来了商品点击」这一步（§7 二期 D2）。

### 6.3 二期的**不可做**（明确排除）

| 不做 | 原因 |
|---|---|
| 全站热搜榜 / 实时热榜 | **平台无此只读入口**（§6.1 实测） |
| 语义相似度模型做话题匹配 | 平台**已按商品做过一遍相关性**；且黑盒相似度「为什么这个词排第一」答不上来（DEF-057 同型不可追溯） |
| 大模型批量生成「高度相似」的 N 篇 | 《重复发布实施细则》**明确处罚**（§3.2.2） |
| 自动发布 | 延续一期「**绝不自动发布**」（设计明文口径） |

## §7 需求规格（**供 Gate 1 评审**）

### 7.1 需求（10 句话）

1. **角色**：本项目唯一实现方（开发者），使用者是管理多店铺/多账号的小红书带货运营者。
2. **项目名称**：「商品笔记智能生成产线」（店铺商品线）。
3. **一期目标**：**商品事实 → 结构化 Prompt → 文案 + 封面/配图 → 自评拦截 →（人工确认）发布**，全程无需人工写文案。
4. 一期产出的笔记必须**通过平台合规判据**（标题长度 / 正文字数 / 话题平台形态 / 禁忌词 / AI 标识）。
5. 一期产出的笔记**绝不相同**（同商品多篇、多账号多篇都必须有可检测的差异）。
6. 一期**绝不自动发布**（发布必须用户显式动作），延续一期口径。
7. **二期目标**：把「平台按商品推荐的热度词 / 场景 / 风格 / 卖点词」接入生成，并与**本账号历史数据**形成反馈环。
8. 二期**不做**全站热搜榜（平台无此只读入口）。
9. 成本：优先用**本机免额度线路 + 免费生图额度**；充值只在验证有效果之后。
10. 复用现有 M1 底座（网关 / 模板 / 素材库 / 队列 / 媒体 / 发布），**不新建能力、不整合开源项目**。

### 7.2 范围外

- ❌ 不整合开源项目代码（RedInk 是 **CC BY-NC-SA（非商用）**；xhs_content_agent 等触碰 C4）。
- ❌ 不做登录逆向、不碰平台写接口（除已有千帆合法发布链路）。
- ❌ 不做全站热搜榜（平台无入口）。
- ❌ 不本地部署大模型（30GB 显存 / vLLM 不在本机能力内）。
- ❌ 不做自动发布、不做评论/私信互动自动化。
- ❌ 不引入语义相似度依赖（保留**可解释**的匹配分口径）。
- ❌ 不做「凑字数 / 堆 emoji」类优化（§4.2.3 实测证明与效果无关）。


1. **AI 标识是强制的**（国家强标 2025-09-01 + 小红书 2026-08-07 账号层升级）。
   **不得提供任何「去除/篡改 AI 标识」的功能或教程**。有价值的一面：**有标识的优质 AI 内容会获得公域流量倾斜**。
2. **重复发布是商品笔记专属红线**：结论 **完全相同 / 高度相似**（含 P图/拼接/顺序调整）都会被限流**并限制账号交易笔记发布数量**。
3. **纯 AI 内容流量下降**（+300% 是「AI 初稿 + 人工润色」的增速，不是纯 AI）⇒ **去 AI 味 + 人工精修是必需品，不是加分项**。
4. **商品笔记考核电商指标**（商品点击率 / 支付转化率 / 加购率），**没有动销会迅速掉量** ⇒ 生成策略要服务「成交」，不是服务「字数/emoji」。
5. **限流与风控**：所有外部调用过 `CrawlRateLimiter.wait_allow()`，额度走运行时配置（基线 8，勿调高）。
6. **密钥安全**：LLM key 走 `system_settings`（按 user 隔离），不落代码/日志（`[REDACTED]`）。
7. **数据合规**：只采公开数据，不碰用户隐私；采集结果仅用于本账号运营决策。
8. **成本**：优先免费额度；不以付费为默认前提。

（正文 60 字、话题丢 `[话题]#` 形态）：**文案 Prompt 是代码兜底的，没人能调**。

#### 11.1.3 细化方案（按「补什么」分三层）

**第一层 · 补文本模板（`task_type="text"`，新建，P0）**

文本模板骨架必须**按 §3.2.4 爆款硬口径**写，至少含以下**六个段位**（每段可被公共模块覆盖）：

| 段位 | 内容 | 依据 |
|---|---|---|
| ① 角色与事实约束 | 沿用现有 `PRODUCT_NOTE_SYSTEM_PROMPT`（只用给定事实 / 不虚构 / 不绝对化） | 已实做，保留 |
| ② **人群 + 场景定位** | 从类目/属性推「谁在什么场景用」 | 「标题 = 搜索关键词（人群/场景/品类）+ 情绪钩子」 |
| ③ **标题结构**（多备选） | 4 套公式各出一条：人群+痛点+方案 / 数字+结果 / 反常识+警示 / 提问代入；**核心词前置** | 青瓜 SOP + 保哥笔记 |
| ④ **正文黄金三段式** | 开头 50 字直击痛点 → 中间分点干货 → 结尾互动钩子；**600–900 字** | 青瓜 SOP |
| ⑤ **埋词位**（**5 个位，含易漏的 2 个**） | 标题 / 正文 / 话题标签 / **封面图片文字（会 OCR 计入权重）** / 评论区引导语 | 保哥笔记 |
| ⑥ **话题三三法则** | 3 核心 + 3 长尾 + 3 场景；核心词出现 3–5 次（>10 次触发堆砌降权） | 青瓜 / 创业密码 |

**第二层 · 补文案用公共模块（P0）**

现有 2 个模块都是图用的，必须新增**文案向**类别（建议 `category` 取值）：

| 建议类别 | 模块示例（可组合） | 作用 |
|---|---|---|
| `tone` 语气 | 「朋友分享口语」「种草感叹」「干货理性」「吐槽真实」 | 去 AI 腔的第一道 |
| `structure` 结构 | 「痛点开场」「清单式」「测评式」「避坑式」 | 对应 §3.2.4 的 6 大框架 |
| `audience` 人群 | 「学生党」「租房党」「宝妈」「打工人」 | 人群词前置 |
| `deai` 去 AI 味 | **禁用词清洗表**：此外 / 至关重要 / 值得一提 / 综上所述 / 赋能 / 打造闭环 | 市场共识（§3.1 事实 3） |
| `taboo_text` 文本禁忌 | 绝对化（最/第一/顶级/必买）/ 营销感（特价/清仓/链接）/ 功效宣称 | 与现有 `forbidden_words` 表（实测 **505** 条）联动 |
| `selling_point` 卖点收窄 | 「**只选 2–3 个核心卖点**，不铺全」 | 平台原文「卖点不要全」 |

**第三层 · 商品事实结构化（承接 §5 缺口 G1）**

当前 `product_payload()` 是**白名单平铺**（`key: value` 直出），缺陷实测：
- `description` 是「键：值」拼串（`是否礼盒：其它 适用场景：日常 风格：新中式穿搭…`）—— 一整串
- `attributes` 与 `description` **内容重复**
- **`seller_point`（平台给的 20 个卖点词）实测存在于 `raw_json` 但没被用上**
- SKU 名里混着规格（`… 藏青色 XL 【建议130-145斤】`）

⇒ 抽取层需产出**结构化事实**（不是平铺串）：`核心卖点 top3` / `人群` / `场景` / `材质` / `尺寸` / `类目路径` / `价格区间`，
且**缺值留空不编造**（AGENTS.md §3.5）。

### 11.2 媒体组合 —— **推翻「六选一」，改「多选组合」**

#### 11.2.1 现状（**实测，这是关键约束**）

| 项 | 现状 |
|---|---|
| `media_source` 类型 | `String(32)` **单值列**（`backend/app/models/generation.py:94`） |
| 可选值 | **六选一**：`product_image` / `material` / `reference_image` / `ai_generate` / `video_ai_generate` / `video_reference` |
| 后端分流 | `_assets_for_media()` 是 **if/elif 链**，命中一个来源就 `return` ⇒ **天然单来源** |
| 前端 | `MEDIA_SOURCE_OPTIONS` 六项**单选**（`llm-generate-modal.tsx:38`），文案已写「四选一」 |
| 注释口径 | `#: media_source 四选一` —— 文档与实现**都不支持组合** |

⇒ **用户要的「智能生成 + 本地素材 + 商品图 组合」在当前形态下做不到**，必须改。

#### 11.2.2 组合方案（**设计定稿建议**）

**形态**：`media_source` 单值 → **`media_sources` 多值集合**（或保留单值列 + 新增 `media_composition` JSON）；
每条来源**各自带参数**（数量 / 顺序 / 参考图）。

建议的组合模型（**有序**，因为顺序决定笔记图序 —— 封面必须是第 1 张）：

```
media_plan = [
  { "source": "ai_generate",   "role": "cover",   "count": 1, "template_id": ..., "require_text": true },
  { "source": "product_image", "role": "content", "count": 3, "pick": [1,3,5] },
  { "source": "material",      "role": "content", "count": 2, "folder_id": ..., "file_ids": [...] },
  { "source": "ai_generate",   "role": "content", "count": 2, "template_id": ... },
]
```

**必须定死的四条规则**：

| # | 规则 | 理由 |
|---|---|---|
| R1 | **封面唯一且必须排第 1** | 封面决定点击率（§3.2.4）；多个封面 = 判据不明 |
| R2 | **总张数上限**（建议沿用现有图 ≤6 / 视频 ≤1 的口径） | 现有校验已存在，组合后**仍必须有一处总闸**（不是各来源各判一次 —— 那是 DEF-044 两份实现） |
| R3 | **同一来源可重复出现**（如两个 `ai_generate` 分组：一个出封面、一个出内页） | 否则「AI 封面 + AI 内页」要求不同模板时表达不了 |
| R4 | **视频与图片可共存**，但**视频不占图片位** | 视频来源实测独立（`VIDEO_MEDIA_SOURCES`），且**异步**（可能几分钟），失败不影响正文落库 |

**用户点名的组合（逐个落到 `media_plan`）**：

| 用户说法 | `media_plan` 表达 |
|---|---|
| 本地素材 | `[{material, content, n}]` |
| 智能生成 | `[{ai_generate, cover, 1, require_text}, {ai_generate, content, n}]` |
| 商品图 | `[{product_image, cover, 1}, {product_image, content, n, pick}]` |
| **智能生成 + 本地** | `[{ai_generate, cover,1}, {material, content,n}]` |
| **智能生成 + 商品图** | `[{ai_generate, cover,1}, {product_image, content,n}]` |
| **智能生成 + 本地 + 商品图** | `[{ai_generate,cover,1}, {material,content,n1}, {product_image,content,n2}]` |
| （隐含）三来源 + 视频 | 上述 + `[{video_ai/video_reference, video, 1}]` |

> 原文（`llm-generate-modal.tsx:39`）：

#### 11.2.4 媒体组合的**失败点**（补进 §7.3 的失败点表）

### 16.6 图片预览（口径 ② 的落地细节）

**三种来源的图来源不同，渲染方式必须不同**：

| 来源 | 图从哪来 | 渲染 | 为什么 |
|---|---|---|---|
| `product_image` | 商品台账主图（`shop_products` → `normalize_item_from_raw` 的 `images[:9]`，**公开 CDN 直链** `http://qimg.xiaohongshu.com/...`） | `<img src={url}>` 直接渲染 | 公开直链，无鉴权 |
| `material` | 素材库文件（**后端内容端点，要 Bearer**） | **必须走 object URL**（`fetchMaterialImageObjectUrl` → `URL.createObjectURL`） | ⚠️ 浏览器**不会**给图片请求带 `Authorization`；直接 `<img src="/api/...">` 必然 401 破图（本仓真实踩过：素材库缩略图曾整片破图） |
| `ai_generate` / 视频 | **尚未生成** | 显式文案「这张图要生成后才有，现在无法预览」 | 不装作有图（缺值口径：不造假、可见） |
| `reference_image` | 商品**首图** | 复用商品图预览条（`max=1`） | 后端就是取台账首图当参考 |

另外三条实现纪律：

1. **object URL 必须 revoke**（依赖变化 / 卸载时）—— 不 revoke 会漏内存，长会话下明显；
2. **依赖数组用内容而非引用**（`fileIds.join(",")`）—— 数组每次渲染都是新引用，直接进依赖会**无限重拉**；
3. **破图要说出来**（`onError` → 显「图裂」），不静默留白 —— 空白会让人以为坏了。

宿主改动：`shop-items-page.tsx` 把 `productImages={llmGenerateItem?.images}` 传进来
（**不传 = 商品原图预览恒空 = 等于没做**，这条也由守卫钉住）。

| 2 | 后端 `build_note_media` 不传 `media_options` | 就算前端传了，**服务端也丢掉** | `_assets_from_product_image(row, media_options)` |
| 3 | **`validate_media_options` 零调用方**（死代码） | 「素材没勾」「参考图超 4 张」**从来没被拦过** | 接进 `build_plan`（端点同步段） |
| 4 | `MAX_REFERENCE_IMAGES = 1` 恒定截断 | 用户勾 4 张，**只剩 1 张生效** | 放宽到 4 + **超限改 400**（不再静默截断） |

> **教训**：这四个都不是「功能没做」，而是**做了但没接线 / 接了但被截断**。
> 本仓「静默失效」出现频率远高于「功能缺失」—— 判据要落在**调用形态**上，
> 不能落在「符号存在」上（M23 首版哑弹正是这个错）。

### 17.5 视频笔记：来源收敛 + 上下布局 + 参考图可含本地素材（2026-10-16 第三批口径）

用户口径（逐字）：

> 「视频与封面 **上下布局**，不要左右布局。视频下拉应**只有本地素材和智能生成视频**。
> 使用本地素材这**无需再生成视频**，后端根据商品，以及提示词，本地素材参考生成相关的
> 文案标题话题等。智能生成视频需支持**选择参考图**，参考图可为**本地素材也可以是商品原图**，
> **最多一共 4 张**」

> 「参考图支持选本地或商品原图，**本地素材均需要支持预览**」

| # | 口径 | 落地 |
|---|---|---|
| 1 | ③ 区**上下布局** | `Space direction="vertical"`（封面在上、视频在下）；**不用 `Row/Col`**（`gutter` 靠负外边距，会把左列顶出容器裁掉标签）；**也不用 grid**（子项默认 `min-width:auto`，里面有横滑带 ⇒ 撑爆列宽）。竖排天然没有这两个坑 |
| 2 | 视频下拉**只 2 项** | `video_material`（本地素材）+ `video_ai_generate`（智能生成视频）；`video_reference` **整项退场**（与「智能生成 + 参考图」是同一件事，两个入口一实现 = 概念冗余） |
| 3 | 本地素材**不生成视频** | 新来源 `video_material` → `_assets_from_material_video()`：**只取素材里的视频**，**不调视频模型**（零成本、秒级）；文案仍走 LLM。⚠️ 选到图片 ⇒ `MATERIAL_VIDEO_REQUIRED` 结构化 400（不静默产出图）；平台只收 1 个视频 ⇒ `videos[:1]` |
| 4 | 智能生成视频**可选参考图** | `ReferenceImagePicker` 在段内（**在提示词上面**，与图片同一交互）；后端 `video_ai_generate` 也读 `reference_image_urls`（此前只有 `video_reference` 读 ⇒ 选了**静默不用**） |
| 5 | 参考图**可含本地素材** | 候选分三组：商品主图 ｜ 商品详情图 ｜ 本地素材（图片）。⚠️ **素材端点要鉴权** ⇒ 预览走 **object URL**（`fetchMaterialImageObjectUrl`），提交的仍是 `/api/xhs/materials/files/{id}/file` |
| 6 | **最多 4 张** | `MAX_REFERENCE_IMAGES = 4`，三组**合计**；前端选满变淡 + 提示，后端 `validate_media_options` 再拦一次（绕过前端时给 400 而非静默截断） |

**为什么本地素材能当参考图**（此前判断过「不行」，是错的）：`ai_service._resolve_image_ref()`
**本来就有**「非 http 引用 ⇒ 读盘转 base64 data URL」的能力（图片链路一直在用）。
视频链路只是**没接这个转换** ⇒ 补上即可，不需要改上游协议。
⚠️ 视频分支的素材引用是 `/api/xhs/materials/files/{id}/file`（素材有**自己的根目录**，
不是 `storage_dir/media`）⇒ 该分支按 `material_files.rel_path` 定位，拼错会静默取不到图。

**顺带修的一个真 bug**：视频分支封面那格的下拉曾显示**原始值 `product_image`**。
根因 = `options={sourceOptions.filter(o => o.form === "image")}`，而 `sourceOptions`
**已按 `noteForm`（video）过滤过** ⇒ 再筛 image 恒得空数组 ⇒ antd `Select` 匹配不到就把原始值印出来。
判据：**`filter` 的输入必须是全集**，不是已筛过的子集。
