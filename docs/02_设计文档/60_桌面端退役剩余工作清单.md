## 二、未完成（按依赖排序）

### 2.1 【阻塞】数据包文件夹选择：从「后端弹框」改为「浏览器上传」

**现状**（`package_precheck.py:96-257` + `:437-510`）：

* `POST /api/xhs/package-precheck/pick-folder` —— 让**服务器进程**弹 Windows 文件夹
  选择框，把 `D:\...` 路径返回给前端；
* `_ask_directory_windows()` / `_has_interactive_desktop()` / `_ask_directory()`
  —— 共约 **160 行**，跑 PowerShell `FolderBrowserDialog` 或 tkinter `askdirectory`；
* 前端 `pickPackageFolder()` → `loadWithPath(serverPath)` → `POST /precheck/local`
  用**服务器路径**打开目录。

**为什么在服务器上必然坏**：

1. 服务器**没有桌面会话** ⇒ `_has_interactive_desktop()` 恒 False，PowerShell 对话框
   要么弹不出要么卡满 180 秒超时；
2. 就算能弹，那也是**机房那台机器**的对话框，不是用户的电脑 —— 用户看不到；
3. 返回的 `D:\...` 路径是服务器本地路径，而用户的包在他自己的电脑上。

**正确形态**：浏览器 `<input type="file" webkitdirectory>` 选整个文件夹 →
从浏览器上传文件 → 服务端落到临时目录 → 复用现有 `_run_precheck()`。

**这不是删几行能完成的**，需要设计：

* 上传协议：multipart 多文件 + 保留相对路径（`webkitRelativePath`）；
* 落盘位置：`storage_dir/uploads/<token>/`，与现有 `token` 生命周期对齐；
* 大小限制与进度：一个数据包常见 100+ 图片、上百 MB；
* 清理：现有 `DELETE /{token}` 要连带删上传的临时目录；
* 前端：把「填写目录路径」输入框换成文件夹选择器 + 上传进度。

**判据**：在**无桌面会话**的容器里（`docker compose up`）能完整跑通一次数据包预检。

### 2.2 打包链路整体移除

`packaging/`（`build.ps1` / `installer.iss` / `SpiderXHS.spec` / `gitee_release.py` /
`github_release.py`）是桌面安装包链路。服务器形态不需要，但它同时承担
「构建前端产物 + 校验 + 冒烟」的部分职责，删除前要确认这些职责有新位置。

### 2.3 常驻服务入口切换

`.hermes/scripts/run-app.py`（监督进程 + 计划任务登录自启）是桌面形态入口。
服务器形态应由 `systemd` / 容器重启策略接管（已在 `deploy/` 备好）。
**但本项目当前仍在本机开发**，删掉它会让本地开发没有一键启动，
⇒ 保留到「真正迁到服务器」时再切，先在文档里标清「这个入口是开发用，不是部署用」。

### 2.4 `_MAIN_LOOP` / GUI 宿主残留

`package_precheck.py:254` 的 `_MAIN_LOOP` 与 `_has_interactive_desktop()`
只服务 2.1，随 2.1 一起删。

## 三、为什么不现在就全删

`pick-folder` 不是死代码 —— **前端 `product-publish-wizard.tsx:1006` 仍在调用它**。
直接删会让「商品发布 → 选择数据包」这一步当场崩掉，而上传协议还没设计。
⇒ 顺序必须是：**先做上传（2.1）→ 再删桌面链路（2.4 与 2.1 的旧实现）→ 最后动打包（2.2）**。
