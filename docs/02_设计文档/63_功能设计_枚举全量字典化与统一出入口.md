# 设计 63 · 枚举全量字典化与统一出入口

> 2026-10-25 立项。用户口径（三条，逐字）：
> ①「先排查当前项目的所有能使用字典的全部切换到使用字典，前端均切到字典」
> ②「所有枚举，类似全部使用字段配置为动态实时可变」
> ③「字段统一出入口」。
> 即：所有「枚举 code → 中文文案 / Tag 颜色 / 下拉选项」的映射，全部改为**数据字典
> （`dict_types` / `dict_items`）配置**，改字典即全站实时生效；前端只有一个取数点。

## §1 现状与根因

字典机制 12 组种子已在（设计 47 §2.4/§2.5：`dict_types`/`dict_items` +
`config/initial_data/dict_seed.json`），但**只有系统管理域几个页面在用**；
业务前端仍然硬编码了 **30+ 个映射族**（本次全量盘点，探查报告归档见本轮会话记录），
典型：

- 调度域：`lib/schedule.ts` 7 张表 + `task-records.ts` 6 张表（任务类型 24 键、
  队列来源 17 键）；
- 发布/账号域：`note-publish-gates.ts` / `login-state.ts` / `sync-gates.ts` /
  `publish-page.tsx STATUS_TAG_MAP` / `accounts-page statusLabelMap`；
- 商品域：`shop-items-view.ts` 4 张 + `qianfan-enums.ts` + `order-format.ts` +
  `datacenter-page` 2 张 + `violation-manage.ts` 2 张颜色函数；
- 系统域：`settings-view.ts` 2 张 + `system-users-panel STATUS_META`。

结构性问题（盘点实测）：4 处**逐字重复字典**（`JOB_STATUS_LABELS` 在
schedule.ts 与 auto-ops-panel.tsx 各一份；`PUBLISH_STATUS_LABELS` 在
note-publish-gates.ts 与 shop-items-page.tsx 各一份；重生成 scope 文案两份；
`ORDER_STATUSES` 在 api.ts 与 order-format.ts 双份）—— 正是「前端写死」的代价。

## §2 设计

### §2.1 统一出入口（后端）

**`GET /api/system/dict/options`**（新增，登录即可、无权限码 —— 枚举文案是每个
页面的展示依赖，不是管理能力；管理端 `GET /items` 仍要 `system:dict:view`）：

- `codes` 查询参数（逗号分隔）可选；缺省 = 全量 normal 组（表几十行，一次全取
  比按页散取省往返 —— 前端 store 一次灌满）；
- 只下发消费方四字段（`value/label/list_class/sort_order`），管理字段不下发；
- 类型与项都只出 `normal`（停用组整组不出、停用项单条不出）；
- 每次读库、无进程内缓存（设计 59 口径）⇒ 字典改完服务端即时生效。

前端唯一请求函数 `fetchSystemDictOptions()`（`lib/api.ts`）。

### §2.2 统一出入口（前端）：`lib/system-dicts.ts`

- 模块级 store：登录后首次有消费方读字典时**惰性拉一次全量**（`ensureDicts()`
  幂等、并发只发一次；未登录不发起）；
- 同步读：`dictLabel(code, value, fallback)` / `dictListClass(code, value, fallback)`
  —— 供 lib 层格式化函数与表格列 render（非组件上下文，不能上 hook）；
- 响应式读：`useDictOptions(code, fallback)` / `useDictLabel(...)` /
  `useDictVersion()`（`useSyncExternalStore` 订阅）；`useDictVersion()` 挂在
  `workspace-shell`，字典一刷新整棵应用树重渲染 ⇒ 表格里的同步读也即时更新；
- **回退口径**：字典未加载 / 组不存在 / value 不在组里 ⇒ 用各枚举自带的**镜像
  常量**兜底（常量保留、继续被既有守卫与 .cjs 契约断言）。字典查到 ⇒ 字典赢。
  缺值不造假、也不裸奔（「平台优先 + 本地跟随」同款思路：字典是配置层，常量是地板）；
- 字典管理页（`system-dict-panel.tsx`）四个变更成功点全部追加 `refreshDicts()`
  ⇒ 全站实时生效（「动态实时可变」的客户端侧）。

### §2.3 `list_class` 白名单放宽（迁移 `c9b8d7e6f5a4`）

前端实际用 antd 预设色 `green/orange/gold/cyan/purple/processing/...`，
原 CHECK 只放行 5 档状态色 ⇒ 字典表达不了颜色。放宽 `ck_dict_items_list_class`
到 **antd 全量预设**（5 状态色 + 13 预设色 + processing/error）：

- `models/dict.py` `LIST_CLASSES` 扩元组（唯一真相源）+ `LIST_CLASS_PATTERN` 共用正则；
- 迁移 `c9b8d7e6f5a4`（revises `e7f8a9b0c1d3`）：PG `DROP CONSTRAINT` +
  `ADD CONSTRAINT`；**SQLite 分支走 batch_alter_table 重建表**（SQLite 不支持
  DROP CONSTRAINT，测试夹具会在 SQLite 上跑全链 —— 迁移 id 初稿用
  `f8a9b0c1d2e3` 与既有迁移撞车，已改名，AGENTS 记过同款教训）；
- `system_dict.py` 建/改项的 `Field(pattern=...)` 改引用同一正则；
- 字典管理页 `LIST_CLASS_OPTIONS` 同步扩（20 档）。

### §2.5 不字典化的边界（明确排除，防口径蔓延）

纯前端**结构**映射不是枚举展示，不入字典：Cron 构建器（字段/预设/占位符）、
任务参数 schema（`PARAM_LABELS`/`PARAM_UNITS`/`KNOWN_KEY_HINTS`）、
路由分组与缓存键（`ROUTE_BUSINESS_LINES`/`ACCOUNT_SCOPE_KEYS`/`SOURCE_ROUTES`/
`HOME_BY_ROLE`）、平台品牌色（`BRAND_ICONS`/`WORKSPACE_COLORS`）、违规平台表头
反向别名（`aliases`，中文→code 方向特殊）、登录方式矩阵、`PRICE_TARGET_LABELS`
（映射表列定义）、`PIE_COLORS`/`LINE_COLORS`。理由：它们不是「平台枚举的展示层」，
改成可配置只会引入「配置坏了页面瘫」的风险，无用户价值。

## §3 硬规矩

1. **回退常量必须保留**：所有被切走的映射，原常量不删（降级地板 + 既有契约测试锚点）。
2. **重复字典必须收敛**：4 处逐字重复，各收敛为一份（fallback 常量单点定义）。
3. **守卫同步抬**：镜像守卫新增组逐个钉；`test_testing_spec_guards` 不放行回归。
4. **字典只管展示**：`value` 永远是代码枚举值，字典改 label/颜色/排序，**不许**
   改 value 语义（改值 = 代码升级，不是配置）。

## §6 系统管理域布局修缮（同日追加，用户两张截图点名 + 「扫描其它系统管理页面全部优化」口径）

**病灶（两类同根）**：`<Content>` 只给了 `minHeight`（无固定高度），面板卡
`height:100%` 落空 ⇒：

| 面板 | 病灶 | 截图 |
|---|---|---|
| 字典管理 | 两张表固定 `scroll.y=520` ⇒ 卡片到视口底之间**一大块空白** | 图 1 红框 |
| 用户管理 | 整卡 `overflow:auto` ⇒ **分页随内容滚出屏外**、末行被截断 | 图 2 红框 |
| 角色 / 菜单 / 日志 | 同用户管理（整卡滚动形态） | 扫描发现 |

**修法（统一，非逐页自创）**：把 `.shop-items-table`（2026-10-11）与
`.violation-table`（2026-10-18）这两份逐字拷贝的三区布局 CSS **收口成共享类
`.fill-table`**（CSS 注释里"第五处该抽公共类"的预言兑现；DEF-044）：

- 页面根 `height: calc(100vh - 87px)`（= 视口 − 顶栏 48 − Content 内边距 15+24，
  与 workspace-shell `<Content>` padding 一字对齐）；
- 卡头 / 筛选行 `flexShrink:0` 固定；`.fill-table` 层 `flex:1; minHeight:0`；
  表格 `scroll={{ x, y: "100%" }}` ⇒ **表体内部滚动**；`.ant-pagination`
  `flexShrink:0` ⇒ **分页钉在卡底**；
- 字典管理为双卡变体：`Row` 撑满，两 `Col` 各 `height:100%`，两卡内部同链
  （无分页，纯表体滚动）。

五个面板（users / roles / menus / dicts / logs）全部接入；`.shop-items-table` /
`.violation-table` 保留为别名（存量页面零改动）。`tsc` 0 error、vitest 545 绿、
页面守卫 + 18 个行为脚本绿（4 条红为存量，干净树复测同样红）。

### §6.1 布局通病入册（2026-10-25 用户两次截图返工后立规，AGENTS §3 硬约束 7）

「撑满 → 分页出屏」本项目已踩三次，根因各不相同但症状一致，全部收进
AGENTS 硬约束 7 + 守卫 `test_fill_table_wrappers_pin_pagination`：

| # | 踩坑 | 根因 |
|---|---|---|
| 1 | 商品台账（2026-10-11 前） | 中间层（Spin/spin-container/wrapper/table）默认 height:auto，高度链断 ⇒ 分页被内容顶出 |
| 2 | 审计日志 Tab（本轮） | 根用 `calc(100vh-87px)` 但处在 Tab 内 ⇒ 叠加 Tab 条高度后正好把分页顶出一根 Tab 条；**Tab 内内容根必须 `height:"100%"`，由 `.fill-tabs` 给高** |
| 3 | 应用日志文本区（本轮） | `flex:1 + minHeight:0` 但没给 `overflow:auto` ⇒ 长文本透明地盖在翻页按钮上（「透明部分影响操作按钮」用户原话） |

**规范动作**：撑满一律用 `.fill-table` / `.fill-tabs` 共享类，不手写；改完真机确认
分页/底部按钮可见；守卫钉「wrapper ⇒ scroll y:"100%"」配对与「logs 文本区 overflow」。
