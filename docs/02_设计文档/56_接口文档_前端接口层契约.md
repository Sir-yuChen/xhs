# 三、错误处理契约（前端唯一入口）

## 3.1 `detail` 两种形态的分流

```ts
// lib/api-error.ts（新建）
export interface ApiErrorBody {
  code: string;
  message: string;
  required?: string;
}

export function parseApiError(err: unknown): ApiErrorBody | null {
  const detail = (err as any)?.response?.data?.detail;
  if (detail && typeof detail === 'object' && typeof detail.code === 'string') {
    return detail as ApiErrorBody;
  }
  if (typeof detail === 'string') return { code: 'LEGACY_STRING', message: detail };
  return null;
}
```

## 3.2 分流规则（写进 `useApiError`）

| `code` | UI 行为 |
|---|---|
| `PERMISSION_DENIED` | `message.warning('无权限：' + required)`，**不跳登录** |
| `USER_PENDING` / `USER_DISABLED` | 登录页内联提示，**不跳登录** |
| `USERNAME_TAKEN` / `EMAIL_TAKEN` / `DICT_ITEM_DUPLICATED` / `ROLE_CODE_TAKEN` / `PERMS_DUPLICATED` / `PATH_DUPLICATED` | **表单字段级红字**（不弹 message） |
| `CONFIRM_NAME_MISMATCH` | 确认框内红字 |
| `LAST_ADMIN_PROTECTED` / `ROLE_SYSTEM_PROTECTED` / `MENU_IN_USE` / `MENU_HAS_CHILDREN` / `ROLE_IN_USE` | `message.error`，文案用后端 `message`（含人数等具体信息） |
| `LEGACY_STRING` | 原样 `message.error` |
| 其它 | `message.error(message \|\| '请求失败')` |

## 3.3 401 的特殊处理（已有拦截器的扩展点）

**401 一律跳登录**（现有行为），**但要排除三种**：

| 端点 | 401 时 |
|---|---|
| `POST /auth/login` | 不跳，就地提示 |
| `POST /auth/refresh` | 不跳，清令牌后跳登录（**现有 `_authRetry` 短路机制，别动**） |
| `POST /auth/send-register-code` 等公开端点 | 不跳 |

> ⚠️ 这条是 DEF-075 的教训：`/auth/refresh` 自身 401 时不能再去 refresh，否则无限递归。

# 四、hooks 契约

## 4.1 `usePermission`

```ts
export interface UsePermission {
  hasPermission: (code?: string | null) => boolean;
  hasAny: (codes: string[]) => boolean;
  hasAll: (codes: string[]) => boolean;
  isAdmin: boolean;
}
```
**判据**
- 权限码来源：**只从 `CurrentUser.permissions` 读**，前端不硬编码任何码（守卫 G12）
- `isAdmin` 判据：`role === 'admin'`（admin 的权限码是后端全量下发，但 UI 上有些「内置不可改」的提示需要知道是不是 admin）
- 空 `code` ⇒ 返回 `true`（「没声明权限 = 不拦」只用于内部工具组件，业务按钮必须显式传码）

## 4.2 `useDict`

```ts
export function useDict(typeCode: string): {
  items: DictItem[];
  loading: boolean;
  error: string | null;
  map: Record<string, DictItem>;       // value -> item
  labelOf: (value: string) => string;  // 缺值返回原值（不造假）
}
```
**缓存语义**
- 进程内 `Map<typeCode, DictItem[]>`
- 飞行中请求复用同一 `Promise`（避免同页多次挂载打 N 次）
- 不设过期（字典变更后由「字典管理页」调 `clearDictCache(typeCode)` 主动清）

## 4.3 `useMenuTree`

```ts
export function useMenuTree(workspace: string): {
  tree: MenuNode[];
  flatC: MenuNode[];          // 拍平的 C 行（侧栏用）
  pathMap: Record<string, MenuNode>;  // path -> C 行（路由守卫用）
```

# 五、路由守卫契约

## 5.1 `RequirePerm`

```tsx
<Route path="/system/users" element={
  <RequirePerm perm="system:user:view"><UsersPage /></RequirePerm>
} />
```
**行为**
| 情况 | 结果 |
|---|---|
| 未登录 | 跳 `/login`（由外层 `ProtectedRoute` 处理） |
| 已登录、无码 | 跳 `/403`，**不显示页面骨架** |
| 已登录、有码 | 渲染 children |

## 5.2 `RequireWorkspace`

```tsx
<RequireWorkspace ws="system">...</RequireWorkspace>
```
**行为**：`workspaces` 里没有该 key ⇒ 跳 `/platform-select`（选工作区页），不跳 403
（因为用户可能只是没进这个工作区，不是没权限）。

## 5.3 侧栏渲染

`app-shell.tsx` 从 `menus[workspace]` 渲染，**不再用硬编码数组**：
```tsx
const items = buildAntdMenu(menus[workspace] ?? []);
// FALLBACK_MENUS 只在 /auth/me 失败时用，且开发期断言 key 集合 == 种子 C 行集合
```
