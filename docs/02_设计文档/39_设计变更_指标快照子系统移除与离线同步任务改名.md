# 设计变更 · 指标快照子系统移除 + 离线同步任务改名

> **状态**：✅ **已实施**（2026-10-13）
> **性质**：**移除**（指标快照/趋势整块退场）+ **改名**（`system.note_data_sync` 显示名）
> **上游**：2026-10-13 用户口径 ——
> *「把商品洞察和内容洞察中的指标相关内容逻辑移除，包括店铺商品指标快照采集、笔记指标快照
> 采集定时任务移除，后续作为专项单独排期。」*
> *「离线笔记数据同步定时任务改为数据中心笔记指标同步。」*
> **本文档是代码变更的发起件**（AGENTS.md §3.1「文档先行」）。
> **取代**：设计 17 §13.5 / §13.9 / §13.10 三节（M2 数据仪表盘切片 1/2/3，已整块废止）。

## §0 一句话

把 **M2 时代的「指标日快照 + 趋势」子系统整块摘掉**：4 个端点、2 个服务模块、2 个内置定时任务、
前端面板与纯逻辑库、两页接线全部退场；**指标口径读取（`note_metrics()`）与两张快照表及其历史数据保留**，
后续作为专项单独排期。同一轮把 `system.note_data_sync` 的中文名从「离线笔记数据同步」
改为「**数据中心笔记指标同步**」（**键不变**，只改显示名与文档口径）。

## §2 改名

| 项 | 旧 | 新 |
|---|---|---|
| `scheduled_jobs.name`（键 **不变** `system.note_data_sync`） | 离线笔记数据同步 | **数据中心笔记指标同步** |
| `scheduled_job_logs.job_name`（历史快照） | 离线笔记数据同步 | **数据中心笔记指标同步**（同一个任务的历史不该被劈成两半，同 `c2d3e4f5a6b7` 纪律）|
| `job_registry.py` JobSpec `name` / 顶部注释 / `scheduler_service` 兜底注释 | 离线笔记数据同步 | 数据中心笔记指标同步 |
| `config/initial_data/scheduled_jobs.json` | 离线笔记数据同步 | 数据中心笔记指标同步 |

**⚠️ 键不变 ⇒ `apscheduler_jobs` 不受影响**（store 里的 job id 是 `job_<scheduled_jobs.id>`，
行主键，见 `scheduler_service._apscheduler_job_id`），也**不存在新旧键并存的重复行问题**
（那是 `c2d3e4f5a6b7` 改名**改键**时才有的坑，见 DEF-077）。

**⚠️ 「离线笔记数据导入」刻意**不改：它是 `POST /notes/offline/import` 写入的**另一条**日志 `job_name`
（导入 xlsx，与「同步」不是一件事），前端数据中心页的导入按钮态正按这个名字收口。**只改同步那条**，
否则导入解析中的按钮态判断会被一起改掉。

## §3 迁移 `b1c2d3e4f5a7`

```
down_revision = a7b8c9d0e1f3   # head
upgrade():
  ① SELECT id FROM scheduled_jobs WHERE job_key IN (两快照键)   # 先查后删：调度注册项 key 要拼
  ② DELETE FROM apscheduler_jobs WHERE id IN ('job_<id>', …)    # 否则调度器继续按旧 cron 跑已删项空转
  ③ DELETE FROM scheduled_jobs WHERE job_key IN (两快照键)       # 幂等：无行时影响 0 行
  ④ UPDATE scheduled_jobs      SET name = '数据中心笔记指标同步' WHERE job_key = 'system.note_data_sync'
  ⑤ UPDATE scheduled_job_logs  SET job_name = '数据中心笔记指标同步' WHERE job_key = 'system.note_data_sync'
downgrade():
  删除项**不重建数据行**（内置初始化数据，回退版本由代码注册表播种恢复 —— 避免「迁移里的种子」与
  代码注册表两份真相源，R24 纪律）；改名回「离线笔记数据同步」。
```

⚠️ **刻意不 import 应用代码**（`APSCHEDULER_JOB_PREFIX` 就地同值定义）：迁移必须能在「当时任意版本的
代码」上跑通。

⚠️ **顺带修夹具**：`test_scheduled_jobs.py::test_dedupe_seeded_scheduled_jobs_migration` 的省略版建表
`CREATE TABLE scheduled_job_logs` 缺 `job_key` / `job_name` 两列（本迁移要 UPDATE 它们 ⇒ 会 `no such column`）。
这两列是更早的 `y8z9a0b1c2d3` 加的、不在该用例 stamp 区间内重跑 ⇒ 补进夹具。

## §5 边界（明确不做）

| 项 | 结论 |
|---|---|
| `note_metric_snapshots` / `shop_metric_snapshots` 表与历史行 | **不 drop、不清理**（后续专项复用） |
| `note_metrics()` 口径（含 `views`） | **保留**（榜单/互动排名/内容洞察 KPI 仍在用） |
| 内容洞察 KPI 概览四卡 | **保留**（实时聚合，非快照） |
| 「离线笔记数据导入」`job_name` | **保留原样**（另一条链路的日志名，前端按钮态依赖） |
| 已废止条目的文档正文 | **原样保留** + 加废止标注（AGENTS.md 的先例：链 7 正文保留作历史） |
| 指标快照的**重新设计** | 不在本轮，按用户口径「后续作为专项单独排期」 |
