## 2. 本轮新增 / 修订需求

### R13（修订）· 任务日志表列收敛为 6 项

**用户口径（2026-09-24）**：
> 日志只需展示任务名称、任务类型、任务状态、触发方式、开始执行时间、
> 任务进度 + 耗时或异常信息；其它信息在详情弹窗中全部展示。

| 列 | 数据源 | 说明 |
|---|---|---|
| 任务名称 | `job_name` 快照 | `job_key` 不再作副行展示，移入详情 |
| 任务类型 | `job_trigger_type` 快照 | 三档：手动执行 / Cron 周期 / 定时一次 |
| 任务状态 | `status` | running / success / failed / skipped |
| 触发方式 | `trigger_type` | scheduled（调度）/ manual（手动） |
| 开始执行时间 | `started_at` | Shanghai 时区格式化 |
| **任务进度 + 耗时或异常** | **新增 `progress` 列** + `duration_ms` / `exception_info` | 一列合并：成功显进度条 + 耗时；失败显进度条 + 异常摘要 |

**移入详情弹窗**（弹窗已在展示 `config_snapshot`，天然覆盖）：
触发器摘要、错过策略、并发、`job_key`、`message`、`result` 全文、异常全文。

**决策记录**：「任务进度」两张表原本都没有 ⇒ **`scheduled_job_logs` 新增 `progress` 列（Integer 0–100，默认 0）**。
不选「只展示耗时/异常」是因为用户明确要求「进度条」。

### R14（新增）· 任务类型收敛为三档，「间隔周期」并入 Cron

**用户口径（2026-09-24）**：
> 只是任务列表新增一个任务类型，与周期性任务一样，另外将间隔周期合并到 cron 周期中。
> 新增「手动执行」任务类型，只能手动触发，触发立刻执行。

| 维度 | 改前 | 改后 |
|---|---|---|
| `trigger_type` 取值 | `at` / `cron` / `interval` | **`manual` / `cron` / `at`** |
| 手动执行 | 无（仅「执行一次」按钮） | 新档位：不参与调度装配，点「执行一次」立刻跑 |
| 间隔周期 | 独立档位（`interval_seconds`） | **并入 cron**（如「每 6 小时」= `0 0 */6 * * *`） |
| `interval_seconds` 列 | 存在 | **彻底删除**（alembic batch，同 `auto_tasks` 删调度列手法） |

**存量换算（alembic 迁移，自动换算）**：

| 旧 interval | 等价 cron | 备注 |
|---|---|---|
| 60 | `0 * * * * *` | 每分钟（秒位 0） |
| 7200 | `0 0 */2 * * *` | 每 2 小时 |
| 21600 | `0 0 */6 * * *` | 每 6 小时 |
| 非整小时（如 5400） | 保守近似 | 迁移内按 `*/N 分钟` 不可表达时回退整点；**逐行记迁移日志** |

⚠️ 换算规则必须**逐字符单测钉死**（与 §4.4 的 `isoweekday→dow` 换算同型要求）。

**新档位语义边界**：

1. `trigger_type=manual` 的行**不被调度器注册**（`sync_jobs_from_db` 跳过）；
2. 「执行一次」按钮对三档都可用（若依同），但只有 `manual` 档是「只能手动触发」；
3. `manual` 档的 `cron_expression` / `run_at` 留空。

> **后续修订（2026-09-24 同日，R15 / R16 / R17）**：本节的「手动执行 / Cron 周期 / 定时一次」
> 作为**表单与详情**的全称保留；**列表列**改用简写，见 §2.5 R15。原句保留，不删。

### R17（新增）· 任务日志查询条件不加「手动执行」

**用户口径（2026-09-24）**：
> 任务类型中添加了手动执行 那么任务日志的查询条件的任务类型是不是不能加这个手动执行？

**裁定：不加。** 依据是**语义分层**，不是「能不能」：

| 维度 | 说明 |
|---|---|
| **任务类型**（R14 三档） | 描述**这个任务怎么被触发**（手动 / Cron / 定时）—— 是**任务自身的属性** |
| **触发方式**（`scheduled_job_logs.trigger_type`） | 描述**这一次执行是谁发起的**（`scheduled` 调度触发 / `manual` 手动执行）—— 是**单次执行的属性** |
| 为什么不加 | 加了就会出现**两个都叫「手动执行」的筛选项指向不同字段**（一个筛任务的类型、一个筛某次执行的发起方）⇒ 用户看到的界面自相矛盾（DEF-044/047/058「同一语义两份实现」的同族：**同一个词两个含义**） |
| 用户想看「手动执行的任务」怎么办 | 在**任务列表**按类型筛（R14 已支持三档）；日志页的「触发方式」筛的是「这次是谁发起的」，两者是**不同维度**的问题 |

**连带修复**：日志页类型筛选原先还留着已退役的 **`interval`** 档（R14 遗留），本轮一并删除 ——
筛选项必须与 `TRIGGER_TYPES`（`manual` / `cron` / `at`）**同源**。⚠️ 该筛项目前列 `cron` / `at`
两档：`manual` 任务**不产生调度日志**（它不被调度器注册，只有「执行一次」的 `trigger_type=manual`
日志行），因此按「任务类型」筛日志时给 `manual` 档没有可筛的对象。
