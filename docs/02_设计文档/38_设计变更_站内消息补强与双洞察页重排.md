# 第一部分 · 站内消息模块成熟度分析与补强（R2-A / R2-C）

## 1. 现状与逐项判定（2026-10-13 实测）

对照「成熟站内消息模块」应具备的能力，逐项判定本项目有 / 无，并给出处置：

| # | 能力 | 旧实现 | 判定 | 处置 |
|---|---|---|---|---|
| 1 | **分页** | `list_notifications` 先 `.all()` 全表读进内存再切片 | ❌ 假分页 | **改 SQL `LIMIT/OFFSET`** + 独立 `total` 计数（`paginated_with_total`） |
| 2 | **未读计数** | 前端 `items.filter(!read).length`（只数当页 20 条） | ❌ 未读 >20 时恒显示 20 | **新增 `GET /notifications/unread-count`** 全量计数端点 |
| 3 | **分类/来源过滤** | `source_type` / `level` 有列但端点不支持过滤 | ❌ | **列表端点新增 `source_type` / `level` 查询参数** |
| 4 | **删除/清理** | 无删除端点、无保留期清理 | ⚠️ 缺 | 本轮**不做**（告知：需要另立保留期口径，见 §3 待办） |
| 5 | **实时性** | 30s 轮询 | ⚠️ 可接受 | 轮询保留（桌面单机 SSE 成本不划算）；**触发侧**改秒级（见第二需求） |
| 6 | **去重** | LLM 预警有同日去重；通用层无 | ⚠️ 部分 | 预警同日去重保留（R2-B）；通用层去重本轮不做 |
| 7 | **点击跳转** | 点击仅标已读，不跳转 | ❌ | **新增来源→路由映射**（`lib/notification-routes.ts`），点击跳来源页 |

## 2. 自动触发（取代定时任务）

用户口径「移除 LLM 网关预警任务，实现根据配置的规则自动触发」的落地：

- **移除** `system.llm_gateway_monitor` 内置任务（`job_registry.py` 删 JobSpec + 种子文件删条目 +
  迁移 `a7b8c9d0e1f3` 清存量 `scheduled_jobs` 行与 `apscheduler_jobs` 注册项）。
- **新触发点** = 台账写入路径：`llm_gateway_usage_service.record_usage()` 成功落一行后
  投递一次评估（`notify_usage_recorded`）⇒ **延迟从「≤10 分钟」降到「秒级」**。
- **异步 + 去抖**：后台单线程 worker 按 `(user_id, gateway_id)` 去抖合并（`DEBOUNCE_SECONDS=5s`），
  避免把评估放大到每一次调用上（记账是旁路，不得拖慢业务，DEF-048）。
- **判定逻辑不重写**：仍调用 `llm_gateway_monitor_service.evaluate_alert`（唯一实现），
  同日去重（`last_fired_at`）与三级作用域（全网关/服务商/具体模型）语义**原样保留**。
- 删的是「定时器」，不是「判定规则」。

## 3. 待办（本轮不做，如实登记）

- **通知保留期清理**：通知只增不减，长期会累积。需先定「保留多少天 / 是否只清已读」口径
  （参考任务记录清理口径）再实施，本轮不做。
- **通用层同源去重**：预警有同日去重，其它 `source_type` 无通用去重。另议。
- **SSE / 长轮询**：30s 轮询对单机桌面够用；上 SSE 需评估后端长连接成本，暂不做。

# 第二部分 · 双洞察页重排（R3-A / R3-B）

## 4. 信息架构复核

| 页 | 承载 | 用户口径 |
|---|---|---|
| **内容洞察**（`insights-content-page.tsx`） | 内容线：内容库笔记指标 + 热点话题 + 评论洞察 | 两条线**分开看** |
| **商品洞察**（`insights-shop-page.tsx`） | 店铺线：商品指标趋势 + 店铺快捷入口 + 订单口径入口 | 同上 |

⚠️ **不得破坏的纪律**：`insights-shop-page` 把订单指标**只放入口**（订单页顶部已有完整指标卡）
—— 复制一份就是两份真相源（同一指标两处不一致时最难查）。重构只**组织**，不**复制**。

## 5. 布局重设计

### 5.1 内容洞察（重排三件事）

① **信息层级**：KPI 概览（4 卡）→ 趋势（主图，全宽）→ 明细（高潜内容主 + 热点/评论侧）→ 高赞评论（全宽）；
② **色板**：走 `useThemePalette()`（深浅主题都过）；
③ **间距/栅格**：区块间距 16、卡片内边距一致、`<Col xs={24} lg={16|8}>` 窄屏塌陷单列。

⚠️ **保留结构性红块**：加载失败走 `<Alert type="error">内容洞察加载失败</Alert>`（三分法），
**不得**被消息化（守卫 `test_page_optimizations.py` 钉住 `type="error"` + `内容洞察加载失败`）。

### 5.2 商品洞察（补齐空洞）

原页仅面板 + 一张入口卡（56 行，观感偏空）。补齐**经营三块**：

① **商品指标趋势**（复用 `MetricsDashboardPanel scope="shop"`，图表实现一份，两侧共用）；
② **店铺快捷入口**（商品管理 / 订单管理 —— 把「看数」接到「干活」）；
③ **订单口径说明**（不复制订单指标卡，只放入口 + 说明）。

## 6. 硬约束（本轮守住的）

- `MetricsDashboardPanel` **一份实现，两侧传 scope**（不得复制）；
- 不得引入「同一指标两处渲染」；
- 颜色走 `useThemePalette()`（禁止硬编码，深浅主题都要过）；
- 用户可见文案禁 Markdown `**`。

## 8. 验收判据（给用户过目）

1. 有预警规则被命中 ⇒ **秒级**（不再等 10 分钟）发站内通知，且同日不重复。
2. 顶栏铃铛未读数 = 后端全量未读数（未读 50 条时显示 50，不再恒 20）。
3. 通知下拉支持「全部/未读」过滤；点击通知**跳到来源页**（LLM 预警 → 大模型网关页）。
4. 双洞察页：内容线层级分明、商品线不再空洞，深浅主题都正常，无「同一指标两处」。
5. `pytest`（预警自动触发 / 通知端点 / 页面守卫）+ `tsc` + `npm test` + `build` 全绿。
