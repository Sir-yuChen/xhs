# 电商 AI 商品图生成：市场成熟方案调研与对标

> **产出背景**：2026-10-03 用户口径「另外你调研一下这个思路方案，目前市场是否有成熟的方案可借鉴学习」。
> **调研对象**：本项目「生成AI商品图」（商品列表 → 操作列 → 独立弹窗 → 按主图/详情图分组生成）。
> **结论**：用户思路与市场主流方案**同向**，且本项目的方向选择（按组生成、多参考图、两段式提示词）
> 与头部产品一致；有 **4 处可直接借鉴的差距**（见 §5）。
> **性质**：只读调研（市场公开资料），不改代码、不引入依赖。所有结论标注来源。

---

## 1. 一句话结论

**「一次上传商品图 → 按固定图位分类（白底主图 / 场景图 / 卖点图 / 尺寸图）批量出整套」**
是当前电商 AI 出图的**行业标准范式**；本项目的「主图 / 详情图**分两大块**」正踩在这个范式上 ——
用户的直觉与行业收敛方向一致。

## 2. 市场主流方案（按成熟度分层）

### 2.1 第一层：Listing 套装生成器（最成熟，与我们的场景最像）

| 产品 | 核心做法 | 可借鉴点 |
|---|---|---|
| **Pixii**（pixii.ai） | 上传商品图 → 一次出「主图 / 场景图 / 信息图 / A+ 模块」；12+ 模型**按任务路由**；`Spot Edit` 框选局部重生成 | **按图位分类**输出；**按任务选模型**（不是一把梭） |
| **GreenOnion** | 一张图 → 9 张套图，**每张回答一个买家问题**；~60 秒；可**单张重做** | **「每张图有明确职责」**；支持单张重生成 |
| **Shotmora** | 1~3 张实拍 → **成组的、可评审的** listing 图集（主图/场景/信息图/对比/尺寸/A+） | **1~3 张参考图**；产出是「一套」而非「一张」 |
| **BeePOP / DeepKolor / Filtrix** | 单 SKU 照片 → 整套（含头条图 / 卖点图 / 场景图）；DeepKolor **按平台画布尺寸**逐模块生成 + 附裁切说明 | **按目标画布尺寸生成**（970px / 1464px / 1464×625） |
| **Clicco.ai** | 一张图 → listing 图文 + 短视频 | 图 + 视频同源 |

**共同结构**（四家高度一致，说明已收敛）：

```
1~3 张真实商品图（参考图）
      ↓
【先规划 image plan】← 按品类决定要哪几种图位
      ↓
逐图位生成（白底主图 / 场景图 / 卖点图 / 对比图 / 尺寸图 / A+ 模块）
      ↓
人工抽检 → 单张可重做 → 导出
```

⚠️ **关键洞察**：它们都是**「先规划图位，再逐图位生成」**，而不是「一句 prompt 出 N 张」。
这正是我们 v2.20 改成「**按组各发各的请求**」的同一个道理 —— **分组是生成前就定的事实**。

### 2.2 第二层：模型能力（决定我们能走多远）

| 模型 | 多参考图能力 | 一致性 | 对项目的意义 |
|---|---|---|---|
| **Nano Banana Pro**（Gemini 3） | **最多 8~14 张**参考融合 | 5 个角色 / 14 个物件一致性；**文字渲染强** | 当前**最强**的参考图融合；适合「多张详情图当参考」 |
| **Seedream 4.0 / 5.0**（字节） | 多图输入多图输出，**十余张参考** | 行业领先主体一致性 | 国内可直连；文档明确支持**多图输出** |
| Gemini 2.5 Flash Image | 多参考 | 迭代编辑连贯 | 性价比路线 |

**模型侧结论**：**多参考图是已具备的能力**（不是我们要自己拼的）。这直接支撑本项目
「勾选多张主图/详情图当参考」的做法 —— 但要注意**每个服务商上限不同**（本项目已按
`MAX_DETAIL_IMAGE_REFERENCES = 5` 自设上限，映射到上游的 8/14 仍有余量）。

### 2.3 第三层：工作流 SOP（Nano Banana Pro 官方电商批量工作流）

来源：`nanobanana-pro.vip` 电商产品图批量出图工作流。其推荐顺序**值得直接抄**：

```
① 白底主图（解决「合规」）
      ↓ 用白底图作参考
② 生活方式场景图（解决「想象」）
      ↓
③ 详情页素材：尺寸参照 / 功能特写 / 套装组合（解决「看得懂」）
```

⚠️ **它强调的一点我们还没做**：**「前一步的成片可作为后一步的参考图，减少产品形态漂移」**。
即**链式参考**（白底图 → 场景图 → 详情图），而不是所有图都从原始商品图出发。
它还给了具体的**防漂移提示词约束**：「保留真实折射与高光，避免塑胶感」「禁止改变产品形状」，
并实测「白底图**通过率明显高于**无结构 prompt」。

## 3. 与我们当前实现的对照

| 维度 | 市场主流 | 本项目（v2.20） | 判断 |
|---|---|---|---|
| 输入 | 1~3 张真实商品图 | 商品主图 + 原商品详情图，多选（≤5） | ✅ 一致，甚至更宽 |
| 分组 | 按**图位**分类（主图/场景/卖点/尺寸/A+） | 按**参考图来源**分两大块（主图组 / 详情图组） | ⚠️ **维度不同**，见 §5-① |
| 生成方式 | 逐图位生成 | **按组各发各的请求**（每组 count 张） | ✅ 同向 |
| 张数 | 每类 1 张为主，「9 张套图」 | 每组 3~10 张 | ✅ 更灵活 |
| 提示词 | 结构化模板（含防漂移约束句） | **两段式**：文本模型整理商品信息 → 出图 | ✅ 更先进（多数产品是固定模板） |
| 结果管理 | 单张重做、抽检 20% | 按组展示 + 成功后落素材库 | ⚠️ 缺**单张重做**，见 §5-② |
| 一致性 | 固定光影描述 / 场景家族 / 后缀句 | 同一 prompt，无显式一致性约束 | ⚠️ 缺**一致性锁**，见 §5-③ |
| 链式参考 | 白底图 → 场景图 → 详情图 | 全部从原始商品图出发 | ⚠️ 可借鉴，见 §5-④ |

## 4. 用户思路的验证

用户提出的三条，**在市场上都能找到对应且更成熟的做法**：

| 用户口径 | 市场对应 | 结论 |
|---|---|---|
| 「主图/详情图**分两大块**不要混搭」 | Pixii / GreenOnion 的**图位分类** | ✅ **同向**（我们按来源分，它们按用途分，本质都是「别混成一个池子」） |
| 「生成多少张图片」 | GreenOnion「9 张套图」、BeePOP「整套」 | ✅ 同向（都是**成组产出**而非单张抽卡） |
| 「把商品名/参数/参考图/要求全部整理扔给大模型」 | DeepKolor「规划完整页面 → 逐模块生成」、Nano Banana「结构化模板」 | ✅ **我们的两段式更彻底**（用模型动态整理，而非固定模板） |

## 5. 可直接借鉴的 4 处差距（建议优先级排序）

### ① 分组维度：从「参考图来源」升级为「图位用途」【建议下一轮】

- **现状**：分两组 = 按**参考图来源**（主图 / 详情图）。
- **市场**：分 N 类 = 按**图的用途**（白底主图 / 场景图 / 卖点图 / 尺寸图 / 对比图 / A+）。
- **为什么值得改**：用户真正要的是「一套能上架的详情页」，用途分类直接产出**可用的组图**；
  来源分类只解决「用哪张参考图」。两者不冲突 —— **来源是输入，用途是输出**。
- **落地方式**：`groups` 从 2 个来源键扩为 N 个用途键，每个用途带**自己的提示词后缀**
  （如「白底/纯背景」「场景/真实使用环境」「卖点/信息图」）。改动集中在常量表 + 前端渲染。

### ② 单张重做【低成本，建议同批做】

- **现状**：一组里某张不满意 → 只能整组重新生成（浪费已成功的）。
- **市场**：Pixii `Spot Edit`、GreenOnion「redo individual images」。
- **落地方式**：端点加 `regenerate_asset_id`（或 `group` + `group_index`），只重跑该张。
  **成本极低**（复用同一实现，只换个循环范围），收益直接。

### ③ 一致性锁（防风格漂移）【低成本，建议同批做】

- **市场做法**：固定「同一套光影描述 / 同一套场景家族 / 固定后缀句」，例如
  「左側 45° 柔光、右侧补光板」「大理石檯面 + 木色柜体」。
- **落地方式**：在 `detail_image_prompt.build_item_brief` 的出图要求里加**固定约束句**
  （已有「画面干净、光线自然」雏形），并在同一组内**复用同一句**（保证组内一致）。

### ④ 链式参考【较大改动，可评估】

- **市场做法**：白底图 → 场景图 → 详情图，逐级作参考，减少形态漂移。
- **本项目现状**：全部从原始商品图出发（**没有漂移累积**，但也少了一层「先定形态」）。
- **取舍**：链式能提高套图**协调性**，但**串行依赖**会让单张失败传导（且更难并行）。
  ⚠️ 本项目「按组并行」的现状反而对**失败隔离**更友好 —— 建议**先做 ①②③，④ 留观察**。

## 6. 平台侧规范（小红书）

调研到的小红书图片规范要点（对本项目有约束）：

- 推荐尺寸 **1080 × 1920**（3:4 竖版优先）；分辨率不足会**被压缩模糊**。
- 封面 = 小红书最重要的图位（决定点击率），资讯类「红墨」等工具会**先生成大纲、再逐页出图**。
- 有工具（红墨，基于 Nano Banana Pro）做「输入主题 → 整套笔记图文一次出齐」，
  其中「**先出大纲再逐页出图**」与我们 §5-① 的「先规划图位再逐图位生成」**完全同构**。

⚠️ **对项目的直接建议**：出图**目标尺寸**应显式对齐平台（竖版 3:4 / 1080×1920），
而不是交给上游默认（多数默认方图 1:1）—— 这与 DeepKolor「按平台画布尺寸逐模块生成」同理。

## 7. 建议的下一步（按性价比排序）

| 优先级 | 事项 | 成本 | 收益 |
|---|---|---|---|
| P0 | **单张重做** | 低（复用现有循环） | 高（省下整组重跑） |
| P0 | **一致性锁**（固定光影/后缀句） | 低（改提示词常量） | 高（组内不漂移） |
| P1 | **目标尺寸对齐平台**（3:4 / 1080×1920） | 中（需确认上游参数支持） | 中高（避免压缩模糊） |
| P1 | **分组维度升级为图位用途** | 中（常量表 + 前端 + 提示词分档） | 高（产出直接可用） |
| P2 | 链式参考（白底→场景→详情） | 高（串行依赖 + 失败传导） | 中 |
