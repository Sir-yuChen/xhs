# 45 · 通用规范 · 平台优先，本地跟随（所有平台写操作适用）

> 定型：2026-10-18（用户口径）
>
> > 「先操作平台数据再检查本地是否存在对应数据，存在则执行操作，不存在则跳过，
> >  所有平台操作均可以使用这种方式」
>
> 本文是从「删除关联内容」（设计 44）里提炼出的**通用流程**，后续所有
> 「打平台 + 动本地」的链路一律照此实现。

---

## 1. 标准流程（四步，顺序不可换）

```
① 打平台 ──失败──▶ 本地一律不动，回执 failed + 平台原文
   │
   成功
   ▼
② 核对本地：这条数据本地有吗？
   │
   ├─ 有 ──▶ ③ 执行本地操作（删除时须清从属行）
   │          成功 ⇒ deleted / 失败 ⇒ 如实回报（平台已改的事实不改）
   │
   └─ 没有 ─▶ ④ 跳过 ⇒ platform_only（**不是失败**）
```

## 2. 三条必须的理由

| 判据 | 为什么这么定 |
|---|---|
| **平台先行** | 反过来先动本地，平台一失败两边就对不上（平台有、本地没了），且本地数据补不回来 |
| **平台失败 ⇒ 本地不动** | 同上。宁可留一条待重试的记录，也不要造出「本地已删、平台还在」的假象 |
| **本地没有 ⇒ 跳过，不算失败** | **本地是缓存，不是平台镜像**。用户可能从没同步过这条数据。把「本地没有」当失败会让「删 10 条 → 7 条报错」看起来像平台坏了 |

## 3. 回执契约（四态）

| status | 触发条件 | 语义 |
|---|---|---|
| `deleted` | 平台成功 + 本地有 + 本地操作成功 | 两边都处理了 |
| `platform_only` | 平台成功 + 本地没有 | 只动了平台，本地跳过 |
| `failed` | 平台失败 | 本地未动 |
| `skipped` | 该类型没有可处理实体（如店铺/账号/直播间） | 未做任何操作 |

⚠️ **四态分别计数**。合并成一个 `deleted` 会让用户看不出「哪几条其实没动」。
⚠️ 前端汇总文案同理：`platform_only` 要单独说「仅动平台（本地无数据，已跳过）」。

## 4. 实现清单（照抄不跑偏）

1. **服务层一个函数管顺序**（路由只做鉴权 + 调服务 + 错误映射），不要在路由里拼顺序。
2. **平台调用与本地操作分两个内部函数**，便于单测打桩（`_delete_platform_x` / `purge_local_x`）。
3. **本地删除要清从属行**：先查外键引用（`grep 'ForeignKey("<表名>.id")'`），
   把引用它的表按「本地实体真删 ⇒ 从属数据跟着走」一并清理，再删本体。
   > 实例：`shop_products` 有 **4 张**引用表（`generation_records` /
   > `topic_goods_match` / `shop_metric_snapshots` / `order_items`），
   > 只清关系行必撞 `FOREIGN KEY constraint failed`。
4. **本地记录可能不存在**：本地查不到也必须**先进平台**，
   并且要有办法拿到平台令牌（必要时让请求显式带 `platform_account_id`），
   还要做归属校验（不许拿别人的账号当令牌）。
5. **去重**：同一条传两次不该打两次平台。

## 4.1 通道兜底：一个平台动作有多条通道时

同一个平台动作可能有多条**令牌通道**（例：删笔记的「创作者通道」与「千帆通道」）。
用户口径（2026-10-18）：

> 「商业笔记和普通笔记均调用一次，先走普通再走千帆，如果其中一个成功则不再走其它的」

规则：

1. **按正路先走一条**（普通笔记 = 创作者；商业笔记 = 千帆）；
2. 失败（含**令牌存在但已过期**）⇒ 换另一条**再试一次**；
3. **任一成功即止**，不许两条都调（同一条数据删两次 = 不可逆风险 + 误报失败）；
4. 两条都失败 ⇒ **两边原文都带出来**（只报最后一条会让用户看不出真正原因）。

⚠️ **「有令牌」不等于「令牌可用」**：账号 8 实测创作者令牌存在、接口却回
「登录已过期，请重新登录」，而千帆 ark 正常。按「有令牌就只走那条」会把能做的操作判失败。

## 4.2 删除前先查存在性（平台不校验，我方必须查）

平台删除接口**不做存在性校验**：实测同一商品连删 3 次，每次回 `success:true`。
⇒ 删除前必须按 ID 查一次详情，查不到就**不调删除接口**：

| 平台 | 本地 | 动作 |
|---|---|---|
| 有 | 有/无 | 删平台 → 核对本地 |
| 无 | 有 | 只清本地（不调平台） |
| 无 | 无 | 回执 `absent`「数据已经被删除，不要重复删除」，批量里跳过该条 |

⚠️ **查询失败 ≠ 不存在**：查询接口报错（网络/令牌）时放行，由删除步骤报真实原因。
⚠️ 查询一律**按 ID**（`get_skus_by_item_ids` / `get_goods_note_page(note_ids=…)`），不翻页。

## 5. 不适用范围

- **纯平台写**：上下架 / 改价 / 发货 / 冻结等，本地没有对应实体 ⇒ 平台成功即可，
  没有「核对本地」这一步。
- **只删本地**（如 `delete_platform=False`）：不碰平台，报「本地无此记录」是对的。
