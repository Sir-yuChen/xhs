# 零、全局约定

## 0.1 认证

除登录/注册外，**所有端点**都要求 `Authorization: Bearer <access_token>`。
缺失或过期 ⇒ `401`。

## 0.2 错误响应（系统域统一形状）

```json
{
  "detail": {
    "code": "PERMISSION_DENIED",
    "message": "缺少权限：system:user:edit",
    "required": "system:user:edit"
  }
}
```

**判据（前端据此分流）**

| `detail` 形态 | 来源 | 前端行为 |
|---|---|---|
| `{"code","message"}` | **系统域（46–53）新增** | 按 `code` 分流：字段级 red / 全局 message / 跳转 |
| `"纯字符串"` | **既有业务域**（历史风格） | 兜底：原样 `message.error(detail)` |

> ⚠️ 系统域**必须**用结构化形态。既有业务域**本轮不改**（改 251 个端点的错误形状 = 前端全炸）。

## 0.3 401 与 403 的分界（关键）

| 场景 | 码 | 理由 |
|---|---|---|
| 没登录 / 令牌过期 / 令牌被撤销 | **401** | 前端拦截器据此跳登录 |
| 登录了但没权限码 | **403** | 前端显示「无权限」，**不跳登录** |
| 账号 `pending` / `disabled` | **403** | 不是密码错（见 §1.1） |

## 0.4 分页

```
?page=1&page_size=20      # page 从 1 起；page_size ∈ [1,100]，默认 20
```
响应：
```json
{"items": [...], "total": 137, "page": 1, "page_size": 20}
```
> `total` 是**过滤后总数**，不是全表数。前端分页器用 `total`。

## 0.5 时间

所有时间字段：**ISO 8601 带时区**，例 `"2026-10-23T21:30:00+08:00"`。空值 ⇒ `null`（不写 `""`）。

# 一、认证域（`api/auth.py`）

## 1.1 `POST /api/auth/login`（改造）

**权限码**：无

**请求体**
| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `username` | string | ✅ | 登录用**用户名**（不是邮箱） |
| `password` | string | ✅ | min 1 |

**成功响应 200**
```json
{
  "access_token": "eyJ...",
  "refresh_token": "eyJ...",
  "token_type": "bearer",
  "user": {"id": 1, "username": "admin", "role": "admin"}
}
```

**错误码（新增三条）**
| HTTP | code | 触发条件 | 前端行为 |
|---|---|---|---|
| 400 | `USER_NOT_FOUND` | 用户名密码错 **或** 用户已软删（`deleted_at` 非空） | 提示「用户名或密码错误」 |
| **403** | **`USER_PENDING`** | `status='pending'`（注册待审） | 提示「账号待管理员审核」，**不跳登录** |
| **403** | **`USER_DISABLED`** | `status='disabled'` | 提示「账号已停用，请联系管理员」 |
| 429 | `LOGIN_LOCKED` | 5 次失败 || 提示「稍后再试」+ 剩余秒数 |

**⚠️ 为什么 `pending` 不能用 401**：401 会让前端拦截器判定「令牌失效」→ 清本地令牌 → 跳登录页 → 用户再登又 401 → **死循环**（项目踩过同类：DEF-075）。

**副作用**：成功 ⇒ 写 `last_login_at` / `last_login_ip`。

## 1.2 `POST /api/auth/send-register-code`（新增）

**权限码**：无 · **前置开关**：`register.enabled = true`（`system_settings`，per-user）

**请求体**
| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `email` | string | ✅ | 邮箱格式 |

**响应 200**
```json
{"sent": true, "expires_in": 300, "resend_after": 60}
```

**错误码**
| HTTP | code | 条件 |
|---|---|---|
| 403 | `REGISTER_DISABLED` | 注册开关关闭 |
| 409 | `EMAIL_TAKEN` | 邮箱已注册（含软删用户） |
| 429 | `CODE_SENT_TOO_SOON` | 60 秒内重复请求（`retry_after` 秒数在 message） |
| 502 | `MAIL_SEND_FAILED` | SMTP 失败（附平台原话） |

**实现要点**
- 6 位数字，5 分钟有效，**一次性**（用后即毁）
- 60 秒限频按 `(email)` 维度
- 存 `system_settings`? **否** —— 存进程内 dict（`{email: (code, expire_at)}`），重启即失效可接受
- SMTP 用标准库 `smtplib`，不引新依赖

## 1.7 `POST /api/auth/change-password`（新增）

**请求体**
| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `old_password` | string | ✅ | 必须与当前一致 |
| `new_password` | string | ✅ | ≥6，且 ≠ old |

**响应 200**：`{"ok": true, "message": "密码已修改，请重新登录"}`

**错误码**：`400 OLD_PASSWORD_WRONG` / `422 PASSWORD_TOO_WEAK`

**副作用（三件，缺一不可）**
1. 更新 `password_hash`
2. `token_version += 1`（**所有旧令牌立即失效**）
3. `must_change_password = 0`（首登强制改密的闸被解除）

> **为什么要 `token_version+1`**：无状态 JWT 唯一的撤销手段。不加 = 改密后旧令牌还能用。

## 1.8 `GET /api/auth/me`（改造 —— **本次最关键的响应形状**）

**权限码**：无（需登录）

**响应 200**
```json
{
  "id": 1,
  "username": "admin",
  "role": "admin",
  "status": "normal",
  "real_name": "管理员",
  "email": "admin@example.com",
  "phone": "",
  "avatar": "",
  "must_change_password": false,
  "last_login_at": "2026-10-23T21:30:00+08:00",
  "deleted_at": null,
  "permissions": ["system:user:view", "system:user:create", "..."],
  "workspaces": [
    {"key": "system", "name": "系统管理", "icon": "SettingOutlined", "sort_order": 10},
    {"key": "xhs",    "name": "小红书",   "icon": "RedditOutlined",  "sort_order": 20}
  ],
  "menus": {
    "system": [
      {
        "id": 101, "parent_id": 0, "name": "系统管理", "menu_type": "M",
        "path": "", "icon": "SettingOutlined", "perms": null,
        "sort_order": 10, "visible": true, "status": "normal",
        "children": [
          {
            "id": 102, "parent_id": 101, "name": "用户管理", "menu_type": "C",
            "path": "/system/users", "icon": "UserOutlined", "perms": "system:user:view",
            "sort_order": 1, "visible": true, "status": "normal",
            "children": [
              {"id": 103, "parent_id": 102, "name": "新建用户", "menu_type": "F",
               "path": "", "perms": "system:user:create", "children": []}
            ]
          }
        ]
      }
    ],
    "xhs": [...]
  }
}
```

**字段契约（前端必须按此写）**

| 字段 | 类型 | 说明 | 空值口径 |
|---|---|---|---|
| `permissions` | `string[]` | **去重 + 排序**的权限码全集（admin = 全部 161 条） | 空数组 `[]`（不是 `null`） |
| `workspaces` | `object[]` | 该用户**至少有一条可见菜单**的工作区 | 空数组 |
| `menus` | `Record<string, TreeNode[]>` | key = workspace，value = 该工作区的**树**（已裁剪） | 无权限的工作区**不出现这个 key** |
| 节点 `menu_type` | `"M"\|"C"\|"F"` | M 目录 / C 页 / F 按钮 | — |
| 节点 `perms` | `string\|null` | C 行是 view 码，F 行是动作码，M 行是 `null` | `null` |
| 节点 `path` | `string` | 只有 C 行有值；M/F 是 `""` | `""` |
| `must_change_password` | `bool` | true ⇒ 前端**必须**拦截到改密页 | — |

**三层过滤（后端唯一实现 `menu_seed_service.build_user_menus`）**
1. 只取 `status='normal'`
2. 只保留 `perms ∈ user_perms`（admin 全部）
3. **祖先链裁剪**：父不可见 ⇒ 子一并丢弃

> ⚠️ **`permissions` 与 `menus` 必须一致**：能让前端 `hasPermission('x:y')` 为 true 的码，
> 一定能在 `menus` 里找到对应的 F/C 行。不一致 = 用户看得见按钮但菜单里没这页（或反之）。

# 二、用户管理（`api/system/users.py`）—— 9 端点

## 2.1 `GET /api/system/users`

**权限码**：`system:user:view`

**Query**
| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `page` / `page_size` | int | 1 / 20 | 见 §0.4 |
| `username` | string | — | 模糊（`func.lower().like`） |
| `email` | string | — | 模糊 |
| `status` | enum | — | `normal` / `pending` / `disabled` |
| `role` | string | — | 角色 code 精确 |
| `include_deleted` | bool | false | true ⇒ 含软删行 |

**响应 200**
```json
{
  "items": [{
    "id": 2, "username": "alice", "real_name": "张三",
    "email": "a@x.com", "phone": "138****2857",
    "role": "user", "role_name": "普通用户",
    "status": "normal",
    "online": true,
    "must_change_password": false,
    "last_login_at": "2026-10-23T10:00:00+08:00",
    "last_login_ip": "10.0.0.5",
    "created_at": "2026-10-01T09:00:00+08:00",
    "deleted_at": null
  }],
  "total": 26, "page": 1, "page_size": 20
}
```

**派生字段判据**
| 字段 | 判据 |
|---|---|
| `online` | **见下方说明 —— 不能用 `login_sessions` 判** |
| `role_name` | join `roles.name`；角色不存在 ⇒ 回落 `role` 原值（不造假） |
| `phone` | **脱敏**：`138****2857`（列表接口一律脱敏，详情才给全） |

**错误码**：`403 PERMISSION_DENIED`

### ⚠️ `online` 字段的正确实现（实测修正）

**踩坑记录**：设计初稿写「查 `login_sessions` 是否存在未过期行」——**实测读模型后推翻**。
`login_sessions` 是**小红书账号的登录会话表**（字段 `platform` / `sub_type` / `qr_id` / `qr_url` /
`encrypted_temp_cookies`），记录的是「绑定小红书账号时扫的那个码」，**不是系统用户的登录态**。

**正确判据（两选一，本项目取 A）**

| 方案 | 实现 | 代价 | 判定 |
|---|---|---|---|
| **A · 按 `token_version` 近似** | 后端在**内存**记 `{user_id: (token_version, last_seen_at)}`，每次请求更新 `last_seen_at`；`online = last_seen_at 在 5 分钟内` | 进程内，多副本不准（单副本部署下够用，见 52 §三） | ✅ **采用** |
| B · 新增 `user_sessions` 表 | 每次登录落一行，登出/改密删 | +1 表 + 每次请求一次写（高频写点是负担） | ❌ 本期不做 |

**如实标注**：方案 A 的 `online` 是**近似值**，判据是「5 分钟内有过请求」。
一个挂了页面不动的人会显示离线 —— 这不是缺陷，是**判据本身的边界**，前端 tooltip 写明
「5 分钟内是否有活动」。

| 409 | `ROLE_SYSTEM_PROTECTED` | `is_system=true` 且改 `status` 或 `code` |
| 422 | `FIELD_IMMUTABLE` | 传了 `code` |

> **`is_system` 能改什么**：`name` / `description` / `sort_order` **可改**；
> `code` **禁改**、`status` **禁改**（内置角色不能停用，否则该角色下所有用户失去权限来源）。
> ⚠️ dataPanel 的 `UpdateRole` **漏了这个拦截**（实测发现），XHS 必须补上。

**副作用**：改 `name` 不影响权限，**不清缓存**（避免无谓踢人）。

## 4.3 `POST /api/system/menus`

**权限码**：`system:menu:create`

**请求体**
| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `parent_id` | int | | 默认 0（顶级） |
| `name` | string | ✅ | ≤64 |
| `menu_type` | enum | ✅ | `M` / `C` / `F` |
| `perms` | string | 视类型 | C/F **必填**且全局唯一；M **必须为空** |
| `path` | string | 视类型 | C 必填且全局唯一；M/F **必须为空** |
| `component` | string | | 预留 |
| `icon` | string | | ≤64 |
| `workspace` | string | 视类型 | C 且 `parent_id=0` 时必填 |
| `sort_order` | int | | 默认 0 |
| `visible` | bool | | 默认 true |
| `status` | enum | | 默认 `normal` |

**校验链（顺序不可换，先报先错）**
1. `menu_type='F'` ⇒ `parent` 必须存在且 `parent.menu_type='C'`，否则 `422 F_MUST_UNDER_C`
2. `menu_type='M'` ⇒ `path`/`perms` 必须为空，否则 `422 M_HAS_PATH_OR_PERMS`
3. `perms` 非空 ⇒ 格式 `^[a-z][a-z0-9_]*:[a-zA-Z][a-zA-Z0-9]*(:[a-zA-Z][a-zA-Z0-9]*)?$`，否则 `422 PERMS_FORMAT`
4. `perms` 非空 ⇒ 全局唯一，否则 `409 PERMS_DUPLICATED`
5. `path` 非空 ⇒ 全局唯一，否则 `409 PATH_DUPLICATED`
6. `menu_type='C'` 且 `parent_id=0` ⇒ `workspace` 必填，否则 `422 WORKSPACE_REQUIRED`

**响应 201**：同 §4.1 节点形状

---

## 4.4 `PUT /api/system/menus/{menu_id}`

**权限码**：`system:menu:edit`

**请求体**（可选）：`name` / `perms` / `path` / `icon` / `sort_order` / `visible` / **`status`** / `workspace`

**错误码**：同 §4.3 的校验链 + `404 MENU_NOT_FOUND`

### ⚠️ `status` 变更的语义（抖音/闲鱼接入开关）

```
停用一条 C 行 ⇒ 该页从所有人的侧栏消失 + 直敲 URL 得 403
停用一条 M 行 ⇒ 其下所有 C 行一并不可见（祖先链裁剪）
```

**两条硬约束**
1. **不静默级联**：停 C 行**不改**其 F 子行的 `status`（重新启用父级即全部恢复）
2. **只清缓存不踢人**：调 `permission_cache.invalidate_workspace(ws)`，**不碰 `token_version`**

> **为什么不踢**：菜单启停是**全站低频**操作（当前用途就是「接入抖音/闲鱼时打开那批菜单」）。
> 若 `token_version+1`，全站用户会在那一刻**莫名掉线**。而它只改变「看得见什么」，
> 不改变「能做什么」—— 清缓存足够。

**响应**：`{"id": 108, "status": "disabled", "affected_users": 26, "kicked_users": 0}`

---

## 4.5 `DELETE /api/system/menus/{menu_id}`

**权限码**：`system:menu:delete`

**Query**：`confirm_name`（**必填**，必须等于该菜单 `name`）

**错误码**
| HTTP | code | 条件 |
|---|---|---|
| 422 | `CONFIRM_NAME_MISMATCH` | `confirm_name` 不符 |
| 409 | `MENU_HAS_CHILDREN` | 有子节点（**不级联删**） |
| 409 | `MENU_IN_USE` | 被 `role_menus` 引用（**不静默收权**），message 带角色名 |

> **为什么删除要输名字**：误删一个 C 行 = 一整页连带它的所有 F 行消失，
> 而 `role_menus` 里那些授权行会被 FK RESTRICT 挡住（删不掉）或 CASCADE 静默清掉（权限悄悄变）。
> 输名字是**最后一道人肉确认**（与图片空间「彻底删除」同款）。
