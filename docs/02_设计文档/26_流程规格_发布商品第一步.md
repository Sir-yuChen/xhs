# 商品配置第一步 · 实现规格（用户口径 2026-10-08）

> 页面：千帆「商品创建」`/app-item/good/create` 首个页面。
> 实测证据见 `26_实测证据_发布商品第一步.md`（CDP 驱动真实 Chrome 操作所得）。

## 一、页面布局（一比一复刻）

按**渐进式**渲染（实测：没主图时页面上只有「商品图片」一个区块）：

| 区块 | 出现条件 | 内容 |
|---|---|---|
| **商品图片** \* | 始终 | 主图槽位（有图显示缩略图 + 「主图N」角标）+「上传图片」空槽；两行说明文案 |
| **商品标题** \* | 有主图 | 输入框（`maxlength=60`，占位「系统已自动在商品标题前拼接品牌名称，请勿重复填写品牌名称。」，计数 `n/60`）+ 右侧「**智能生成**」 |
| **智能推荐行** | 平台给了建议 | `智能推荐` tag + 建议文本 + **✓ 立即使用** |
| **商品类目** \* | 有主图 | 无标题 → 提示「上传图片并完成标题后为您智能识别类目」；有标题 → 「已选类目 A > B > C > D」+ 智能推荐 chip 行 + 类目列表；下方搜索框「请输入商品名称关键词搜索，如：帽子、面霜」 |
| 底部 | 始终 | 「**信息已确认，下一步**」 |

## 二、与千帆的**唯一**差异（用户口径）

| 项 | 千帆 | 本项目 |
|---|---|---|
| 选图 | 弹「选择图片」抽屉（图片空间） | **不弹** —— 选本地文件后**静默上传**，直接预览 |
| 文件名 | 原名 | **内容 MD5**（`md5(content) + ext`），同图恒同名、天然去重 |

## 三、交互链路（实测同序）

```
1. 选本地主图 → 静默上传（MD5 命名）→ 拿链接 → 预览
2. 平台自动出标题建议
3. 点「立即使用」 → 标题落框 → **立刻自动识别类目**
4. 点「智能生成」可换新标题 → 再点「立即使用」
5. 类目区支持关键词搜索
```

## 四、后端契约（实测）

| 用途 | 端点 / action | 备注 |
|---|---|---|
| 上传图片空间 | `POST /picture-space/upload` | 三步：permit → PUT ROS → 登记；文件名留空 ⇒ 后端按内容 MD5 |
| 类目搜索 | `POST /api/edith/product/search_category` | `{keyword}`，**无需签名**，只回 `isLeaf` |
| 标题+类目预检 | `publish_async` → `itemAuditPreCheck` | `{name, categoryPath[{level, categoryId}]}` |
| 属性/品牌联动 | `getProductPropertyConfig` / `getPropertyGroups` / `getRecommendBrand` | 同一次交互被唤起 |

⚠️ `publish_async` 的 `data` 是**字符串化 JSON**（要 dump 一次）。
⚠️ `search_category` **没有 `path` 字段**，只有 `fatherId` + `level`；
想要「一级 > … > 四级」的完整链路，必须**按 `fatherId` 逐级上溯**（平台自己不给完整路径）。

## 五、缺值口径

- 类目识别失败 ⇒ **不造假**：退回空列表，用户仍可手动搜。
- 读不到图片内容 ⇒ 退回原名（不让流程断），后端 MD5 分支兜底。
