# 68 · 设计 · 配置项三级归属规则（**新增配置必须遵守**）

> 2026-10-25 用户验收通过（「验收通过，你总结一下，记录规则，后续配置相关的参数按照三级区分」）。
> 本文是**配置项归属的唯一判据来源**；代码里 `SETTING_SCOPES` 是它的实现。
> 守卫 `tests/backend/test_settings_placement.py`（9 条）把它钉成会红的断言。

## §1 一句话判据

**问一句：「换一个平台（抖音 / 闲鱼），这个值还要不要另配一份？」**

| 答案 | 归属 |
|---|---|
| 要另配一份 | **工作区级**（workspace） |
| 照用，全站一个值 | **系统级**（system） |
| 每人各一份（跟"你这个人"绑） | **个人级**（user） |

⚠️ 判据是**语义**，不是「现在有几个平台」。只有小红书一个平台时，
工作区级的键**仍然是**工作区级 —— 否则接第二个平台时要回头改分类 + 迁数据。

## §2 三个级别的完整定义

| 级别 | 含义 | 入口 | 谁能改 | 存储 |
|---|---|---|---|---|
| **系统级** | 全站唯一事实，与任何平台无关 | 系统管理 → 配置管理（`/system/settings`） | admin | `user_id IS NULL ∧ workspace IS NULL` |
| **工作区级** | 某个业务工作区私有 | **侧栏「设置」**（`/settings`，挂在业务工作区下） | admin | `workspace = '<id>'`（如 `xhs`） |
| **个人级** | 本人私有，与工作区无关 | **头像下拉 →「个人配置」弹窗** | 本人 | `user_id = <id>` |

**生效优先级**：工作区级 > 个人级 > 系统级 > 内置默认

## §4 新增一个配置项的完整流程（照做，别跳步）

1. **定归属**：按 §1 判据决定，写进 `settings_service.SETTING_SCOPES`。
   漏登记 ⇒ 守卫 `test_settings_scope_map_covers_every_key` 红。
2. **加默认值**：`BUILTIN_DEFAULTS`（只在 `LIVE_KEYS` 里有读点的才加）。
3. **加分组与文案**：`_BUILTIN_CATEGORY` + `_BUILTIN_LABEL` +
   `config/initial_data/setting_descriptions.json`（说明 ≤20 字，只讲"这个开关做什么/改它会怎样"）。
4. **接运行时读点**：用 `live_int` / `live_bool` / `live_value`（**不要直接查库**）。
   工作区级的键由 `effective_value` 的 `workspace` 分支自动读到工作区行 —— 不用自己写查询。
5. **播种**：系统级走 `seed_system_settings`（已按归属过滤）；工作区级走
   `seed_workspace_settings(db, workspace)`；新接平台时在
   `seed_builtin_settings_from_initial_data` 里追加工作区 id。
6. **跑守卫**：`pytest tests/backend/test_settings_placement.py`。

## §5 四条踩过的坑（都是实测的，别重犯）

### ① 归属不能靠「库里哪一级有行」判断

早期实现按行位置分区，结果三种混乱同时出现：
- 同一键系统级 1 行 + 用户级 5 行 ⇒ **两个页面都列它**；
- `register.enabled` 系统级 1 + 用户级 2，读取还特判"以管理员行为准"；
- 三个工作区级键库里 **0 行** ⇒ 哪个页面都不显示，等于不可配置。

⇒ 归属由 `SETTING_SCOPES` **代码固定**，页面按清单分区。

### ② 内置键按清单过滤，**用户自建键不过滤**

严格过滤会让用户刚建的键**立刻从列表消失**（比混乱更糟）。

### ③ 改归属必须同时改读取路径，否则**静默失效**

5 个键从系统级改到工作区级后，`effective_value` 仍按「用户级 → 系统级」查行
⇒ 页面能改、业务用旧值、**零报错**。
⇒ `effective_value` 里按 `SETTING_SCOPES.get(key) == "workspace"` 先取工作区行。

### ④ 播种必须按归属过滤，否则每次启动重建孤儿行

`seed_system_settings` 原无条件给全部内置键种系统级行
⇒ 清掉 8 行孤儿行后重启又回来 8 行；`list_scoped_settings(scope="system")`
把它们列进系统配置页 —— 这就是"私有配置错位"的直接来源。

## §6 界面布局规则

| 规则 | 理由 |
|---|---|
| **标注 ≠ 归属正确** | 把工作区配置放系统管理页 + 标「只对小红书生效」被用户否掉 |
| 全局位置（顶栏/齿轮）不承载单一工作区配置 | 全局按钮点下去必须"猜"配哪个，猜错就是配错地方（实测显示「工作区配置 · system」） |
| 同一件事只留一份实现 | 个人配置曾在 `/settings` 页和头像弹窗各一份，内容完全相同 |
| `scope_hit` 报**归属**不报行位置 | 否则界面显示「来源：系统级」而实际只对小红书生效 |

## §7 数据层不变量

- 唯一约束三条 partial unique：`(key) WHERE user_id IS NULL AND workspace IS NULL`、
  `(user_id, key) WHERE user_id IS NOT NULL`、`(workspace, key) WHERE workspace IS NOT NULL`
- **系统级不该有工作区级键的行**（守卫 `test_system_seeding_skips_workspace_scoped_keys`）
- 列表接口给「归属本级但还没行」的内置键**合成虚拟行**（`id = -1`）⇒
  前端见 `id < 0` 必须走**新建**（POST），否则保存 404「配置项不存在」
- 「只补缺不覆盖」：播种永不重置用户改过的值
