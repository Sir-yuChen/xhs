# 功能设计 · 前端页面整合

> **版本**：v1.0（2026-10-04）
> **性质**：二开需求 · 纯前端整合（**零新端点、零新表、零迁移、后端零改动**）
> **发起**：用户口径「很多功能页面可以整合到一起，有些功能且是重复的，梳理并给方案」
> **前置文档**：本文由 `21` 编号登记，依据「文档先行」铁律，代码变更须由本文发起。

---

## 1. 一句话

把 XHS 工作区 19 个导航入口中「实质重复 / 孤儿 / 死代码」的页面整合收敛，复用「笔记工坊（§36）已验证的一页多 Tab + 旧路由重定向」范式，目标收敛到 **12 个入口**，删约 **900 行**重复/死代码，**后端与数据层零改动**。

### 2.2 结论分类

| 类别 | 项 | 判定 |
|---|---|---|
| **实质重复** | 竞品监控 ⊂ 监控中心 | benchmarks-page 只是 monitoring-page 的 `filter(note_url)` 视图；monitoring-page 是孤儿页（设计 04 §2.9 已确认「import 无 Route」） |

## 3. 整合方案（分四个切片，按依赖顺序）

### 切片 A · 竞品监控并入监控中心（收益最大、风险最低）

**目标**：删 `benchmarks-page.tsx`，把 `monitoring-page.tsx` 接线上路由，菜单「竞品监控」改名「监控中心」。

| 步骤 | 动作 | 文件 |
|---|---|---|
| A1 | 菜单项 `benchmarks` → `monitoring`（label 改「监控中心」，图标沿用 `AimOutlined`） | `app-shell.tsx` |
| A2 | 路由 `/platforms/xhs/benchmarks` → `/platforms/xhs/monitoring`，element 从 `XhsBenchmarksPage` 改 `XhsMonitoringPage`；删 `XhsBenchmarksPage` import | `router.tsx` |
| A3 | 删除 `benchmarks-page.tsx` | 删文件 |
| A4 | `monitoring-page.tsx` 默认目标类型 = `note_url`（保留竞品监控既有体验），四种类型同屏露出 | `monitoring-page.tsx` |
| A5 | 旧路由 `/platforms/xhs/benchmarks` 重定向到 `/platforms/xhs/monitoring`（深链/书签不死） | `router.tsx` |

**为什么删 benchmarks 而不是删 monitoring**：monitoring-page 功能是 benchmarks 的**超集**（4 种目标类型 vs 1 种），且已写完只是没接线；保留超集、删子集。

**测试锚点同步**（合并必带，否则回归红）：
- `test_page_optimizations.py` 的 `MESSAGE_FEEDBACK_PAGES` 元组：删 `benchmarks-page.tsx` 行（monitoring-page 行已存在）。
- `test_api.py` 若有 benchmarks 相关锚点（本轮已核：无）。
- 若存在竞品监控页面结构守卫，锚点从 benchmarks 文件改指 monitoring 文件。

**验收判据**：
- [ ] `/openapi.json` paths 数不变（零端点）
- [ ] 菜单「监控中心」可点、四类型可切、默认笔记 URL
- [ ] 旧 `/benchmarks` 深链重定向到 `/monitoring`
- [ ] `tsc --noEmit` 0 error
- [ ] `pytest tests/backend/test_page_optimizations.py tests/backend/test_api.py -q` 绿

### 切片 D · 模型配置（**已拍板：不合并，保持现状**）

**结论（2026-10-04 用户拍板）**：`/models` **不移动**。模型配置是**每个工作区内业务使用大模型的配置入口**，各工作区独立持有，不进大模型网关工作区。

**原方案（已否决）**：`/models` 从 XHS 侧栏底部移除，作为网关工作区第 4 个子页 `/llm-gateway/mappings`。

**否决理由**：模型配置是「工作区内业务点 → 服务商」的**独立入口**，与「网关服务商实体管理」是两层；跨工作区合并反而破坏「各工作区内独立配置」的边界。

## 5. 硬约束与纪律（沿用 AGENTS.md）

1. **零后端改动**：不碰 `backend/`，端点 / path / 表 / 迁移数字不得漂移。
2. **测试锚点必同步**：`test_api.py` / `test_page_optimizations.py` 直接 `open()` 页面文件做源码断言，合并/改名/删文件必连带改锚点，否则回归红。
3. **逐需求闭环**：每个切片独立做「实现 → tsc → 相关测试 → 文档回写」，不攒批。
4. **旧路由重定向**：所有被合并的路径一律 `Navigate` 重定向，深链/书签不死（沿用 §36 范式）。
5. **文档先行**：本文即发起文档；每切片完成后回写本文「验收判据」勾选 + 数字口径。
