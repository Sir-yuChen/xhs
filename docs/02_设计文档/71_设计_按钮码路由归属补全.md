# 71 · 按钮码路由归属补全（零路由码清零）

> 2026-10-26 用户口径：「你来决定全面细化执行步骤后再一个一个执行，保持历史原有业务逻辑」
>
> **本轮只改「路由挂哪个码」，不改任何业务逻辑、不改前端行为、不动数据。**

## 1. 问题是什么（实测，不是推测）

权限体系有四处真相源，本轮之前**从未对账过第四处**：

| # | 真相源 | 本轮前的状态 |
|---|---|---|
| ① | `core/perms_registry.py`（码定义） | 206 条：页面 33 / 按钮 173 |
| ② | `config/initial_data/menus.seed.json`（授权页能看到什么） | 217 行，码与①一一对应 |
| ③ | `core/route_perms.py`（`METHOD path → code` 登记） | 328 条（**曾有 10 个重复键静默覆盖**，已修） |
| ④ | **运行时的 `Depends(require_perm(...))`** | **279 条写路由里只有 25 条真的挂了** |

**「零路由码」= 授权页上能勾、后端永远不按它判权。** 它有两种成因，修法完全不同：

| 成因 | 例子 | 修法 |
|---|---|---|
| **A. 旧合并码仍顶着**（码拆出来了，路由没改挂） | `xhs:monitor:edit/delete/refresh` 三条零路由，四个动作全由 `xhs:monitor:create` 承担 | 把路由**改挂**到它自己的码上 |
| **B. 一个端点按参数分派多码** | `xhs:item:offShelf` / `delete`（`POST /items/operate` 的 `action`） | 登记白名单，不占路由 |
| **C. 前端判据，后端无端点** | `xhs:draft:*` 六个码（草稿工坊的前端动作） | 登记白名单并写清「无端点」 |

## 4. 硬约束（每一组都必须守）

1. **不改业务逻辑**：只改 `route_perms.py` 里 `"METHOD path": "code"` 的**值**。
   不动端点函数体、不动服务层、不动前端、不动数据库。
2. **不改前端可见性**：前端已经在按新码判权（上一轮已做），本轮只让后端追上。
3. **一码一动作**：每组改完，那一组的零路由数必须归零，且**不许新增**多条共用。
4. **每组配一条守卫**：直接断言 `ROUTE_PERMS["METHOD path"] == "新码"`，
   防以后有人改回去。
5. **每组跑一次回归**：`test_route_perms_integrity` + `test_button_level_perms` +
   `test_menu_permission_alignment` + `test_permission_code_only` 必须全绿。
6. **真机只做只读验证**：用普通用户调这些写端点确认 403 里 `perm` 指向新码；
   **不真触发平台写操作**（下架/删除/改价一律不点）。
