# 千帆发布商品 · 第二部分参数（真机实测 2026-10-08）

> 来源：**CDP 驱动真实 Chrome 走进第二页**并 dump DOM（`.hermes/tmp/evidence_publish/step2_survey.json`）
> + bundle（`itemark/8091.*.js`）逆出的校验文案。
> 第一部分（商品图片 / 标题 / 类目）见 `26_实测证据_发布商品第一步.md`。

## 一、进入方式（真机时序）

```
第一步：商品图片 → 标题（上传主图后自动出建议 → 「立即使用」）
       → 类目（采用标题后自动带出，走 getRecommendCategory）
       → 点「信息已确认，下一步」
第二步：进入商品主要参数配置（本页）
```

⚠️ 两步**同一路由** `/app-item/good/create`（SPA 分段切换），不跳新页。
⚠️ 进第二页后类目会**重新识别**成更贴切的一个（实测：第一步「梳妆台/桌」→ 第二步「**书桌**」），
   页面提供「**修改类目**」入口。

## 二、页面骨架

| 位置 | 内容 |
|---|---|
| 左侧锚点导航 | `类目信息` · `基础信息`（2 项必填）· `图文信息` · `价格库存`（1 项必填）· `服务信息` |
| 顶部 | 商品发布助手 · 发布提示(3) · 已选类目 + `修改类目` |
| 底部 | `保存草稿` · `提交商品` |

## 四、网络契约（第二部分用到的 action，全部需签名）

| action | 作用 |
|---|---|
| `getProductPropertyConfig` | 取该类目**属性配置**（`{categoryId}`） |
| `getPropertyGroups` | 取**规格分组**（`{variants[]}`） |
| `getRecommendBrand` | 按标题+主图**推荐品牌** |
| `predictProductProperty` | 类目+图+标题 → **属性预测** |
| `getLogisticsPlanHasAddress` | 物流模板 |
| `itemAuditPreCheck` | 标题+类目合法性预检（`{name, categoryPath[]}`） |

⚠️ 全经 `POST /api/edith/product/publish_async`，`data` 是**字符串化 JSON**，**需签名**。

## 六、实现口径

1. **按类目动态渲染**：属性项、规格类型、尺码表都不是恒有 —— 由 `getProductPropertyConfig` 决定。
2. **必填标记真实**：基础信息 2 项必填（品牌、标题）；价格库存 1 项必填（售价）。
3. **缺值口径**：取不到就留空，**不造假**（不填 0、不填「未知」）。
4. **分块**：与左锚点一致（基础信息 / 图文信息 / 价格库存 / 服务信息），每块一个外框。
5. **红线**：`提交商品` = 真实上架，后端发布成功后**立即下架**。
