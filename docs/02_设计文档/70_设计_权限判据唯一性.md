# 70 · 权限判据唯一性：全项目只按权限码授权

> 立文时间：2026-10-26
> 用户口径（原话）：「**按照归属分流和按照权限码执行是一样吗？项目全部应按照权限码**」

## 1. 结论：不一样，而且不能混用

三者判的对象根本不同：

| 判据 | 判的是什么 | 失效方式 |
|---|---|---|
| **按数据归属分流** | 这条数据属于哪一级（`job.workspace == "system"`） | 数据性质**顶替**了权限判定。授权侧再怎么配，接口仍按自己的规则减量 —— 用户被授予的能力被**悄悄拿掉** |
| **按身份判权** | 这个人是不是 `admin` | admin 之外的人**无法单独获得**某项能力，只能整块给或整块不给 |
| **按权限码**（唯一正解） | 这个人**有没有这个动作的码** | 没有。授权配了什么就是什么 |

**判据链只有一条**：`auth → 权限码 → 通过/拒绝`。
其余任何"顺带判断"都不得改变「能不能做」这个结论。

## 2. 两类容易被当成"归属分流"的东西，必须分清

### 2.1 选码（允许）：归属只用来决定**查哪个码**

```python
# ✅ 正确：归属选码，权限码判权
code = "system:scheduler:run" if job.workspace == "system" else f"{job.workspace}:taskcenter:run"
if not has_perm(user, code):
    raise HTTPException(403, ...)
```

两级任务中心各有自己的码，必须先看任务属于哪一级才能知道该查哪个码 ——
这一步是**选码**，不是判权。放不放行只由 `has_perm()` 决定。

### 2.2 按权限减量（禁止）

```python
# ❌ 错误：按归属偷偷少给数据
if not has_perm(user, "system:scheduler:view"):
    statement = statement.where(ScheduledJob.workspace != "system")   # 隐式授权
```

这就是本轮修掉的写法。它的问题不是"少给了"，而是：
**用户得到的可见范围不由授权决定，而由接口里一行 `where` 决定**，
管理员从授权页上完全看不出这一层限制。

要「只让他看某个工作区的任务」，正确做法是授他哪个工作区的码，而不是接口里减数据。

## 3. 允许保留的三类非权限码判断（都要带理由登记）

| 类别 | 例子 | 为什么不能改成权限码 |
|---|---|---|
| **防锁死规则** | 不许删最后一个 admin / admin 不查授权表 | 若写成权限码，删光授权后系统**永久锁死**，没人能再管 |
| **数据分区（查询条件）** | `where(Setting.workspace == "xhs")` | 这是「取哪些行」，不是「能不能取」 |
| **选码** | 见 §2.1 | 见 §2.1 |

防锁死的四处（`ROLE_CHECKS_ALLOWED`，全部在 `backend/app/api/`）：

| 文件 | 规则 |
|---|---|
| `system_menus.py` | admin 不查授权表 —— 授权表被清空后仍要能进菜单管理 |
| `system_roles.py` | 改 admin 角色权限时不踢令牌 |
| `system_users.py` | 不许删最后一个 admin（不可恢复事故） |
| `system_permissions.py` | 返回 `is_admin` 只做前端展示，不参与授权判定 |

## 4. 守卫

`tests/backend/test_permission_code_only.py`（3 条）：

1. `test_role_checks_only_in_whitelisted_files` —— 除白名单外，API 层不许出现
   `role == "admin"` / `normalize_role(...) == ROLE_ADMIN` 判权；
2. `test_workspace_branch_always_ends_in_has_perm` —— 按工作区分支选码之后
   **必须**调用 `has_perm`（不许 `if workspace == "system": return job`）；
3. `test_no_workspace_filter_used_as_permission` —— 不许出现
   `where(... workspace != "system")` 这种以权限为条件的减量。

> ⚠️ 守卫必须剥掉 docstring 再扫：本仓 docstring 大量写「不要写成 `role == "admin"`」
> 这类反例，只剥 `#` 会把反例当成真代码（第一版就栽在这）。

## 5. 前端侧的同一条口径

前端同样只按码渲染，不按身份：

```tsx
// ✅
{hasPermission("xhs:taskcenter:create") && <Button>新增任务</Button>}
// ❌
{isAdmin && <Button>新增任务</Button>}
```

「没有权限就不展示」是用户既有口径（2026-10-25），与本文件同源：
**展示与否 = 有没有这个码**，不是"是不是管理员"。
